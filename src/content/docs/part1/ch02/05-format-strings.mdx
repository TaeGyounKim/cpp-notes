- 다루는 것: 값을 끼워 넣어 문자열을 만들고 출력하는 방법
- 배우는 요소: `std::format`, `std::print` / `std::println`, 형식 문자열, 인수 번호, 컴파일 타임 검사, `std::vformat`
- 지금까지 `std::println("{}", 값)` 꼴로만 써 온 것의 전체 모습을 여기서부터 살펴봄. 값의 모양을 다듬는 형식 지정자는 다음 글에서 다룸

## 세 가지 방식

| 방식 | 예 | 타입 안전 | 읽기 쉬움 | 직접 만든 타입 지원 |
| --- | --- | --- | --- | --- |
| C의 `printf` | `printf("x=%d y=%d\n", x, y);` | 아님 | 좋음 | 안 됨 |
| I/O 스트림 | `std::cout << "x=" << x << " y=" << y << '\n';` | 안전 | 나쁨 | 됨 |
| `std::format` / `std::print` | `std::println("x={} y={}", x, y);` | 안전 | 좋음 | 됨 |

- `printf` <CppRef path="cpp/io/c/fprintf" />
  - 문장의 틀과 값이 나뉘어 있어 읽기 쉽고, 다른 언어로 번역하기도 쉬움
  - 형식 지정(`%d`)과 실제 인수의 타입이 맞는지 아무도 검사해 주지 않음. 틀리면 정의되지 않은 동작
- I/O 스트림
  - 타입에 맞게 알아서 출력함
  - 문장과 값이 `<<`로 뒤섞여 읽기 어렵고 번역하기도 어려움
- `std::format` <Badge text="C++20" />: 두 방식의 장점을 합친 것. `<format>` 헤더 <CppRef path="cpp/utility/format/format" />
- `std::print` / `std::println` <Badge text="C++23" />: `std::format`으로 만든 문자열을 바로 출력. `<print>` 헤더 <CppRef path="cpp/io/print" />
  - 지금 콘솔 출력에 권장되는 방법
  - 유니코드 출력을 더 잘 다룸. 한글, 일본어, 이모지 같은 UTF-8 문자를 유니코드를 지원하는 콘솔에 바르게 출력
  - 내부적으로 스트림을 쓰지만, 스트림에 직접 `<<`로 쓰는 것보다 빠름

## 형식 문자열

- **형식 문자열** (format string): 결과가 어떤 모양일지 적은 틀. 보통 첫 번째 인수 <CppRef path="cpp/utility/format/spec" />
- **치환 필드** (replacement field): 형식 문자열 안의 중괄호 `{}`. 뒤따르는 인수의 값이 그 자리에 들어감
- 치환 필드 안에 적을 수 있는 것: `{번호:형식 지정자}`. 둘 다 생략할 수 있음

| 꼴 | 뜻 |
| --- | --- |
| `{}` | 다음 인수를 기본 모양으로 |
| `{1}` | 1번 인수를 기본 모양으로 |
| `{:>8}` | 다음 인수를 지정한 모양으로 |
| `{1:>8}` | 1번 인수를 지정한 모양으로 |

- 중괄호 글자 자체를 출력하려면 두 번 적음: `{{`, `}}`
- 형식 문자열은 생략할 수 없음
  - `std::println(x);` → 안 됨. `std::println("{}", x);`
  - `std::println();` → 안 됨. 빈 줄은 `std::println("");`

### 인수 번호

- 치환 필드에 번호를 적으면 몇 번째 인수를 넣을지 직접 고름. 번호는 0부터
- 규칙
  - 모두 생략하거나, 모두 적거나. 섞어 쓸 수 없음
  - 같은 번호를 여러 번 써도 됨
- 쓸모: 인수의 순서는 그대로 두고 문장 안에서의 순서만 바꿀 수 있음
  - 언어마다 어순이 다르므로, 문장을 번역할 때 형식 문자열만 바꾸면 됨

- 해 볼 것: 주석 처리된 마지막 줄의 `//`를 지우고 실행
  - 결과: 컴파일 오류. 형식 문자열이 잘못되었다는 것을 컴파일러가 알아냄

### 출력할 곳 바꾸기

- `std::print` / `std::println`의 첫 인수로 스트림을 주면 그곳으로 출력함
  - `std::println(std::cerr, "오류: {}", code);` → 표준 오류로
- 생략하면 표준 출력. `std::cout`과 같은 곳

## 형식 문자열은 컴파일할 때 검사됨 <Badge text="C++23" />

- `std::format`, `std::print`, `std::println`의 형식 문자열은 **컴파일할 때 값을 알 수 있는 상수**여야 함
- 이유: 컴파일러가 형식 문자열의 문법과 인수의 개수·타입을 컴파일 단계에서 검사하기 위함
  - 형식 문자열의 실수가 실행 중의 오류가 아니라 컴파일 오류로 드러남
- 그래서 변수에 든 문자열을 형식 문자열 자리에 넣을 수 없음

| 코드 | 결과 |
| --- | --- |
| `std::println("{}", message);` | 됨. 형식 문자열이 리터럴 |
| `std::println(message);` (`message`는 `std::string`) | 컴파일 오류 |
| `constexpr auto pattern{ "Value: {}" }; std::println(pattern, 11);` | 됨. `constexpr` 변수는 컴파일할 때 값이 정해짐 |

- `constexpr`: 컴파일할 때 값이 정해진다는 표시. 9장에서 다룸
- 오류 메시지는 컴파일러마다 다르고 알아보기 어려운 편. GCC 16.2의 경우 `call to consteval function ... is not a constant expression`

## 실행 중에 정해지는 형식 문자열

- 문제 상황: 형식 문자열을 실행 중에 골라야 할 때가 있음. 예: 사용자의 언어에 따라 번역된 문장을 고르기
- 이럴 때 쓰는 함수: 이름이 `v`로 시작하는 것들

| 함수 | 하는 일 |
| --- | --- |
| `std::vformat(형식 문자열, 인수 묶음)` | 문자열을 만들어 돌려줌 <CppRef path="cpp/utility/format/vformat" /> |
| `std::vprint_unicode(출력할 곳, 형식 문자열, 인수 묶음)` | 바로 출력 <CppRef path="cpp/io/vprint_unicode" /> |
| `std::vprint_nonunicode(...)` | 유니코드 처리를 하지 않고 출력 |

- 인수를 그대로 나열할 수 없음. `std::make_format_args(인수...)`로 묶어서 넘김 <CppRef path="cpp/utility/format/make_format_args" />
- 검사가 실행 중에 이루어짐 → 형식 문자열이 잘못되면 `std::format_error` 예외가 던져짐 <CppRef path="cpp/utility/format/format_error" />
  - `std::format`, `std::print`, `std::println`은 컴파일할 때 검사를 끝내므로 형식 문자열 때문에 이 예외를 던지는 일이 없음

<RunCode client:load code={runtimeCode} />

- 볼 것
  - `localizedFormat`이 돌려주는 문자열은 실행 중에 정해짐. `std::println`에는 넘길 수 없고 `std::vprint_unicode`에는 넘길 수 있음
  - 마지막: 형식 문자열이 5번 인수를 요구하는데 인수는 하나뿐 → `std::format_error`

## 이전 표준에서는

| 이 글에서 쓴 것 | 들어온 표준 | 그 이전에는 |
| --- | --- | --- |
| `std::format`, `std::vformat`, `std::make_format_args` | C++20 | I/O 스트림 또는 `printf` |
| `std::print`, `std::println`, `std::vprint_unicode` | C++23 | C++20: `std::cout << std::format(...)` |
| 형식 문자열의 컴파일 타임 검사 | C++23 (C++20에도 소급 적용) | 최신 컴파일러는 C++20 모드에서도 검사함 |

- C++20의 `std::format`을 쓸 수 없는 환경: `{fmt}` 라이브러리를 많이 씀. `std::format`의 바탕이 된 오픈 소스 라이브러리이고 C++11부터 쓸 수 있음

## 헷갈리기 쉬운 점

- `std::make_format_args`에는 변수를 넘겨야 함
  - `std::make_format_args(1, 2)`처럼 리터럴이나 임시 값을 바로 넘기면 컴파일 오류. 인수를 참조로 받기 때문
  - 예전 자료에는 리터럴을 넘기는 코드가 있음. 지금의 컴파일러에서는 변수에 담아 넘길 것
- `std::vprint_unicode`의 첫 인수
  - 표준에는 출력할 곳을 생략한 형태도 있지만, GCC 16.2의 표준 라이브러리에서는 `stdout`이나 스트림을 첫 인수로 줘야 컴파일됨. 항상 적어 주면 어느 쪽에서나 동작
- `std::format`은 출력하지 않음
  - 문자열을 만들어 돌려줄 뿐. 출력은 `std::print` / `std::println` 또는 `std::cout`이 함
- 인수가 남는 것은 오류가 아님
  - `std::println("{}", 1, 2);`는 컴파일됨. 2는 쓰이지 않음
  - 반대로 인수가 모자라면 컴파일 오류

## 정리

| 요소 | 핵심 | 들어온 표준 |
| --- | --- | --- |
| `std::format(형식, 인수...)` | 문자열을 만들어 돌려줌 | C++20 |
| `std::print` / `std::println` | 만들어서 바로 출력. 권장 | C++23 |
| `{}` | 치환 필드. `{번호:형식 지정자}` | C++20 |
| `{{`, `}}` | 중괄호 글자 출력 | C++20 |
| 인수 번호 | `{0}`, `{1}`. 모두 적거나 모두 생략 | C++20 |
| `std::println(std::cerr, ...)` | 출력할 곳 지정 | C++23 |
| 컴파일 타임 검사 | 형식 문자열은 컴파일 타임 상수 | C++23 |
| `std::vformat`, `std::vprint_unicode` | 실행 중에 정해지는 형식 문자열. 잘못되면 `std::format_error` | C++20, C++23 |

## 복습 질문

<details>
<summary>`printf`와 비교해 `std::format`이 나은 점은?</summary>

- 타입 안전. 형식 문자열과 인수가 맞지 않으면 컴파일 오류
- 직접 만든 타입도 출력할 수 있게 확장할 수 있음

</details>

<details>
<summary>`std::println("{1} {0} {1}", "a", "b");`의 출력은?</summary>

- `b a b`
- 번호는 0부터 세고, 같은 번호를 여러 번 쓸 수 있음

</details>

<details>
<summary>`std::string text{ "{} items" }; std::println(text, 3);`이 컴파일되지 않는 이유는?</summary>

- 형식 문자열은 컴파일할 때 값을 알 수 있는 상수여야 함
- `text`는 실행 중에 값이 정해지는 변수
- 고치는 법: 리터럴을 직접 쓰거나 `constexpr`로 선언. 정말 실행 중에 정해져야 한다면 `std::vformat`

</details>

<details>
<summary>출력에 중괄호 `{ok}`를 그대로 내보내려면 형식 문자열을 어떻게 적나요?</summary>

- `"{{ok}}"`
- 중괄호 글자는 두 번씩 적음

</details>

<details>
<summary>`std::vformat`에 잘못된 형식 문자열을 넘기면 언제, 어떻게 알게 되나요?</summary>

- 실행 중에 `std::format_error` 예외가 던져짐
- `std::format`과 달리 컴파일할 때 검사하지 못하기 때문

</details>
