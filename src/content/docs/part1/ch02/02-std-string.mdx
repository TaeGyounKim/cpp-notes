## C 스타일 문자열의 무엇이 문제인가

| 장점 | 단점 |
| --- | --- |
| 단순함. 문자와 배열만 알면 됨 | 제대로 된 문자열 타입처럼 쓰려면 손이 아주 많이 감 |
| 가벼움. 꼭 필요한 메모리만 씀 | 찾기 어려운 메모리 버그가 생기기 쉬움 |
| 저수준. 메모리를 그대로 다루고 복사할 수 있음 | 내부 구조(널 문자, 배열 크기)를 프로그래머가 늘 의식해야 함 |
| | C++의 객체 지향 기능을 살리지 못함 |

- `std::string`은 오른쪽 단점을 모두 없애고, 왼쪽 장점은 대부분 그대로 가짐
- `std::string`: 문자열을 나타내는 표준 라이브러리 클래스. `<string>` 헤더 <CppRef path="cpp/string/basic_string" />
  - 정확히는 `std::basic_string<char>`의 타입 별칭
  - `<cstring>` 함수들이 하던 일을 멤버 함수와 연산자로 제공하고, 메모리 관리는 스스로 함
- 쓰는 마음가짐: 클래스이지만 `int` 같은 기본 타입처럼 다루면 됨

## 이어 붙이기와 비교

| 하는 일 | C 스타일 | `std::string` |
| --- | --- | --- |
| 이어 붙이기 | 메모리를 직접 마련하고 `strcpy`, `strcat` | `a + b`, `a += b` |
| 같은지 비교 | `strcmp(a, b) == 0` | `a == b` |
| 순서 비교 | `strcmp(a, b) < 0` | `a < b` |

- C 스타일 문자열에 `==`를 쓰면 안 되는 이유: 내용이 아니라 **주소**를 비교함
  - 내용이 같아도 서로 다른 배열이면 거짓
- `std::string`의 비교 연산자(`==`, `!=`, `<`, `>` 등): 실제 글자를 비교함. 크고 작음은 사전 순서
- `compare()` 멤버 함수: `strcmp`처럼 음수, 0, 양수를 돌려줌
  - 주의: 같으면 **0**. `if (a.compare(b))`는 "같을 때"가 아니라 "다를 때" 참
  - 같은지만 알고 싶으면 `compare()`를 쓰지 말고 `==`를 쓸 것
- 삼중 비교 연산자 `<=>`도 쓸 수 있음 <Badge text="C++20" />
  - `std::is_lt`, `std::is_eq`, `std::is_gt`로 결과를 읽음

- 마지막 줄 `false`: 내용이 똑같이 `"12"`인 두 배열인데도 다르다고 나옴. 주소를 비교했기 때문

## 메모리 관리

- 문자열이 길어지면 필요한 메모리를 `std::string`이 알아서 늘림. 넘쳐 쓰는 일이 없음
- 글자 하나에 접근: 배열처럼 `[ ]`
- 대입(`=`)과 복사: 내용이 통째로 복사됨. 복사본을 바꿔도 원본은 그대로
- 메모리 누수가 없는 이유
  - `std::string` 객체가 사라질 때 소멸자가 쓰던 메모리를 돌려줌
  - 지역 변수로 만든 문자열은 블록이 끝나면 자동으로 정리됨
  - 소멸자의 자세한 동작: 8장에서 다룸

<RunCode client:load code={memoryCode} />

- `size()`와 `capacity()`
  - `size()`: 지금 들어 있는 글자 수
  - `capacity()`: 다시 메모리를 마련하지 않고 담을 수 있는 글자 수
  - 글자를 하나 붙일 때마다 메모리를 새로 마련하지 않도록 여유 있게 잡아 둠. 출력되는 숫자는 컴파일러마다 다름

## C 스타일 문자열과의 호환

- C 스타일 문자열을 받는 함수에 `std::string`을 넘겨야 할 때

| 멤버 함수 | 돌려주는 것 |
| --- | --- |
| `c_str()` | `const char*`. 널 문자로 끝나는 C 스타일 문자열 <CppRef path="cpp/string/basic_string/c_str" /> |
| `data()` | `const`가 아닌 문자열에서는 `char*` <Badge text="C++17" />. 그 전에는 `c_str()`과 같은 `const char*` <CppRef path="cpp/string/basic_string/data" /> |

- 받아 둔 포인터가 못 쓰게 되는 때
  - 문자열이 길어져 메모리를 새로 마련했을 때
  - 문자열 객체가 사라졌을 때
- 규칙
  - 포인터를 보관하지 말고, 쓰기 직전에 `c_str()`을 부를 것
  - 함수 안의 지역 문자열에서 얻은 `c_str()`을 반환하지 말 것. 함수가 끝나면 문자열이 사라짐

## 자주 쓰는 연산

| 멤버 함수 | 하는 일 | 들어온 표준 |
| --- | --- | --- |

## 문자열 리터럴 s <Badge text="C++14" />

- 보통의 문자열 리터럴 `"Hello"`의 타입은 `std::string`이 아님. `const char`의 배열
- 리터럴 뒤에 `s`를 붙이면 `std::string`이 됨 <CppRef path="cpp/string/basic_string/operator%22%22s" />

| 코드 | 변수의 타입 |
| --- | --- |
| `auto a{ "Hello" };` | `const char*` |
| `auto& b{ "Hello" };` | `const char[6]`에 대한 참조 |
| `auto c{ "Hello"s };` | `std::string` |

- `s`를 쓰려면 아래 가운데 하나가 필요

```cpp
using namespace std::string_literals;
using namespace std::literals;
using namespace std;
```

- 셋 다 되는 이유: `string_literals`와 `literals`가 **인라인 네임스페이스**이기 때문
- **인라인 네임스페이스** (inline namespace): 그 안의 이름이 바깥 네임스페이스에도 그대로 보이는 네임스페이스. `inline namespace 이름 { }`으로 만듦 <CppRef path="cpp/language/namespace#Inline_namespaces" />

```cpp
namespace std {
    inline namespace literals {
        inline namespace string_literals {
            // 접미사 s가 여기에 정의되어 있음
        }
    }
}
```

### CTAD와 문자열

- 1장에서 본 것: `std::vector`는 초기화 값을 보고 원소 타입을 추론함(CTAD)
- 함정: 문자열 리터럴로 초기화하면 `std::string`의 벡터가 **아님**

| 코드 | 추론된 타입 |
| --- | --- |
| `std::vector names{ "Kim", "Lee" };` | `std::vector<const char*>` |
| `std::vector names{ "Kim"s, "Lee"s };` | `std::vector<std::string>` |

- `const char*`의 벡터가 되면 원소에 `size()`나 `+`를 쓸 수 없고, 비교도 주소 비교가 됨
- 해결: 리터럴에 `s`를 붙이거나, `std::vector<std::string>`이라고 타입을 직접 적음

## 헷갈리기 쉬운 점

- `"Hello" + "World"`는 컴파일되지 않음
  - 둘 다 `std::string`이 아니라 문자 배열. 한쪽이라도 `std::string`이어야 `+`가 됨
  - `"Hello"s + "World"` 또는 `std::string{ "Hello" } + "World"`
- `find`가 못 찾았을 때의 결과는 -1이 아님
  - `std::string::npos`는 부호 없는 타입의 가장 큰 값. `int`에 담아 `-1`과 비교하는 코드는 피할 것
  - `auto position{ text.find("x") };`로 받고 `npos`와 비교
- `substr`과 `replace`의 둘째 인수는 "끝 위치"가 아니라 **길이**
- `size()`와 `length()`는 같은 것. 이름만 다름

| --- | --- | --- |
| `a + b`, `a += b` | 이어 붙이기 | |
| `==`, `<`, `<=>` | 내용 비교. `<=>`는 C++20 | |
| 메모리 | 알아서 늘어나고, 사라질 때 알아서 정리됨 | |
| `c_str()`, `data()` | C 스타일 문자열로 넘기기. 포인터는 보관하지 말 것 | |
| `substr`, `find`, `replace` | 부분 꺼내기, 찾기, 바꾸기 | |
| `starts_with`, `ends_with` | 시작과 끝 검사 | C++20 |
| `contains` | 포함 검사 | C++23 |
| `"..."s` | `std::string` 리터럴 | C++14 |
| `std::vector v{ "a", "b" };` | `const char*`의 벡터가 됨. `s`를 붙일 것 | |

## 복습 질문

<details>
<summary>`char a[]{ "hi" }; char b[]{ "hi" };`일 때 `a == b`가 거짓인 이유는?</summary>

- 배열 이름끼리의 `==`는 내용이 아니라 주소를 비교함
- 두 배열은 내용은 같아도 서로 다른 곳에 있음
- `std::string`으로 바꾸면 `==`가 내용을 비교함

</details>

<details>
<summary>`if (a.compare(b)) { ... }`는 언제 실행되나요?</summary>

- `a`와 `b`가 **다를 때**
- `compare()`는 같으면 0(거짓), 다르면 0이 아닌 값(참)을 돌려줌
- 같은지 확인하려면 `a == b`

</details>

<details>
<summary>`std::string text{ "report.txt" };`에서 확장자 `"txt"`만 꺼내려면?</summary>

- `text.substr(7)` 또는 `text.substr(7, 3)`
- 일반적으로는 `text.substr(text.find(".") + 1)`

</details>

<details>
<summary>`std::vector names{ "Kim", "Lee" };`의 타입은 무엇이고, 무엇이 문제인가요?</summary>

- `std::vector<const char*>`
- 원소가 `std::string`이 아니라 포인터. `size()`나 `+`를 쓸 수 없고 `==`는 주소를 비교함
- `"Kim"s`처럼 `s`를 붙이면 `std::vector<std::string>`

</details>

<details>
<summary>`const char* p{ text.c_str() };`로 받아 둔 포인터를 한참 뒤에 쓰면 안 되는 이유는?</summary>

- 그 사이에 `text`가 길어져 메모리를 새로 마련했거나 `text`가 사라졌다면, `p`는 이미 돌려준 메모리를 가리킴
- 쓰기 직전에 `c_str()`을 다시 부를 것

</details>
