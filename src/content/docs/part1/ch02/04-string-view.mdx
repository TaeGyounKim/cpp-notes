- 다루는 것: 문자열을 "갖지 않고 보기만 하는" 타입
- 배우는 요소: `std::string_view`, `string`과의 변환, 임시 문자열의 함정, 리터럴 접미사 `sv`
- 한 줄 요약: 읽기만 할 문자열을 함수가 받을 때는 `std::string_view`

## 무엇이 문제였나

- 문제 상황: 문자열을 읽기만 하는 함수의 매개변수 타입을 무엇으로 할까

| 선택 | 문제 |
| --- | --- |
| `const char*` | `std::string`을 가진 쪽은 `c_str()`을 불러야 함. 함수 안에서는 `std::string`의 편리한 멤버 함수를 쓸 수 없음 |
| `const std::string&` | 문자열 리터럴을 넘기면 임시 `std::string`이 만들어져 복사가 일어남 |
| 두 가지를 모두 받도록 오버로딩 | 같은 함수를 두 번 써야 함 |

- `std::string_view` <Badge text="C++17" />: 이 문제를 푸는 타입. `<string_view>` 헤더 <CppRef path="cpp/string/basic_string_view" />
  - 정확히는 `std::basic_string_view<char>`의 타입 별칭

## string_view란

- **문자열 뷰** (string view): 다른 곳에 있는 문자열을 읽기 전용으로 들여다보는 창
- 들어 있는 것은 두 가지뿐

| 들어 있는 것 | 뜻 |
| --- | --- |
| 포인터 | 보려는 문자들이 시작하는 곳 |
| 길이 | 거기서부터 몇 글자를 볼지 |

- 문자열을 **절대 복사하지 않음**. 글자들은 원래 있던 곳에 그대로 있음
- 그래서 복사 비용이 아주 쌈. 문자열이 아무리 길어도 포인터 하나와 정수 하나만 복사됨
  - 함수에 넘길 때 참조가 아니라 **값으로** 넘기는 것이 보통
- `const std::string&` 자리에 그대로 바꿔 넣을 수 있음. 읽기용 멤버 함수가 `std::string`과 거의 같음

| `std::string`과 비교 | 내용 |
| --- | --- |
| 같은 것 | `size`, `[ ]`, `substr`, `find`, `rfind`, `starts_with`, `ends_with`, `contains`, 비교 연산자 |
| 없는 것 | `c_str()`. 널 문자로 끝난다는 보장이 없기 때문. `data()`는 있음 |
| 더 있는 것 | `remove_prefix(n)`: 앞에서 n글자를 시야에서 뺌. `remove_suffix(n)`: 뒤에서 n글자를 뺌 <CppRef path="cpp/string/basic_string_view/remove_prefix" /> |

<RunCode client:load code={paramCode} />

- 볼 것
  - `std::string`, `const char*`, 문자열 리터럴을 모두 같은 함수로 받음. 어느 경우에도 문자열 복사가 없음
  - 반환값도 `std::string_view`. 받은 문자열의 일부를 가리키는 뷰를 돌려줌
  - `std::string_view{ raw, 8 }`: 포인터와 길이를 직접 줌. 널 문자로 끝나지 않는 범위도 볼 수 있고, 길이를 이미 알 때는 글자 수를 다시 세지 않아도 됨
- `rfind`: `find`와 같되 뒤에서부터 찾음. 마지막 점을 찾으려고 씀

## string과 오가기

- `std::string` → `std::string_view`: 자동으로 됨. 복사가 없으므로 위험이 없음
- `std::string_view` → `std::string`: **자동으로 되지 않음**
  - 이유: 이 변환은 반드시 글자들을 복사함. 모르는 사이에 복사가 일어나지 않도록 막아 둔 것
  - 방법: `std::string`을 직접 만듦. `std::string copy{ view };`
- `std::string + std::string_view`도 안 됨. 같은 이유

| 하려는 일 | 코드 |
| --- | --- |
| 뷰를 문자열로 | `std::string copy{ view };` |
| 문자열 뒤에 뷰를 붙인 새 문자열 | `text + std::string{ view }` |
| 문자열 뒤에 뷰를 덧붙임 | `text.append(view);` |

<RunCode client:load code={opsCode} />

- 볼 것: `remove_prefix`와 `remove_suffix` 뒤에도 원본 `text`는 공백이 그대로. 바뀐 것은 뷰가 보는 범위뿐
- 해 볼 것: 주석 처리된 `auto bad{ greeting + view };`의 `//`를 지우고 실행
  - 결과: 컴파일 오류 `no match for 'operator+'`

## 뷰가 가리키는 문자열은 살아 있어야 함

- `std::string_view`는 문자열을 갖고 있지 않음. 가리키는 문자열이 사라지면 뷰는 매달린 포인터를 품게 됨
- 가장 흔한 실수: **임시 문자열**을 뷰로 받기

```cpp
std::string name{ "Hello" };
std::string_view view{ name + " World!" };   // 위험!
std::println("{}", view);                    // 정의되지 않은 동작
```

- 무슨 일이 일어나는가
  - `name + " World!"`는 임시 `std::string`을 만듦
  - `view`는 그 임시 문자열의 글자들을 가리킴
  - 그 줄이 끝나면 임시 문자열은 사라짐. `view`는 이미 돌려준 메모리를 가리킴
- 결과는 예측할 수 없음. 죽을 수도, 앞 글자가 깨져 나올 수도, 멀쩡해 보일 수도 있음
- 규칙 세 가지
  - 임시 문자열을 `std::string_view`에 담지 말 것
  - 함수가 문자열을 **돌려줄** 때는 `std::string`이나 `const std::string&`로. 뷰를 돌려주면 가리키던 문자열이 바뀌거나 사라졌을 때 문제가 됨. 위 예제처럼 받은 인수의 일부를 가리키는 뷰를 돌려주는 것은, 호출한 쪽이 그 인수를 살려 두는 동안만 안전함
  - 클래스의 데이터 멤버로는 `std::string_view`나 `const std::string&` 대신 `std::string`을 둘 것. 객체가 사는 동안 문자열도 함께 살아 있어야 하기 때문

### 리터럴 sv <Badge text="C++17" />

- 리터럴 뒤에 `sv`를 붙이면 `std::string_view`가 됨 <CppRef path="cpp/string/basic_string_view/operator%22%22sv" />
  - `auto view{ "My string_view"sv };`
- 쓰려면 아래 가운데 하나가 필요

```cpp
using namespace std::string_view_literals;
using namespace std::literals;
using namespace std;
```

- 문자열 리터럴은 프로그램이 끝날 때까지 살아 있으므로, 리터럴을 가리키는 뷰는 안전함

## 표준이 아닌 문자열 타입

- `std::string`을 쓰지 않는 C++ 코드도 많음. 이유
  - 예전에는 `std::string`이 표준에 없었음
  - `std::string`은 문자 인코딩을 전혀 신경 쓰지 않음. 그 점이 불편해 직접 문자열 타입을 만든 곳이 있음. 인코딩은 21장에서 다룸
  - 프레임워크와 운영체제가 자기 문자열 타입을 갖고 있음. 예: MFC의 `CString`, Qt의 `QString`
- 프로젝트를 시작할 때 정해 둘 것: 문자열을 무엇으로 나타낼지

| 선택 | 판단 |
| --- | --- |
| C 스타일 문자열 | 고르지 말 것 |
| 쓰는 프레임워크의 문자열 타입 | 그 프레임워크 안에서 통일한다면 괜찮음 |
| `std::string` | 읽기 전용으로 넘길 때는 `std::string_view`와 함께 |

## 이전 표준에서는

| 이 글에서 쓴 것 | 들어온 표준 | C++11에서는 |
| --- | --- | --- |
| `std::string_view`, `"..."sv` | C++17 | `const std::string&`로 받음. 리터럴을 넘기면 복사가 한 번 일어남 |
| `starts_with`, `ends_with` | C++20 | `compare`로 직접 비교 |
| `contains` | C++23 | `find(...) != npos` |
| `nullptr`로 뷰를 만들면 컴파일 오류 | C++23 | 컴파일은 되고 실행 중에 문제가 생김 |

## 헷갈리기 쉬운 점

- `std::string_view`는 "가벼운 문자열"이 아니라 "남의 문자열을 보는 창"
  - 글자를 갖고 있지 않으므로, 원본이 사라지거나 바뀌면 뷰도 못 쓰게 됨
- 뷰가 보는 문자들은 널 문자로 끝나지 않을 수 있음
  - `view.data()`를 C 스타일 문자열을 받는 함수에 그대로 넘기면 안 됨. 길이 정보가 사라짐
  - 꼭 필요하면 `std::string{ view }.c_str()`처럼 문자열로 만든 뒤 넘김
- `std::string_view`로는 글자를 바꿀 수 없음
  - 읽기 전용. `view[0] = 'x';`는 컴파일 오류
- 매개변수는 `std::string_view`, 반환과 저장은 `std::string`
  - 받는 쪽은 뷰가 가장 유연하고, 내보내거나 오래 들고 있을 것은 문자열을 직접 갖는 것이 안전

## 정리

| 요소 | 핵심 | 들어온 표준 |
| --- | --- | --- |
| `std::string_view` | 포인터 + 길이. 복사하지 않는 읽기 전용 뷰 | C++17 |
| 매개변수로 쓰기 | 값으로 받음. `string`, `const char*`, 리터럴을 모두 받음 | C++17 |
| `remove_prefix`, `remove_suffix` | 보는 범위를 앞뒤로 줄임 | C++17 |
| 뷰 → 문자열 | 자동 변환 없음. `std::string{ view }` | |
| 임시 문자열 | 뷰에 담지 말 것. 매달린 포인터가 됨 | |
| `"..."sv` | `std::string_view` 리터럴 | C++17 |
