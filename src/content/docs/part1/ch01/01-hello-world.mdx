## 주석

- **주석** (comment): 사람이 읽으라고 적어 두는 메모 <CppRef path="cpp/comment" />
- 컴파일러는 주석을 없는 것으로 취급함
- 쓰는 방법 두 가지

```cpp
// 슬래시 두 개 뒤부터 그 줄 끝까지가 주석

/* 슬래시와 별표로 시작해서
   별표와 슬래시로 끝나는 주석은
   여러 줄에 걸칠 수 있음 */
```

- 주석을 잘 쓰는 방법: 3장에서 다룸

## 라이브러리 가져오기

- **표준 라이브러리** (Standard Library): 컴파일러와 함께 제공되는 코드 모음 <CppRef path="cpp/standard_library" />
  - 화면 출력 기능은 C++ 언어 자체가 아니라 표준 라이브러리에 들어 있음
  - 쓰려면 먼저 내 코드로 가져와야 함
- **헤더 파일** (header file): 기능들의 선언이 적힌 파일 <CppRef path="cpp/header" />
  - 표준 라이브러리에는 헤더가 100개 넘게 있음
  - 출력 기능은 `<print>` 헤더에 있음
- **모듈** (module): 헤더 파일을 대신하려고 만든 새 방식 <Badge text="C++20" /> <CppRef path="cpp/language/modules" />
  - `std` 모듈 하나로 표준 라이브러리 전체를 가져올 수 있음 <Badge text="C++23" />

### 가져오는 문법 세 가지

| 문법 | 뜻 | 문법이 들어온 표준 |
| --- | --- | --- |
| `import std;` | 표준 라이브러리 전체를 모듈로 가져옴 | <Badge text="C++23" /> |
| `import <print>;` | `<print>` 헤더 하나를 모듈처럼 가져옴 | <Badge text="C++20" /> |
| `#include <print>` | `<print>` 헤더 파일의 내용을 이 자리에 붙여 넣음 | 처음부터 있음 |

- 표의 표준은 **가져오는 문법**에 대한 것
  - `#include` 문법은 어느 표준에서나 쓸 수 있음
  - `<print>` 헤더 자체는 C++23에 생김 → 아래 [헷갈리기 쉬운 점](#헷갈리기-쉬운-점) 참고
- 표기 차이: `import std;`에는 꺾쇠괄호가 없고, 헤더 이름에는 `<print>`처럼 꺾쇠괄호가 붙음
- C++23 기준의 예제는 보통 `import std;`로 시작하지만, 이 사이트의 실행 예제는 `#include` 사용
  - 이유: [import std와 #include](../../../guide/import-std/) 참고
- 모듈을 직접 만드는 방법: 이 장의 뒷부분과 11장에서 다룸

### 이전 표준에서는

- C++11 ~ C++17: `#include`만 사용 가능
- C++20: `import <print>;` 같은 헤더 단위 가져오기 가능. 단, 컴파일러와 빌드 도구의 지원이 고르지 않음
- 옛 표준까지 지원해야 하는 코드: `#include`로 쓰는 것이 유일하게 안전한 선택

### 전처리 지시문

- **전처리 지시문** (preprocessor directive): `#include <print>`처럼 `#`으로 시작하는 줄 <CppRef path="cpp/preprocessor" />
- C++ 문장이 아니라 전처리기에게 내리는 명령 → 끝에 세미콜론을 붙이지 않음
- 자세한 내용: 11장에서 다룸

:::note[소스 파일은 UTF-8로 저장]
- 모든 컴파일러가 UTF-8로 저장한 소스 파일을 받아들여야 함 <Badge text="C++23" />
- 한글처럼 영어가 아닌 글자를 코드에 쓰려면 UTF-8로 맞추는 것이 안전
- 그 이전 표준: 소스 파일 인코딩이 컴파일러마다 달랐음. 아래 옵션으로 직접 맞춰야 함
- 컴파일러별 설정
  - Visual C++: 프로젝트 속성의 C/C++ 명령줄 추가 옵션에 `/utf-8`
  - GCC: `-finput-charset=UTF-8`
  - Clang: 기본값이 UTF-8이라 설정 불필요
:::

## main 함수

- 프로그램의 시작점: 운영체제가 프로그램을 실행하면 `main` 함수의 첫 줄부터 차례로 실행됨 <CppRef path="cpp/language/main_function" />
- `main` 앞의 `int`: 이 함수가 정수 하나를 돌려준다는 뜻
  - 그 정수는 프로그램이 어떻게 끝났는지 운영체제에 알리는 데 쓰임

```cpp
int main()
{
    // 여기에 적은 문장이 위에서부터 차례로 실행됨
}
```

- `main`의 모양은 둘 중 하나

```cpp
int main()                        // 아무것도 받지 않음
int main(int argc, char** argv)   // 프로그램을 실행할 때 붙인 인수를 받음
```

- `argc`: 인수(argument)의 개수
- `argv`: 인수들의 목록
  - 예: 터미널에서 `copy a.txt b.txt`라고 실행하면 `a.txt`와 `b.txt`가 인수
  - 실제 인수는 `argv[1]`부터 들어 있음
  - `argv[0]`: 보통 프로그램 이름이지만 빈 문자열일 수도 있음 → 이 값에 기대는 코드는 금물

### 이스케이프 시퀀스

- **이스케이프 시퀀스** (escape sequence): `\n`처럼 역슬래시로 시작하는 글자 조합 <CppRef path="cpp/language/escape" />
- 용도: 키보드로 직접 넣기 어려운 글자를 문자열 안에 적음

| 이스케이프 시퀀스 | 뜻 |
| --- | --- |
| `\n` | 줄바꿈: 다음 줄의 맨 앞으로 감 |
| `\r` | 캐리지 리턴: 줄은 그대로 두고 현재 줄의 맨 앞으로 감 |
| `\t` | 탭 |
| `\\` | 역슬래시 글자 자체 |
| `\"` | 큰따옴표 글자 자체 |

### std::endl과 줄바꿈 문자의 차이

- **버퍼** (buffer): 스트림이 받은 글자를 모아 두는 임시 공간
  - 스트림은 글자를 곧바로 내보내지 않고 버퍼에 모았다가 한꺼번에 내보냄
- **플러시** (flush): 버퍼에 쌓인 것을 강제로 내보내는 일

| | 줄바꿈 | 플러시 |
| --- | --- | --- |
| `'\n'` | 함 | 하지 않음 |
| `std::endl` | 함 | 함 |

- 플러시는 느린 작업
  - 반복문 안에서 `std::endl`을 수천 번 쓰면 프로그램이 눈에 띄게 느려짐
- 평소에는 `'\n'` 사용 권장

- 두 방법의 대응 관계

| 하려는 일 | `std::format` | 스트림 조작자 |
| --- | --- | --- |
| 8칸에 왼쪽 정렬 | `{:<8}` | `std::left << std::setw(8)` |
| 5칸에 오른쪽 정렬 | `{:>5}` | `std::right << std::setw(5)` |
| 소수점 아래 두 자리 | `{:.2f}` | `std::fixed << std::setprecision(2)` |
| 5칸을 0으로 채우기 | `{:05}` | `std::setfill('0') << std::setw(5)` |

- 조작자 방식의 함정: 조작자마다 효력이 지속되는 범위가 다름
  - `std::setw`: 바로 다음 값 하나에만 적용 → 값마다 다시 써야 함
  - `std::left`, `std::right`, `std::fixed`, `std::setprecision`, `std::setfill`: 한번 설정하면 계속 유지
- 해 볼 것: 두 번째 프로그램의 마지막 줄 아래에 `std::cout << std::setw(5) << 7 << '\n';`을 추가하고 실행
  - 결과: `00007` 출력
  - 이유: 앞에서 설정한 `std::setfill('0')`이 아직 남아 있음
  - `std::format`에서는 형식이 그 `{}` 하나에만 적용되므로 이런 일이 없음
- `std::println`은 `std::format`과 같은 형식 문법을 씀
- 형식 문법 전체는 2장, 스트림 조작자 전체는 13장에서 다룸

- 해 볼 것: "키보드 입력" 칸의 값을 바꿔 가며 실행

<RunCode client:load code={cinCode} stdin="21" />

- `int number{ 0 };`: 정수를 담는 변수 `number`를 만들고 0으로 채워 두는 문장
  - 변수와 중괄호 초기화 문법: 이 장의 뒤쪽 "리터럴, 변수, 연산자" 글에서 다룸
- `>>`는 값을 하나 읽은 뒤 공백을 만나면 멈춤
  - 띄어쓰기가 들어간 문장은 이 방법으로 한 번에 읽을 수 없음
- 해 볼 것: 입력 칸에 숫자 대신 글자를 넣고 실행
  - 사용자는 무엇이든 입력할 수 있으므로 입력을 다루는 코드는 까다로움
  - 자세한 내용: 13장에서 다룸

:::caution[printf와 scanf는 쓰지 않음]
- C 언어의 `printf()`와 `scanf()`도 C++에서 쓸 수는 있음
- 문제: 형식 문자열과 실제 값의 타입이 맞는지 검사하지 않음 → 잘못 써도 컴파일되고 실행 중에 엉뚱하게 동작
- `std::println`과 `std::format`은 이 검사를 컴파일할 때 해 줌
- C++11 ~ C++17에서의 선택: 타입 검사가 되는 스트림(`std::cout`) 사용
:::

## 함수에서 돌아가기

- `return`: 함수를 끝내고 값을 돌려줌
- `main`에서 `return`하면 프로그램이 끝나고, 돌려준 정수는 운영체제로 전달됨
- **종료 코드** (exit code): `main`이 돌려준 정수
  - `0`: 문제없이 끝남
  - `0`이 아닌 값: 오류가 있었음

## 헷갈리기 쉬운 점

### `#include`는 옛 문법인데, `<print>`는 옛 표준에서도 되나요?

- 안 됨. "가져오는 문법"과 "가져오는 대상"은 따로 봐야 함
  - `#include`: C++ 초창기부터 있던 **문법**
  - `<print>`: C++23에 추가된 **헤더**
- `std::println`을 쓰려면 두 조건이 모두 맞아야 함

| 조건 | 맞지 않을 때 생기는 일 |
| --- | --- |
| 컴파일러가 충분히 새것 (GCC 14, Clang 18, Visual Studio 2022 17.7 이상) | `<print>` 파일을 찾을 수 없다는 오류 |
| C++23 옵션을 켬 (`-std=c++23`, Visual Studio는 `/std:c++latest`) | `println`이 `std`에 없다는 오류 |

- `<print>`를 쓸 수 없는 환경에서의 대안: 위의 [표준별 출력 방법](#표준별-출력-방법) 참고

## 정리

| 요소 | 핵심 | 들어온 표준 |
| --- | --- | --- |
| 주석 | `//` 한 줄, `/* */` 여러 줄. 컴파일러는 무시함 | |
| `#include <헤더>` | 헤더 파일의 내용을 붙여 넣음 | |
| `import std;` | 표준 라이브러리 전체를 모듈로 가져옴 | C++23 |
| 빌드 | 전처리 → 컴파일 → 링크 | |
| `main` | 프로그램의 시작점. `int`를 돌려줌. `return` 생략 가능 | |
| `std::println` | `{}` 자리에 값을 넣어 출력하고 줄을 바꿈 | C++23 |
| `std::format` | `{}` 자리에 값을 넣은 문자열을 만듦 | C++20 |
| `std::cout <<` | 스트림으로 출력 | |
| 스트림 조작자 | `std::setw` 등으로 출력 형식 지정 | |
| `std::cin >>` | 스트림으로 입력 | |
| 줄바꿈 | 평소에는 `'\n'`. `std::endl`은 플러시까지 함 | |

## 복습 질문

<details>
<summary>`import std;`와 `#include <print>`는 무엇이 다른가요?</summary>

- `import std;`: 표준 라이브러리 전체를 모듈로 한 번에 가져옴. C++23
- `#include <print>`: `<print>` 헤더 파일 하나의 내용을 그 자리에 붙여 넣음
- 출력 기능을 쓸 수 있게 된다는 결과는 같음

</details>

<details>
<summary>빌드의 세 단계는 무엇이고, 각 단계의 결과물은 무엇인가요?</summary>

- 전처리 → 번역 단위
- 컴파일 → 오브젝트 파일
- 링크 → 실행 파일

</details>

<details>
<summary>`std::println("{} / {}", 10);`은 어떻게 되나요?</summary>

- 컴파일 오류
- `{}`는 두 개인데 값은 하나뿐이고, 컴파일러가 이를 미리 검사함

</details>

<details>
<summary>C++17까지만 쓸 수 있는 프로젝트에서 `std::println("{} + {} = {}", 3, 2, 5);`를 어떻게 바꿔 쓰나요?</summary>

- `std::cout << 3 << " + " << 2 << " = " << 5 << '\n';`
- `std::println`은 C++23, `std::format`은 C++20이라 둘 다 쓸 수 없음
- 헤더는 `<iostream>`

</details>

<details>
<summary>반복문 안에서 줄을 바꿀 때 `std::endl`보다 `'\n'`이 나은 이유는 무엇인가요?</summary>

- `std::endl`은 줄을 바꿀 때마다 버퍼를 플러시함
- 플러시는 느린 작업이라 반복되면 성능이 떨어짐
- `'\n'`은 줄만 바꿈

</details>

<details>
<summary>`main` 함수에 `return` 문이 없으면 어떻게 되나요?</summary>

- 컴파일러가 `return 0;`을 넣어 준 것처럼 동작함
- 이 특례는 `main`에만 적용됨

</details>
