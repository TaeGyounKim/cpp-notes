## if / else 문

- **조건문** (conditional statement): 조건이 참인지에 따라 실행할 코드를 고르는 문장
- `if` 문 <CppRef path="cpp/language/if" />
  - 괄호 안의 조건이 참이면 바로 뒤의 블록을 실행
  - 거짓이면 `else`가 있을 때 그쪽을 실행. 없으면 그냥 지나감
- `else if`로 이어 붙이면 위에서부터 차례로 검사하고, 처음으로 참인 곳 하나만 실행

```cpp
if (temperature > 30) {
    // 30보다 클 때
} else if (temperature > 15) {
    // 30 이하이고 15보다 클 때
} else {
    // 나머지 전부
}
```

- 조건 자리에 올 수 있는 것: `bool` 값, 또는 `bool`로 바뀔 수 있는 값
  - 정수: 0은 거짓, 0이 아닌 값은 모두 참
  - `if (0)`은 `if (false)`와 같음

```cpp
if (초기화; 조건) {

```

- `if` 문이 끝나면 그 변수는 사라짐

## switch 문

- `switch` 문: 값 하나를 여러 후보와 견주어, 같은 후보의 코드를 실행하는 문장 <CppRef path="cpp/language/switch" />

```cpp
switch (button) {
    case 1:
        // button이 1일 때
        break;
    case 2:
        // button이 2일 때
        break;
    default:
        // 어느 case에도 해당하지 않을 때
        break;
}
```

- 구성 요소
  - `case 값:`: 후보 하나. 값은 상수여야 함
  - `break;`: `switch` 문을 빠져나감
  - `default:`: 맞는 `case`가 없을 때 실행되는 곳. 없어도 됨
- 괄호 안에 올 수 있는 타입: 정수 타입, 정수로 바뀔 수 있는 타입, 열거형
  - `double`이나 문자열은 쓸 수 없음
- `switch` 문은 언제나 `if` / `else if`로 바꿔 쓸 수 있음
  - `switch`가 어울리는 경우: 값 하나를 정해진 여러 후보와 비교할 때
  - `if`가 어울리는 경우: 후보가 한둘이거나, "크다 / 작다" 같은 조건을 볼 때

### break가 없으면: fallthrough

- **폴스루** (fallthrough): `break`를 만나지 않아 다음 `case`의 코드까지 이어서 실행되는 것
  - 맞는 `case`를 찾은 뒤에는 `break`를 만날 때까지 아래로 계속 실행함
  - 중간에 다른 `case` 줄이 있어도 멈추지 않음
- 실수로 `break`를 빠뜨리면 버그가 됨 → 컴파일러가 경고해 주는 경우가 많음
  - 예외: 코드 없이 `case`만 연달아 적은 것은 경고하지 않음. 여러 값에 같은 코드를 쓰는 흔한 방법
- 일부러 이어 가는 경우: `[[fallthrough]];`를 적음 <Badge text="C++17" /> <CppRef path="cpp/language/attributes/fallthrough" />
  - 읽는 사람과 컴파일러에게 "실수가 아님"을 알림. 경고도 사라짐
  - `[[ ]]` 문법(어트리뷰트): 다음 글에서 다룸

### 열거형과 switch

- `switch` 문 안에 `using enum`을 두면 `case`마다 열거형 이름을 붙이지 않아도 됨 <Badge text="C++20" />
  - 효력이 그 `switch` 문 안으로 한정됨. 앞 글에서 말한 "범위를 좁게"의 좋은 예
- 열거형을 `switch`할 때는 `default`를 쓰지 말고 모든 열거자를 `case`로 적을 것
  - 이유: 나중에 열거자를 추가했을 때, 빠뜨린 `switch` 문을 컴파일러가 경고로 알려 줌
  - `default`가 있으면 새 열거자가 조용히 `default`로 처리되어 알아채기 어려움
- 해 볼 것: 위 코드에서 `case Standard:`와 그 아래 `break;`를 지우고 실행

## 조건 연산자

- **조건 연산자** (conditional operator) `?:`: `조건 ? 참일 때의 값 : 거짓일 때의 값` <CppRef path="cpp/language/operator_other#Conditional_operator" />
  - C++에 하나뿐인 삼항 연산자
  - 읽는 법: 물음표 앞을 질문으로 읽음. "점수가 60 이상인가? 그렇다면 합격, 아니면 불합격"
- `if` 문과 다른 점: 문장이 아니라 **식**. 결과가 값으로 나옴
  - 값이 필요한 자리 어디에나 쓸 수 있음. 출력하는 자리, 변수를 초기화하는 자리 등
- 조건을 감싸는 괄호는 있어도 되고 없어도 됨. `(score >= 60) ? ...`와 `score >= 60 ? ...`는 같음

## 비교 연산자와 논리 연산자

- 결과가 항상 `true` 또는 `false`인 연산자들

| 연산자 | 뜻 | 예 |
| --- | --- | --- |
| `<` `<=` `>` `>=` | 작다, 작거나 같다, 크다, 크거나 같다 | `age >= 19` |
| `==` | 같다 | `age == 25` |
| `!=` | 같지 않다 | `age != 25` |
| `<=>` | 삼중 비교. 아래에서 다룸 | `a <=> b` |
| `!` | 논리 NOT. 참과 거짓을 뒤집음 | `!member` |
| `&&` | 논리 AND. 양쪽이 모두 참일 때만 참 | `adult && member` |
| <code>&#124;&#124;</code> | 논리 OR. 한쪽이라도 참이면 참 | <code>adult &#124;&#124; member</code> |

- 비교 연산자 <CppRef path="cpp/language/operator_comparison" />, 논리 연산자 <CppRef path="cpp/language/operator_logical" />
- 주의: `==`(같은지 비교)와 `=`(대입)를 혼동하지 말 것
  - `if (age = 25)`는 비교가 아님. `age`에 25를 넣고, 그 값 25가 0이 아니므로 항상 참
- 앞 글의 비트 연산자 `&`, <code>&#124;</code>와도 다름. 논리 연산자는 기호를 두 번 씀

### 단락 평가

- **단락 평가** (short-circuit evaluation): 결과가 이미 정해지면 나머지 부분을 계산하지 않는 것
  - `A && B`: `A`가 거짓이면 결과는 거짓으로 확정 → `B`는 계산하지 않음
  - <code>A &#124;&#124; B</code>: `A`가 참이면 결과는 참으로 확정 → `B`는 계산하지 않음
- 쓸모
  - 안전: 앞에서 확인하고, 통과했을 때만 뒤를 실행. `count != 0 && total / count > 10`
  - 성능: 값싼 검사를 앞에, 비싼 검사를 뒤에 둠
- 주의: 뒤쪽 식이 무언가를 바꾸는 코드(예: 함수 호출)라면 그 코드가 실행되지 않을 수 있음. 찾기 어려운 버그의 원인

### 부동소수점은 ==로 비교하지 않음

- 앞 글에서 본 것: `0.1 + 0.2 == 0.3`은 거짓
- 대신 쓰는 방법: 두 값의 차이가 충분히 작은지 확인
  - `std::abs(a - b) < 허용 오차`. `std::abs`는 `<cmath>` 헤더의 절댓값 함수 <CppRef path="cpp/numeric/math/fabs" />
- 허용 오차를 얼마로 둘지는 다루는 값의 크기에 따라 다름. 정해진 답이 없음

## 삼중 비교 연산자 <Badge text="C++20" />

- **삼중 비교 연산자** (three-way comparison operator) `<=>`: 두 값의 순서를 한 번에 알려 주는 연산자 <CppRef path="cpp/language/operator_comparison#Three-way_comparison" />
  - 모양 때문에 우주선 연산자(spaceship operator)라고도 부름
  - 한 번의 비교로 "작다 / 같다 / 크다" 가운데 어느 것인지 알려 줌
- 결과 타입: `bool`이 아님. 답이 셋 이상이라 `bool`로는 담을 수 없음
  - `<compare>` 헤더에 정의된 타입으로 돌려줌

| 결과 타입 | 나올 수 있는 값 | 이런 비교에서 나옴 |
| --- | --- | --- |
| `std::strong_ordering` <CppRef path="cpp/utility/compare/strong_ordering" /> | `less`, `equal`, `greater` | 정수 |
| `std::partial_ordering` <CppRef path="cpp/utility/compare/partial_ordering" /> | `less`, `equivalent`, `greater`, `unordered` | 부동소수점 |
| `std::weak_ordering` <CppRef path="cpp/utility/compare/weak_ordering" /> | `less`, `equivalent`, `greater` | 직접 만든 타입에서 골라 씀 |

- 세 타입의 차이
  - `strong_ordering`: 모든 값의 순서가 정해짐. 같다고 나온 두 값은 정말로 같은 값
  - `partial_ordering`: 순서를 정할 수 없는 경우가 있음(`unordered`). NaN은 어떤 값보다 작지도, 같지도, 크지도 않음
  - `weak_ordering`: 순서는 모두 정해지지만, 같지 않은데 동등한 값이 있을 수 있음. 예: 대소문자를 무시하고 비교할 때의 "Hello"와 "hello"
- `equal`과 `equivalent`: `equivalent`(동등)는 "순서로는 구별되지 않음"이라는 뜻. 예: `-0.0`과 `+0.0`
- 결과를 읽는 방법 두 가지
  - 값과 비교: `result == std::strong_ordering::less`
  - 이름 있는 함수: `std::is_lt(result)` <CppRef path="cpp/utility/compare/named_comparison_functions" />

| 함수 | 뜻 |
| --- | --- |
| `std::is_eq` / `std::is_neq` | `==` / `!=` |
| `std::is_lt` / `std::is_lteq` | `<` / `<=` |
| `std::is_gt` / `std::is_gteq` | `>` / `>=` |

## 헷갈리기 쉬운 점

- `case` 줄은 실행을 멈추지 않음
  - `case`는 "여기로 들어오라"는 표지판일 뿐. 멈추는 것은 `break`
- `if (a = b)`는 컴파일됨
  - 대입도 식이고 그 결과가 값이라서 조건 자리에 올 수 있음
  - 컴파일러가 경고해 주지만(`suggest parentheses around assignment used as truth value`) 오류는 아님
- `a < b < c`는 수학의 뜻대로 동작하지 않음
  - 왼쪽부터 `(a < b) < c`로 계산됨. `a < b`의 결과 `true`/`false`가 1/0으로 바뀌어 `c`와 비교됨
  - 바르게 쓰는 법: `a < b && b < c`

## 정리

| 요소 | 핵심 | 들어온 표준 |
| --- | --- | --- |
| `if` / `else if` / `else` | 위에서부터 처음 참인 곳 하나만 실행 | |
| `if (초기화; 조건)` | 그 `if` 문 안에서만 쓰는 변수 | C++17 |
| `switch` / `case` / `break` / `default` | 값 하나를 여러 상수와 비교 | |
| 폴스루 | `break`가 없으면 다음 `case`로 이어짐. 일부러라면 `[[fallthrough]];` | C++17 |
| 열거형 `switch` | `default` 없이 모든 열거자를 적음. `using enum`으로 짧게 | C++20 |
| `조건 ? A : B` | 값을 돌려주는 식 | |
| `&&`, <code>&#124;&#124;</code> | 단락 평가. 결과가 정해지면 뒤는 계산하지 않음 | |
| 부동소수점 비교 | `==` 대신 `std::abs(a - b) < 허용 오차` | |
| `<=>` | 순서를 한 번에. 결과는 `strong` / `partial` / `weak` `_ordering` | C++20 |

</details>

<details>
<summary>`count != 0 && total / count > 10`에서 `count`가 0이면 나눗셈은 실행되나요?</summary>

- 실행되지 않음
- `&&`의 왼쪽이 거짓이면 결과가 거짓으로 확정되므로 오른쪽은 계산하지 않음(단락 평가)

</details>

<details>
<summary>`double`끼리 `<=>`로 비교한 결과 타입이 `std::strong_ordering`이 아닌 이유는?</summary>

- NaN 때문. NaN은 어떤 값과도 순서를 정할 수 없음
- 그래서 "순서 없음"(`unordered`)을 표현할 수 있는 `std::partial_ordering`이 결과 타입

</details>

<details>
<summary>C++11에서 `if (int total{ a * b }; total > 100) { ... }`를 어떻게 바꿔 쓰나요?</summary>

- `int total{ a * b };`를 `if` 문 앞에 선언
- `total`이 바깥에 남지 않게 하려면 선언과 `if` 문 전체를 `{ }`로 감쌈

</details>
