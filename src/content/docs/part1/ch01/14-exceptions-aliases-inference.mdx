## 예외

- 문제 상황
  - 함수가 일을 끝낼 수 없는 상황이 있음. 0으로 나누라는 요청, 열리지 않는 파일, 끊어진 연결
  - 방법 하나: 약속한 특별한 값이나 오류 코드를 돌려줌. 호출한 쪽이 확인을 잊으면 문제를 모르고 지나감
- **예외** (exception): 정상적인 흐름에서 벗어난 상황을 알리는 장치 <CppRef path="cpp/language/exceptions" />

| 용어 | 뜻 | 문법 |
| --- | --- | --- |
| 예외를 **던진다** (throw) | 문제를 발견한 코드가 그것을 알림 | `throw 예외객체;` <CppRef path="cpp/language/throw" /> |
| 예외를 **잡는다** (catch) | 다른 코드가 그 알림을 받아 처리함 | `try { ... } catch (타입 이름) { ... }` <CppRef path="cpp/language/try_catch" /> |

```cpp
int average(int total, int count)
{
    if (count == 0) {
        throw std::invalid_argument{ "count는 0일 수 없습니다." };
    }
    return total / count;
}
```

- `throw`가 실행되면 함수는 값을 돌려주지 않고 그 자리에서 끝남
- `std::invalid_argument`: 표준 라이브러리가 제공하는 예외 타입 가운데 하나. `<stdexcept>` 헤더 <CppRef path="cpp/error/invalid_argument" />
- 잡는 쪽: 예외가 날 수 있는 코드를 `try` 블록으로 감싸고, 바로 뒤에 `catch` 블록을 둠

```cpp
try {
    // 예외가 던져질 수 있는 코드
} catch (const std::invalid_argument& exception) {
    // 예외가 던져졌을 때 실행되는 코드
}
```

- 예외는 **const 참조**로 잡을 것. `catch (const std::invalid_argument& exception)`
- `what()`: 표준 라이브러리의 모든 예외가 갖고 있는 멤버 함수. 예외를 설명하는 문자열을 돌려줌

## 타입 별칭 <Badge text="C++11" />

- **타입 별칭** (type alias): 이미 있는 타입에 붙이는 새 이름 <CppRef path="cpp/language/type_alias" />

```cpp
using ScoreList = std::vector<int>;
```

- 새 타입을 만드는 것이 아님. 별칭과 원래 타입은 **완전히 같은 타입**
  - `ScoreList` 변수와 `std::vector<int>` 변수는 서로 대입할 수 있음
- 쓰는 이유
  - 길고 복잡한 타입에 짧은 이름을 붙임. 템플릿을 쓰면 타입이 금방 길어짐
  - 뜻이 드러나는 이름을 붙임. `std::vector<int>`보다 `ScoreList`가 무엇을 담는지 알려 줌
- 표준 라이브러리도 씀: `std::string`은 사실 `std::basic_string<char>`의 별칭

### typedef

- `typedef`: C++11 이전의 방식. 하는 일은 같지만 순서가 반대 <CppRef path="cpp/language/typedef" />

| 방식 | 코드 |
| --- | --- |
| 타입 별칭 | `using IntPtr = int*;` |
| `typedef` | `typedef int* IntPtr;` |

- `typedef`는 "원래 타입"이 앞, "새 이름"이 뒤. 읽기 헷갈림
- 권장: 항상 타입 별칭(`using`)을 쓸 것
  - 템플릿과 함께 쓸 때 타입 별칭만 할 수 있는 일이 있음. 12장에서 다룸

## 타입 추론

- **타입 추론** (type inference): 컴파일러가 식을 보고 타입을 알아내는 것
- 키워드 두 가지: `auto`, `decltype`

### auto <Badge text="C++11" />

- `auto`: 초기화하는 값의 타입으로 변수의 타입을 정함 <CppRef path="cpp/language/auto" />

```cpp
auto count{ 123 };              // int
auto size{ scores.size() };     // scores.size()가 돌려주는 타입
```

- 쓸모
  - 길고 복잡한 타입을 직접 적지 않아도 됨
  - 함수의 반환 타입이 바뀌어도, 받는 쪽 코드를 고치지 않아도 됨
- `auto`의 다른 쓰임: 함수의 반환 타입 추론, 구조적 바인딩(앞의 글들에서 다룸). 그 밖의 쓰임은 12장과 19장에서 다룸

### auto는 참조와 const를 떼어 냄

- 가장 중요한 주의점: `auto`는 타입에서 **참조와 `const`를 떼어 냄**. 그 결과 복사본이 만들어짐

| 코드 (`getMessage()`는 `const std::string&`를 돌려줌) | 변수의 타입 | 복사 |
| --- | --- | --- |
| `auto copy{ getMessage() };` | `std::string` | 일어남 |
| `auto& ref{ getMessage() };` | `const std::string&` | 없음 |
| `const auto& view{ getMessage() };` | `const std::string&` | 없음 |

- 복사를 원하지 않으면 `auto&` 또는 `const auto&`로 적을 것
- 같은 이유로 `auto result{ std::as_const(text) };`도 복사본. `const` 참조가 되지 않음

- 마지막 두 줄: 주소를 비교해 같은 객체인지 확인함. `view`는 원본과 같은 객체, `copy`는 다른 객체

### auto와 포인터

- 포인터도 `auto`로 받을 수 있음. `auto p{ &value };`의 타입은 `int*`
- 권장: `auto*`로 적을 것. 포인터라는 것이 코드에 드러남
- `const`와 함께 쓰면 `auto`와 `auto*`의 결과가 달라짐

| 코드 | 타입 | `const`인 것 |
| --- | --- | --- |
| `const auto p1{ &value };` | `int* const` | 포인터 |
| `auto const p2{ &value };` | `int* const` | 포인터 |
| `const auto* p3{ &value };` | `const int*` | 가리키는 값 |
| `auto* const p4{ &value };` | `int* const` | 포인터 |
| `const auto* const p5{ &value };` | `const int* const` | 둘 다 |

- 헷갈리는 곳: `const auto p1`
  - 기대: 가리키는 값을 보호하는 `const int*`
  - 실제: 포인터 자신이 `const`인 `int* const`. `auto`가 통째로 `int*`이고 거기에 `const`가 붙기 때문
- `auto*`로 적으면 `const int*`를 적을 때와 같은 규칙으로 읽힘

### auto와 중괄호

- 중괄호 초기화에는 두 가지 형태가 있음

| 형태 | 이름 |
| --- | --- |
| `T obj = { 값, ... };` | 복사 리스트 초기화 (copy list initialization) |
| `T obj{ 값, ... };` | 직접 리스트 초기화 (direct list initialization) |

- `auto`와 함께 쓰면 둘의 결과가 다름

| 코드 | 결과 |
| --- | --- |
| `auto a = { 11 };` | `std::initializer_list<int>` |
| `auto b = { 11, 22 };` | `std::initializer_list<int>` |
| `auto c{ 11 };` | `int` |
| `auto d{ 11, 22 };` | 오류. 값이 하나여야 함 |
| `auto e = { 11, 22.5 };` | 오류. 모든 값의 타입이 같아야 함 |

- 이 사이트의 방식(`auto c{ 11 };`)을 따르면 기대한 타입이 나옴

### decltype <Badge text="C++11" />

- `decltype(식)`: 그 식의 타입을 알려 줌 <CppRef path="cpp/language/decltype" />

```cpp
int x{ 123 };
decltype(x) y{ 456 };   // y의 타입은 x의 타입, 즉 int
```

- `auto`와의 차이: `decltype`은 참조와 `const`를 **떼어 내지 않음**
  - `decltype(getMessage()) b{ getMessage() };` → `b`의 타입은 `const std::string&`. 복사가 일어나지 않음
- 지금은 쓸 일이 많지 않음. 진가는 템플릿에서 드러남. 12장과 26장에서 다룸

## 이전 표준에서는

| 이 글에서 쓴 것 | 들어온 표준 | C++11에서는 |
| --- | --- | --- |
| `throw`, `try` / `catch`, `typedef` | C++11 이전 | 그대로 사용 |
| 타입 별칭 (`using 이름 = 타입;`) | C++11 | 그대로 사용 |
| `auto`, `decltype` | C++11 | 그대로 사용 |

- C++98 / C++03: 타입 별칭, `auto`, `decltype`이 없음. `typedef`를 쓰고 타입을 직접 적음
- `auto c{ 11 };`의 타입: 처음의 C++11 규칙에서는 `std::initializer_list<int>`였음. 이후 규칙이 고쳐져 `int`가 됨
  - GCC 16.2는 `-std=c++11`에서도 `int`로 추론함
  - 아주 오래된 컴파일러를 쓴다면 `auto c = 11;`처럼 적는 편이 안전

## 헷갈리기 쉬운 점

- 예외는 "오류 메시지 출력"이 아님
  - `throw`는 실행의 흐름을 바꿈. 잡는 곳이 나올 때까지 함수들을 빠져나감
  - 출력은 잡은 쪽에서 직접 해야 함
- 타입 별칭은 새 타입이 아님
  - `using Meters = double; using Seconds = double;`이라고 해도 둘은 같은 `double`. 서로 섞어 써도 컴파일러가 막지 않음
- `auto`는 "타입이 없다"거나 "나중에 정해진다"는 뜻이 아님
  - 컴파일할 때 타입이 하나로 정해지고, 그 뒤로는 바뀌지 않음
  - `auto x{ 1 }; x = "text";`는 컴파일 오류. `x`는 `int`
- `auto`로 받았더니 원본이 바뀌지 않음
  - 참조가 떨어져 나가 복사본을 받은 것. `auto&`로 받아야 원본을 다룸

## 정리

| 요소 | 핵심 | 들어온 표준 |
| --- | --- | --- |
| `throw` | 문제를 알림. 함수는 즉시 끝남 | |
| `try` / `catch` | 예외를 잡아 처리. `const` 참조로 잡음 | |
| 잡지 않은 예외 | 프로그램이 종료됨 | |
| `using 이름 = 타입;` | 타입 별칭. 새 타입이 아니라 다른 이름 | C++11 |
| `typedef 타입 이름;` | 옛 방식. `using`을 쓸 것 | |
| `auto` | 초기화 값에서 타입을 추론. 참조와 `const`는 떨어져 나감 | C++11 |
| `auto&`, `const auto&`, `auto*` | 참조, 읽기 전용 참조, 포인터로 받기 | C++11 |
| `decltype(식)` | 식의 타입. 참조와 `const`를 그대로 둠 | C++11 |

<details>
<summary>`using Count = int;`를 한 뒤 `Count a{ 3 }; int b{ a };`는 컴파일되나요?</summary>

- 컴파일됨
- `Count`는 `int`의 다른 이름일 뿐, 같은 타입

<details>
<summary>`const std::string& getName();`이 있을 때 `auto name{ getName() };`의 타입은 무엇이고, 복사가 일어나나요?</summary>

- `std::string`. 복사가 일어남
- `auto`가 참조와 `const`를 떼어 내기 때문
- 복사를 피하려면 `const auto& name{ getName() };`

</details>

<details>
<summary>`int value{ 1 }; const auto p{ &value };`에서 `*p = 2;`는 컴파일되나요?</summary>

- 컴파일됨
- `p`의 타입은 `int* const`. 포인터 자신이 `const`이고, 가리키는 값은 바꿀 수 있음
- 가리키는 값을 보호하려면 `const auto* p{ &value };`

</details>

<details>
<summary>`auto`와 `decltype`의 차이는?</summary>

- `auto`: 참조와 `const`를 떼어 냄
- `decltype`: 식의 타입을 그대로 가져옴. 참조와 `const`가 남음

</details>
