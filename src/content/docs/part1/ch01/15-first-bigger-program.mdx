## 표준 라이브러리를 먼저 떠올릴 것

- 표준 라이브러리에는 바로 가져다 쓸 수 있는 클래스가 많음. 직접 만들기 전에 이미 있는지부터 확인할 것
- 표준 라이브러리를 쓰면 좋은 점
  - 다시 만들 필요가 없음. 그 시간을 풀려는 문제에 씀
  - 수많은 사용자가 써 오며 검증된 코드
  - 성능까지 다듬어져 있어, 직접 만든 것보다 빠른 경우가 대부분
- C 언어에 익숙한 사람은 특히 주의: C의 방식으로 풀 수 있는 문제에는 대개 더 쉽고 안전한 표준 라이브러리 방식이 있음
- 1장에서 이미 만난 것: `std::string`, `std::array`, `std::vector`, `std::pair`, `std::optional`
- 표준 라이브러리 전체의 지도: 16장부터 24장에서 다룸

## 1단계: Task 클래스

- 하는 일: 할 일 하나에 대한 정보를 담고, 그 정보를 읽고 바꾸는 멤버 함수를 제공

| 데이터 멤버 | 뜻 | 첫 값 |
| --- | --- | --- |
| `m_title` | 제목 | 생성자에서 받음 |
| `m_id` | 번호 | `-1` (아직 번호가 없다는 표시) |
| `m_priority` | 우선순위. 클수록 급함 | `DefaultPriority` (3) |
| `m_done` | 끝냈는지 | `false` |

- 여기서 볼 문법
  - 데이터 멤버는 모두 `private`. 읽고 바꾸는 길은 `public` 멤버 함수뿐
  - 첫 값은 클래스 내부 초기화로 정함. 생성자는 제목만 받음
  - 값을 바꾸지 않는 멤버 함수에는 모두 `const`
  - 문자열은 `const std::string&`로 받고, `const std::string&`로 돌려줌. 복사가 일어나지 않음
  - 상수 이름: 대문자로 시작(`DefaultPriority`). 변수와 구별하기 위한 이 사이트의 관례

### 새로 나오는 문법: 기본 인수

- **기본 인수** (default argument): 호출할 때 인수를 생략하면 대신 쓰이는 값 <CppRef path="cpp/language/default_arguments" />

```cpp
void raisePriority(int amount = DefaultPriorityStep);
```

| 호출 | 쓰이는 값 |
| --- | --- |
| `task.raisePriority();` | `DefaultPriorityStep` (1) |
| `task.raisePriority(5);` | 5 |

- 기본 인수는 **선언에만** 적음. 정의를 따로 적을 때는 다시 적지 않음

### 클래스 안에서도 getter와 setter를 쓰는 이유

- `display()`는 `m_priority`를 직접 읽을 수 있는데도 `getPriority()`를 부름
- 좋은 습관으로 여겨지는 이유
  - 나중에 `setPriority()`에 범위 검사를 넣으면, 그 함수를 거치는 모든 코드에 한꺼번에 적용됨
  - 디버깅할 때 한곳에 중단점을 걸어 값이 읽히고 바뀌는 순간을 모두 볼 수 있음
  - 데이터를 담는 방식을 바꿔도 getter와 setter만 고치면 됨
- 단순해 보여도, 데이터 멤버를 `public`으로 여는 것보다 낫다는 뜻

## 2단계: TaskList 클래스

- 하는 일: `Task` 객체들을 `std::vector`에 모아 두고, 추가·검색·출력을 맡음

| 멤버 함수 | 하는 일 |
| --- | --- |
| `addTask(제목)` | 새 할 일을 만들어 번호를 매기고 목록에 넣음. 넣은 할 일의 참조를 돌려줌 |
| `getTask(번호)` | 그 번호의 할 일을 찾아 참조를 돌려줌. 없으면 예외 |
| `getTask(제목)` | 그 제목의 할 일을 찾아 참조를 돌려줌. 없으면 예외 |
| `displayAll()` / `displayPending()` / `displayDone()` | 전체 / 남은 일 / 끝낸 일 출력 |

- 여기서 볼 문법
  - 번호는 `TaskList`가 매김. `m_nextId++`: 지금 값을 쓰고 나서 1 올림(후위 증가)
  - `getTask`가 두 개: 매개변수가 다르므로 함수 오버로딩
  - 찾는 반복문은 `for (auto& task : m_tasks)`. 복사본이 아니라 벡터 안의 원소 자체를 돌려줘야 하므로 `auto&`
  - 출력하는 반복문은 `for (const auto& task : m_tasks)`. 읽기만 하므로 `const auto&`
  - 찾지 못하면 `throw std::logic_error{ ... }`. 돌려줄 참조가 없으므로 "없음"을 값으로 나타낼 수 없음
  - `m_tasks.back()`: 벡터의 마지막 원소의 참조

## 파일로 나눈다면

- 이 사이트의 실행 예제는 파일 하나만 쓸 수 있어 전부 한 파일에 적었음
- 실제 프로젝트라면 클래스마다 파일을 나눔 <Badge text="C++20" />

| 파일 | 내용 | 첫 줄 |
| --- | --- | --- |
| `task.cppm` | `Task` 클래스의 정의 (모듈 인터페이스) | `export module task;` |
| `task.cpp` | `Task` 멤버 함수들의 정의 (모듈 구현) | `module task;` |
| `task_list.cppm` | `TaskList` 클래스의 정의 | `export module task_list;` |
| `task_list.cpp` | `TaskList` 멤버 함수들의 정의 | `module task_list;` |
| `main.cpp` | 사용자 인터페이스 | `import task_list;` |

- 모듈 밖에서 써야 하는 것에만 `export`를 붙임
  - `Task` 클래스, `DefaultPriorityStep`: 밖에서 쓰므로 `export`
  - `DefaultPriority`: `Task` 안에서만 쓰므로 `export`하지 않음
- 모듈의 자세한 내용: 11장에서 다룸
- C++17까지: 모듈이 없음. `.cppm` 대신 헤더 파일(`task.h`)에 클래스 정의를 두고 `#include "task.h"`로 가져옴

## 헷갈리기 쉬운 점

- `addTask`가 돌려준 참조를 오래 들고 있으면 안 됨
  - `std::vector`는 원소가 늘어나 자리가 모자라면 더 큰 메모리로 통째로 옮겨 감. 그러면 예전 원소를 가리키던 참조는 사라진 곳을 가리키게 됨
  - 이 글의 코드는 참조를 받자마자 쓰고, 다음 `addTask` 뒤에는 다시 쓰지 않음
  - 나중에 다시 필요하면 번호를 기억해 두었다가 `getTask(번호)`로 다시 찾을 것
- 기본 인수를 정의에도 적으면 컴파일 오류
  - 선언과 정의를 따로 적을 때는 선언에만 적음
- `int selection;`처럼 초기화하지 않고 `std::cin >>`으로 받는 코드를 흔히 봄
  - 입력이 실패하면 변수에 무엇이 들어 있을지 알기 어려움. 이 글의 코드는 `int selection{};`으로 0을 넣어 둠
- 프로그램이 길어 보여도 새로 배울 문법은 없음
  - 이해되지 않는 줄이 있으면 그 문법을 다룬 앞의 글로 돌아가 볼 것
  - 가장 좋은 방법은 코드를 고쳐서 실행해 보는 것
