## C 스타일 배열

- **배열** (array): 같은 타입의 값 여러 개를 줄지어 담는 것. 위치 번호로 각 값에 접근 <CppRef path="cpp/language/array" />
- C 스타일 배열: C 언어에서 물려받은 배열. `타입 이름[크기]`로 만듦
- 새 코드에서는 쓰지 않는 것이 좋음. 아래의 `std::array`와 `std::vector`를 씀
  - 그래도 알아야 하는 이유: 오래된 코드에서 계속 만나게 됨

```cpp
int scores[3];     // int 세 칸
scores[0] = 90;    // 첫 칸
scores[2] = 60;    // 마지막 칸
```

- 규칙
  - 크기는 선언할 때 정해야 하고, 상수여야 함. 변수를 크기로 쓸 수 없음
  - **첫 칸의 번호는 0**. 마지막 칸의 번호는 "크기 - 1"
  - 번호를 대괄호 `[ ]` 안에 적어 칸을 고름. 이 번호를 인덱스(index)라고 부름

### 초기화

| 코드 | 결과 |
| --- | --- |
| `int a[3];` | 초기화하지 않음. 세 칸 모두 알 수 없는 값 |
| `int a[3]{};` | 세 칸 모두 0 |
| `int a[3]{ 7 };` | 7, 0, 0. 값을 적지 않은 칸은 0 |
| `int a[]{ 1, 2, 3, 4 };` | 크기를 비우면 컴파일러가 값의 개수(4)로 정함 |

- 오래된 코드의 표기: `int a[3] = { 0 };`, `int a[3] = {};`. 등호가 있어도 뜻은 같음

### 칸의 개수 알아내기

| 방법 | 코드 | 들어온 표준 |
| --- | --- | --- |
| `std::size` | `std::size(numbers)` | <Badge text="C++17" /> <CppRef path="cpp/iterator/size" /> |
| 옛 방법 | `sizeof(numbers) / sizeof(numbers[0])` | |

- `std::size`: `<array>` 등 여러 헤더에 들어 있음
- 옛 방법의 원리: 배열 전체의 바이트 수를 한 칸의 바이트 수로 나눔
- `std::size_t`: 크기나 개수를 나타내는 부호 없는 정수 타입. `<cstddef>` 헤더 <CppRef path="cpp/types/size_t" />
  - 리터럴 접미사 `uz`: `42uz`는 `std::size_t` 타입의 42 <Badge text="C++23" />

## std::array <Badge text="C++11" />

- `std::array`: 크기가 고정된 배열을 나타내는 표준 라이브러리 타입. `<array>` 헤더 <CppRef path="cpp/container/array" />
  - C 스타일 배열을 얇게 감싼 것. 성능은 같음
- C 스타일 배열보다 나은 점
  - 자기 크기를 항상 알고 있음: `scores.size()`
  - 포인터로 자동 변환되지 않음. 그 때문에 생기던 버그가 없음 (포인터는 뒤의 글에서 다룸)
  - 원소를 차례로 도는 기능(반복자)을 제공함. 17장에서 다룸
- 선언: 꺾쇠괄호 안에 **원소의 타입**과 **원소의 개수**를 적음

```cpp
std::array<int, 3> scores{ 90, 75, 60 };
```

- 꺾쇠괄호의 정체: `std::array`는 클래스 템플릿. 꺾쇠괄호 안에 적는 것을 템플릿 인수라고 부름. 12장에서 다룸
- **CTAD** (class template argument deduction, 클래스 템플릿 인수 추론): 초기화 값을 보고 컴파일러가 꺾쇠괄호 안을 알아내는 기능 <Badge text="C++17" /> <CppRef path="cpp/language/class_template_argument_deduction" />
  - `std::array prices{ 4500, 3000 };` → `std::array<int, 2>`
  - 초기화 값이 있어야만 동작함
- C 스타일 배열과 `std::array`의 공통점: 크기가 컴파일할 때 정해짐. 실행 중에 늘리거나 줄일 수 없음

## std::vector

- `std::vector`: 실행 중에 크기가 바뀌는 배열. `<vector>` 헤더 <CppRef path="cpp/container/vector" />
  - 원소를 추가하면 필요한 메모리를 알아서 마련함. 메모리 관리를 직접 하지 않아도 됨
  - C 스타일 배열을 대신하는, 더 유연하고 안전한 수단
- **컨테이너** (container): 값을 여러 개 담아 두는 타입을 통틀어 부르는 말. `std::array`와 `std::vector`가 대표적. 18장에서 자세히 다룸
- 선언: 꺾쇠괄호 안에 원소의 타입을 적음. 모든 원소는 같은 타입이어야 함

```cpp
std::vector<int> numbers{ 11, 22 };
```

| 하는 일 | 코드 |
| --- | --- |
| 뒤에 원소 추가 | `numbers.push_back(33);` |
| 원소 읽기, 바꾸기 | `numbers[0]` |
| 원소의 개수 | `numbers.size()` |

- CTAD도 됨: `std::vector prices{ 4500.0, 3000.5 };` → `std::vector<double>` <Badge text="C++17" />
  - 초기화 값이 없으면 안 됨. `std::vector numbers;`는 컴파일 오류. 원소 타입을 알아낼 근거가 없음
- `std::println`으로 `vector`를 통째로 출력할 수 있음: `[11, 22, 33, 44]` <Badge text="C++23" />

### 어느 것을 쓸까

| 상황 | 쓸 것 |
| --- | --- |
| 개수가 실행 중에 바뀜, 또는 잘 모르겠음 | `std::vector` |
| 개수가 처음부터 정해져 있고 바뀌지 않음 | `std::array` |
| 오래된 코드를 읽거나 C 코드와 맞물려야 함 | C 스타일 배열 |

## std::pair

- `std::pair`: 값 두 개를 묶은 타입. 두 값의 타입이 달라도 됨. `<utility>` 헤더 <CppRef path="cpp/utility/pair" />
- 두 값의 이름은 정해져 있음: `first`, `second`
- CTAD도 됨: `std::pair point{ 10, 'A' };` <Badge text="C++17" />

- 주의: 함수가 값 두 개를 돌려줘야 할 때 `pair`보다 구조체가 나음
  - `pair`를 받은 쪽은 `first`, `second`라는 뜻 없는 이름을 써야 함
  - 구조체를 만들면 `price`, `grade`처럼 뜻이 드러나는 이름을 붙일 수 있음

## std::optional <Badge text="C++17" />

- `std::optional`: 어떤 타입의 값 하나를 담고 있거나, **아무것도 담고 있지 않은** 타입. `<optional>` 헤더 <CppRef path="cpp/utility/optional" />
- 문제 상황
  - 함수가 결과를 돌려줄 수도 있고 못 돌려줄 수도 있음. 예: 찾는 것이 없을 때
  - 예전 방법 1: 약속한 특별한 값을 돌려줌 (`-1`, `nullptr` 등). 그 값이 진짜 결과와 헷갈릴 수 있음
  - 예전 방법 2: 성공 여부를 `bool`로 돌려주고, 진짜 결과는 매개변수를 통해 따로 내보냄. 쓰기 번거로움
- `std::optional`을 쓰면: "값이 없음"이 타입에 드러남. 특별한 값을 약속할 필요가 없음
- 선언: 꺾쇠괄호 안에 담을 타입을 적음. `std::optional<int>`

| 하는 일 | 코드 |
| --- | --- |
| 값 없음을 돌려줌 | `return std::nullopt;` 또는 `return {};` |
| 값이 있는지 확인 | `data.has_value()` 또는 `if (data)` |
| 값 꺼내기 | `data.value()` 또는 `*data` |
| 값이 없으면 대신 쓸 값 | `data.value_or(0)` |

<RunCode client:load code={optionalCode} />

- 값이 없는데 꺼내면
  - `value()`: `std::bad_optional_access` 예외가 발생하고, 처리하지 않으면 프로그램이 멈춤. 예외는 뒤의 글에서 다룸
  - `*data`: 검사하지 않음. 무슨 일이 생길지 알 수 없음. 값이 있다고 확인한 뒤에만 쓸 것
- 해 볼 것: `main` 끝에 `std::println("{}", guest.value());`를 추가하고 실행
  - 결과: `terminate called after throwing an instance of 'std::bad_optional_access'`
- `*` 연산자의 원래 쓰임(포인터): 이 장의 뒤쪽 "포인터와 동적 메모리" 글에서 다룸
- 참조는 담을 수 없음. `std::optional<T&>`는 안 됨. 대신 포인터를 담음 (참조도 뒤의 글에서 다룸)

## 구조적 바인딩 <Badge text="C++17" />

- **구조적 바인딩** (structured binding): 묶여 있는 값들을 한 줄로 풀어 변수 여러 개에 나눠 담는 문법 <CppRef path="cpp/language/structured_binding" />
- 풀 수 있는 것: 배열, `std::array`, 구조체, `std::pair` 등

```cpp
std::array values{ 11, 22, 33 };
auto [first, second, third]{ values };
```

- 규칙
  - 반드시 `auto`를 씀. `int [a, b, c]`처럼 타입을 직접 적을 수 없음
  - 변수의 개수가 풀려는 값의 개수와 같아야 함
  - 구조체는 모든 데이터 멤버가 공개(`public`)되어 있어야 함. `struct`는 기본이 공개
- 복사가 아니라 원본을 가리키게 하는 방법: `auto&`, `const auto&`. 이 장의 뒤쪽 "참조" 글에서 다룸

## 헷갈리기 쉬운 점

- 크기가 3인 배열에 `[3]`번 칸은 없음
  - 쓸 수 있는 번호는 0, 1, 2
  - 범위를 벗어난 번호를 써도 `[ ]`는 검사하지 않음. 컴파일도 되고, 남의 메모리를 건드려 엉뚱한 일이 생김
  - 검사가 필요하면 `at()`을 씀: `numbers.at(3)`은 범위를 벗어나면 예외를 발생시킴 (`std::array`, `std::vector` 모두 지원)
- `std::array<int, 3>`와 `std::vector<int>`의 꺾쇠괄호 안이 다른 이유
  - `std::array`는 크기가 타입의 일부. 크기가 다르면 다른 타입
  - `std::vector`는 크기가 실행 중에 바뀌므로 타입에 크기가 없음
- `std::vector<int> v{ 5 };`와 `std::vector<int> v(5);`는 다름
  - 중괄호: 원소가 `5` 하나인 벡터
  - 소괄호: 원소가 다섯 개(모두 0)인 벡터

## 정리

| 요소 | 핵심 | 들어온 표준 |
| --- | --- | --- |
| C 스타일 배열 | `int a[3]{};`. 번호는 0부터. 새 코드에서는 피함 | |
| `std::array<T, N>` | 고정 크기. 자기 크기를 앎 | C++11 |
| `std::vector<T>` | 크기가 바뀌는 배열. `push_back`, `size`, `[ ]` | |
| CTAD | 초기화 값에서 꺾쇠괄호 안을 추론 | C++17 |
| `std::size_t`, `std::size` | 개수를 나타내는 타입, 개수를 알아내는 함수 | `std::size`는 C++17 |
| `std::pair<A, B>` | 값 두 개의 묶음. `first`, `second` | |
| `std::optional<T>` | 값이 있거나 없음. `has_value`, `value`, `value_or` | C++17 |
| 구조적 바인딩 | `auto [a, b]{ 묶음 };` | C++17 |
