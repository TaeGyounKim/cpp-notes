## 참조 변수

- **참조** (reference): 이미 있는 변수에 붙이는 다른 이름 <CppRef path="cpp/language/reference" />
- 선언: 타입 뒤에 `&`를 붙임

```cpp
int x{ 3 };
int& ref{ x };   // ref는 x의 다른 이름
ref = 10;        // x가 10이 됨
```

- 참조를 바꾸면 원래 변수가 바뀌고, 원래 변수를 바꾸면 참조로 읽은 값도 바뀜. 둘은 같은 것
- 쓰는 문법은 보통의 변수와 같음. 포인터처럼 `*`를 붙일 필요가 없음
- 규칙 두 가지
  - **만들 때 반드시 초기화**해야 함. `int& ref;`는 컴파일 오류
  - **한번 붙으면 다른 변수로 옮길 수 없음**
- 선언에서의 `&`와 식에서의 `&`
  - 선언에서: `int& ref` → 참조라는 표시
  - 식에서: `&x` → `x`의 주소 (앞 글)

- 볼 것: `ref = y;`
  - 포인터라면 가리키는 곳이 바뀌었겠지만, 참조는 그렇지 않음
  - 참조에 대입하는 것은 언제나 "원래 변수에 값을 넣는 것"

### const 참조

- **const 참조** (reference-to-const): 읽기만 할 수 있는 참조. `const 타입&`
  - 이 참조를 거쳐서는 값을 바꿀 수 없음
  - 원래 변수가 `const`가 되는 것은 아님. 원래 변수로는 여전히 바꿀 수 있음
- 포인터보다 단순한 이유
  - 참조는 원래부터 다른 변수로 옮길 수 없음. "참조 자신이 `const`"인 경우를 따로 생각할 필요가 없음
  - 그래서 `const`가 붙는 자리는 "가리키는 값" 하나뿐
- `const int& ref`와 `int const& ref`는 같은 뜻
- 이름 없는 값에는 `const` 참조만 붙일 수 있음

| 코드 | 결과 | 이유 |
| --- | --- | --- |
| `int& a{ 5 };` | 오류 | 리터럴 5를 바꿀 수 있다는 뜻이 되어 버림 |
| `const int& a{ 5 };` | 가능 | 읽기만 하므로 문제없음 |
| `std::string& s{ makeGreeting() };` | 오류 | 함수가 돌려준 임시 객체도 이름 없는 값 |
| `const std::string& s{ makeGreeting() };` | 가능 | 임시 객체는 참조가 살아 있는 동안 함께 살아 있음 |

- **임시 객체** (temporary object): 식을 계산하는 도중에 잠깐 생기는, 이름 없는 객체. 함수가 값으로 돌려준 결과가 대표적

### 포인터와 참조를 함께 쓸 때

- 포인터에 대한 참조: `int*& pRef`. "`int*` 변수의 다른 이름"
  - 드물게 쓰임. 함수 안에서 호출한 쪽의 포인터를 바꿔야 할 때
- 참조의 주소: `&ref`는 원래 변수의 주소와 같음
- 만들 수 없는 것: 참조에 대한 참조(`int& &`), 참조를 가리키는 포인터(`int&*`)

## 참조 매개변수

- 참조가 가장 많이 쓰이는 곳: 함수의 매개변수
- 함수에 값을 넘기는 두 가지 방식

| | **값으로 전달** (pass-by-value) | **참조로 전달** (pass-by-reference) |
| --- | --- | --- |
| 매개변수 | `int n` | `int& n` |
| 받는 것 | 인수의 복사본 | 인수 그 자체(의 다른 이름) |
| 함수 안에서 바꾸면 | 복사본만 바뀜 | 호출한 쪽의 변수가 바뀜 |
| 호출하는 문법 | `f(count)` | `f(count)`. 같음 |

- C 언어의 방식: 포인터를 넘기고 함수 안에서 `*`로 역참조. 참조를 쓰면 `&`와 `*`가 사라져 코드가 깔끔해짐

  - 포인터를 갖고 있는데 참조를 받는 함수를 부를 때: `*pa`처럼 역참조해서 넘김
- 해 볼 것: 주석 처리된 마지막 줄의 `//`를 지우고 실행

### const 참조로 전달

- `const 타입&` 매개변수: 복사하지 않고 받되, 바꾸지 않겠다는 약속
- 두 가지를 한꺼번에 얻음
  - 효율: 복사가 일어나지 않음. 큰 객체일수록 차이가 큼
  - 안전: 함수가 원본을 바꿀 수 없음
- 리터럴과 임시 객체도 받을 수 있음. `printTitle("Hello")`

### 매개변수를 정하는 기준

| 넘기는 것 | 함수가 바꾸는가 | 매개변수 |
| --- | --- | --- |
| `int`, `double` 같은 단순한 기본 타입 | 바꾸지 않음 | 값 (`int n`) |
| 객체 (`std::string`, `std::vector`, 직접 만든 클래스 등) | 바꾸지 않음 | `const` 참조 (`const std::string& s`) |
| 무엇이든 | 바꿔야 함 | 참조 (`std::string& s`) |

- 참조로 전달하는 이유는 "바꾸려고"만이 아님
  - 큰 객체는 복사에 시간이 걸림
  - 복사 자체가 허용되지 않는 클래스도 있음
- 이 기준은 9장에서 조금 고쳐짐. 이동 의미론을 배우면 객체를 값으로 받는 것이 나은 경우가 생김

## 참조 데이터 멤버와 구조적 바인딩

- 클래스의 데이터 멤버도 참조일 수 있음
  - 참조는 만들 때 초기화해야 하므로, **생성자 초기화 리스트**에서 초기화해야 함. 생성자 본문에서 대입하는 것으로는 안 됨
- 구조적 바인딩에 `&`를 붙이면 복사본이 아니라 원본의 다른 이름이 됨 <Badge text="C++17" />

| 코드 | 풀려 나온 변수 |
| --- | --- |
| `auto [a, b]{ item };` | 복사본 |
| `auto& [a, b]{ item };` | 원본의 다른 이름. 바꾸면 `item`이 바뀜 |
| `const auto& [a, b]{ item };` | 원본을 읽기 전용으로 |

- 범위 기반 `for` 문도 같은 방식
  - `for (int score : scores)`: 복사본
  - `for (int& score : scores)`: 원소 자체. 바꾸면 컨테이너가 바뀜
  - `for (const std::string& name : names)`: 복사 없이 읽기만

## 참조를 돌려주는 함수

- 함수의 반환 타입도 참조일 수 있음
- 쓰는 경우
  - 돌려줄 것이 복사하기 비싼 객체일 때. 흔한 예: 데이터 멤버를 `const` 참조로 내주는 멤버 함수
  - 돌려받은 것에 바로 대입할 수 있게 하려고. `=`, `+=` 같은 연산자를 직접 만들 때. 15장에서 다룸
- 절대 하면 안 되는 것: **함수 안의 지역 변수를 참조로 돌려주기**
  - 지역 변수는 함수가 끝나면 사라짐. 돌려받은 참조는 이미 없는 것을 가리킴
  - C++23에서는 컴파일 오류. 그 이전 표준에서는 경고만 나오고 컴파일됨

```cpp
int& broken()
{
    int local{ 5 };
    return local;   // 함수가 끝나면 local은 사라진다.
}
```

## 결과를 돌려주는 방법: 출력 매개변수 대 반환

- **출력 매개변수** (output parameter): 결과를 내보내려고 받는 `const`가 아닌 참조 매개변수
- 예전에 출력 매개변수를 쓴 이유: 큰 객체를 값으로 돌려주면 복사가 일어나 느릴 것이라고 생각했음
- 지금은 그렇지 않음
  - 함수가 임시 객체를 바로 돌려주는 경우(`return 타입{ ... };`): 복사나 이동을 하지 않도록 표준이 **보장**함 <Badge text="C++17" /> <CppRef path="cpp/language/copy_elision" />
  - 이름 있는 지역 변수를 돌려주는 경우(`return result;`): 컴파일러가 복사를 생략하는 것이 허용됨. 보장은 아니지만 대부분의 컴파일러가 함. 이 최적화를 NRVO(named return value optimization)라고 부름
- 권장: **결과는 값으로 돌려줄 것**. 출력 매개변수는 피함
  - 여러 개를 돌려줘야 하면 구조체에 담아 돌려줌

## 참조와 포인터 가운데 고르기

- 참조로 할 수 있는 일은 포인터로도 모두 할 수 있음. 그래도 참조를 먼저 고려함

| | 참조 | 포인터 |
| --- | --- | --- |
| "아무것도 가리키지 않음" | 불가. 항상 무언가에 붙어 있음 | 가능 (`nullptr`) |
| 다른 것을 가리키도록 바꾸기 | 불가 | 가능 |
| 쓰는 문법 | 보통의 변수와 같음 | `*`, `->`, `&`가 필요 |
| 실수할 여지 | 적음 | 널 포인터, 초기화하지 않은 포인터 |

- 권장: **참조를 쓸 수 있으면 참조**. 포인터는 참조로 안 될 때만
- 포인터가 필요한 경우
  - 가리키는 대상을 나중에 바꿔야 할 때
  - "없음"을 나타내야 할 때 (`nullptr`)
  - `new`로 만든 메모리의 주소를 받아 둘 때
- 예전 코드의 관례: 받은 쪽이 `delete`할 책임을 지면 포인터, 아니면 참조로 넘김
  - 지금은 책임을 넘길 때 스마트 포인터를 씀. 7장에서 다룸
- 참조도 완전히 안전한 것은 아님
  - 잘못된 포인터를 역참조해서 참조에 넘기면 참조도 잘못된 곳을 가리킴
  - 이미 사라진 변수를 가리키는 참조도 만들 수 있음(위의 지역 변수 반환)

## const_cast

- 형변환 연산자는 모두 다섯 가지: `const_cast`, `static_cast`, `reinterpret_cast`, `dynamic_cast`, `std::bit_cast`
  - `static_cast`: "형변환, 부동소수점, 연산자" 글에서 다룸
  - 나머지: 10장에서 다룸
- `const_cast`: `const`를 붙이거나 떼는 형변환. `const`를 뗄 수 있는 유일한 형변환 <CppRef path="cpp/language/const_cast" />
- 원칙적으로는 쓸 일이 없어야 함. `const`인 것은 `const`로 남아야 함
- 실제로 쓰게 되는 경우
  - 고칠 수 없는 외부 라이브러리의 함수가, 값을 바꾸지 않으면서도 매개변수에 `const`를 빠뜨렸을 때
  - 그 함수가 정말로 값을 바꾸지 않는다고 확신할 때만 사용
  - 원래부터 `const`로 만들어진 객체를 `const_cast`로 풀어서 바꾸면 정의되지 않은 동작
- `std::as_const(객체)`: 객체를 `const` 참조로 바꿔 돌려줌. `<utility>` 헤더 <Badge text="C++17" /> <CppRef path="cpp/utility/as_const" />
  - `const_cast<const 타입&>(객체)`와 같은 일을 더 짧고 읽기 쉽게

## 헷갈리기 쉬운 점

- `ref = other;`는 참조를 옮기는 것이 아님
  - 참조가 붙어 있는 원래 변수에 `other`의 값을 넣는 것
- `&`의 세 가지 뜻
  - 선언에서 타입 뒤: 참조 (`int& ref`)
  - 식에서 변수 앞: 주소 (`&x`)
  - 두 값 사이: 비트 AND (`a & b`)
- `const` 참조가 붙어 있어도 값은 바뀔 수 있음
  - `const int& view{ score };` 뒤에 `score = 90;`을 하면 `view`로 읽은 값도 90
  - `const` 참조는 "이 이름으로는 바꾸지 않겠다"는 뜻일 뿐
- 함수 호출만 봐서는 참조로 넘기는지 알 수 없음
  - `addOne(count)`가 `count`를 바꾸는지는 함수 선언을 봐야 앎
  - 그래서 바꾸지 않는 매개변수에는 `const`를 꼭 붙여 둘 것. 선언만 보고 판단할 수 있게 됨

| `int& ref{ x };` | `x`의 다른 이름. 반드시 초기화, 옮길 수 없음 | |
| `const int& ref` | 읽기 전용 참조. 리터럴과 임시 객체에도 붙음 | |
| 값으로 전달 / 참조로 전달 | 복사본을 받음 / 원본을 받음 | |
| `const 타입&` 매개변수 | 복사 없이 받고, 바꾸지 않음. 객체를 받을 때의 기본 | |
| `auto& [a, b]`, `for (int& x : v)` | 복사본 대신 원본의 다른 이름 | 구조적 바인딩은 C++17 |
| 참조 반환 | 지역 변수의 참조는 절대 돌려주지 말 것 | |
| 출력 매개변수 | 피함. 결과는 값으로 돌려줌 | 복사 생략 보장은 C++17 |
| 참조 대 포인터 | 참조를 먼저. 포인터는 참조로 안 될 때만 | |
| `const_cast`, `std::as_const` | `const`를 떼기 / 붙이기 | `std::as_const`는 C++17 |

## 복습 질문

<details>
<summary>`int a{ 1 }; int b{ 2 }; int& r{ a }; r = b; b = 5;`를 실행한 뒤 `a`의 값은?</summary>

- 2
- `r = b;`는 `r`을 `b`로 옮기는 것이 아니라 `a`에 `b`의 값 2를 넣는 것
- 그 뒤에 `b`를 바꿔도 `a`와는 관계가 없음

</details>

<details>
<summary>`void reset(int n) { n = 0; }`으로는 호출한 쪽의 변수를 0으로 만들 수 없습니다. 어떻게 고치나요?</summary>

- 매개변수를 참조로 바꿈: `void reset(int& n) { n = 0; }`
- 값으로 받으면 `n`은 복사본이라 바꿔도 원본에 영향이 없음

</details>

<details>
<summary>문자열을 받아 출력만 하는 함수의 매개변수는 어떻게 선언하는 것이 좋은가요?</summary>

- `const std::string& text`
- 복사가 일어나지 않고, 함수가 원본을 바꿀 수 없으며, 리터럴도 받을 수 있음

</details>

<details>
<summary>`int& r{ 5 };`는 왜 컴파일되지 않나요?</summary>

- 이름 없는 값(리터럴)에는 `const`가 아닌 참조를 붙일 수 없음
- `const int& r{ 5 };`는 가능

</details>

<details>
<summary>함수가 지역 변수의 참조를 돌려주면 안 되는 이유는?</summary>

- 지역 변수는 함수가 끝나면 사라짐
- 돌려받은 참조는 이미 없는 것을 가리키게 됨

</details>

<details>
<summary>참조 대신 포인터를 써야 하는 경우 두 가지는?</summary>

- 가리키는 대상을 나중에 바꿔야 할 때
- "가리키는 것이 없음"(`nullptr`)을 나타내야 할 때

</details>
