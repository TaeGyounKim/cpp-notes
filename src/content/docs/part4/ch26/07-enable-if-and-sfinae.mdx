## SFINAE

- **SFINAE** (substitution failure is not an error): "치환 실패는 오류가 아니다" <CppRef path="cpp/language/sfinae" />
  - 함수 템플릿에 템플릿 인수를 **치환**하다 선언이 잘못된 꼴이 되면, 그것을 컴파일 오류로 보지 않고 그 템플릿을 **오버로드 후보에서 뺌**
- 고급 기능이라 여기서는 기본만 봄

## enable_if <Badge text="C++11" />

- 오버로드 집합에서 어떤 오버로드를 타입 트레이트에 따라 **선택적으로 끔** <CppRef path="cpp/types/enable_if" />
- `enable_if<B, T>`: `B`가 참이면 `type` 별칭이 `T`, 거짓이면 `type`이 **없음**

```cpp
template <bool B, class T = void>
struct enable_if {};
template <class T>
struct enable_if<true, T> { using type = T; };
```

- 보통 반환 타입이나 이름 없는 타입이 아닌 템플릿 매개변수에 씀

### 반환 타입에 쓰기

```cpp
template <typename A, typename B>               // ①
std::enable_if_t<std::is_same_v<A, B>, bool>
check(const A&, const B&);

template <typename A, typename B>               // ②
std::enable_if_t<!std::is_same_v<A, B>, bool>
check(const A&, const B&);
```

- `check(1, 32)`를 컴파일할 때
  - ①: `A`, `B`를 `int`로 추론. 반환 타입 `enable_if_t<true, bool>`은 `bool`. 후보에 들어감
  - ②: 같은 추론. `enable_if_t<false, bool>`은 타입이 없어 반환 타입이 잘못됨. **오류가 아니라** 후보에서 빠짐(SFINAE)
  - 후보가 ① 하나뿐이라 모호하지 않음
- `check(1, 3.5)`는 반대로 ②만 남음
- 아무것도 돌려주지 않을 거면 두 번째 인수를 빼고 `enable_if_t<조건>`(= `void`)

### 이름 없는 템플릿 매개변수에 쓰기

- 반환 타입을 어지럽히지 않아 더 읽기 쉬움

```cpp
template <typename T, std::enable_if_t<std::is_integral_v<T>, int> = 0>
void half(T v);

template <typename T,
          std::enable_if_t<std::is_floating_point_v<T>, int> = 0>
void half(T v);
```

- 조건이 거짓이면 두 번째 매개변수의 타입이 없어져 그 템플릿이 빠짐
- **생성자**는 반환 타입이 없으므로 `enable_if`를 쓰려면 이 방법뿐

### 콘셉트를 쓴다 <Badge text="C++20" />

- 위 `enable_if` 문법은 C++20 전까지의 최선. C++20부터는 **콘셉트**(12장)를 씀. 모양이 비슷하지만 훨씬 읽기 쉬움

```cpp
void half(std::integral auto v);
void half(std::floating_point auto v);
```

:::caution
SFINAE는 신중하게 쓴다. 특수화, 콘셉트 같은 다른 방법으로 풀 수 없는 오버로드 모호함을 풀 때만 쓴다. 잘못된 타입이 들어오면 그냥 컴파일을 실패시키고 싶은 정도라면 콘셉트나 `static_assert`(아래)를 쓴다. 엉뚱한 오버로드를 꺼 버리면 추적하기 어려운 컴파일 오류가 난다.
:::

## if constexpr로 단순하게 <Badge text="C++17" />

- `enable_if` 쌍으로 하던 일을 함수 하나로 쓸 수 있는 경우가 많음
- 예: `work()` 멤버가 있으면 부르고, 없으면 메시지를 출력
  - `enable_if`로는 "어떤 기반 클래스에서 파생되었나"(`is_base_of`)로 두 오버로드를 나눠야 함
- `if constexpr`는 고르지 않은 쪽을 **컴파일하지 않으므로** 한 함수로 됨

```cpp
template <typename T>
void try_work(const T& t)
{
    if constexpr (std::is_base_of_v<Worker, T>) { t.work(); }
    else { std::println("work()가 없음"); }
}
```

- 보통 `if`로는 안 됨: 두 갈래를 모두 컴파일하므로 `work()`가 없는 타입에서 `t.work()`가 오류
- C++20이면 `is_base_of` 대신 **`requires` 식**(12장)으로 "이 식이 되는가"를 직접 물음 <CppRef path="cpp/language/requires" />

```cpp
if constexpr (requires { t.work(); }) { t.work(); }
```

## 논리 연산 트레이트 <Badge text="C++17" />

- `conjunction`(AND), `disjunction`(OR), `negation`(NOT). `_v` 변수 템플릿도 있음 <CppRef path="cpp/types/conjunction" />
- 트레이트 타입을 몇 개든 받음

```cpp
// true
std::conjunction_v<std::is_integral<int>, std::is_integral<short>>
// true
std::disjunction_v<std::is_integral<double>, std::is_integral<long>>
// false
std::negation_v<std::is_integral<int>>
```

- `&&`, `||`와 달리 앞에서 결과가 정해지면 뒤 트레이트를 인스턴스화하지 않음(단락 평가)

## static_assert <Badge text="C++11" />

- 조건을 **컴파일 시간**에 단언함. 거짓이면 컴파일 오류 <CppRef path="cpp/language/static_assert" />
- 인수: 컴파일 시간에 평가할 식, 그리고 (선택) 오류 메시지 문자열

```cpp
static_assert(sizeof(void*) == 8, "64비트로 컴파일해야 한다");
static_assert(sizeof(void*) == 8);   // 메시지 생략(C++17). 메시지는 컴파일러가 정함
```

- 타입 트레이트와 함께 템플릿 인수를 검사함

```cpp
template <typename T>
T twice(T v)
{
    static_assert(std::is_arithmetic_v<T>, "twice()는 산술 타입만 받는다");
    return v * 2;
}
```

## 메타프로그래밍을 쓸 때

- 템플릿 메타프로그래밍은 강력하지만 아주 복잡해지기 쉬움
- 모든 일이 컴파일 시간에 일어나므로 **디버거로 문제를 짚을 수 없음**
- 쓴다면 무엇을 왜 그렇게 하는지 주석으로 잘 설명해 둠. 그렇지 않으면 다른 사람은 물론 나중의 자신도 이해하기 어려움

## 헷갈리기 쉬운 점

- `enable_if<false, T>`는 컴파일 오류를 낸다?
  - `type`이 없을 뿐. 템플릿 치환 중이면 그 오버로드만 빠짐(SFINAE)
- SFINAE는 함수 본문 안의 오류도 숨긴다?
  - 선언(반환 타입, 매개변수, 템플릿 매개변수)의 **직접적인 치환** 실패만. 본문 오류는 진짜 오류
- 보통 `if`로도 `if constexpr`처럼 맞지 않는 쪽을 건너뛴다?
  - 실행은 건너뛰어도 컴파일은 둘 다 함
- `static_assert`는 실행 중에 검사한다?
  - 컴파일 시간. 실행 시간 검사는 `assert`(31장)
- 새 코드에서도 `enable_if`를 쓴다?
  - C++20이면 콘셉트가 먼저. `enable_if`는 이전 표준과 오래된 코드에서 읽을 줄 알면 됨

## 정리

| 요소 | 핵심 |
| --- | --- |
| SFINAE | 치환 실패는 후보 제외일 뿐 오류가 아님 |
| `enable_if` | 조건이 참일 때만 `type`. 반환 타입이나 이름 없는 템플릿 매개변수에 |
| 콘셉트 | C++20의 더 읽기 쉬운 대안 |
| `if constexpr` | 한 함수 안에서 컴파일 시간 분기. `requires` 식과 함께 |
| 논리 트레이트 | `conjunction`, `disjunction`, `negation`. 단락 평가 |
| `static_assert` | 컴파일 시간 단언. 트레이트로 템플릿 인수 검사 |
