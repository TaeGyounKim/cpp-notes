- 다루는 것: 따로 동기화하지 않아도 여러 스레드가 함께 읽고 쓸 수 있는 **원자적 타입** (atomic type)
- 이 글에서 배우는 요소: `std::atomic`, 잠금 없음, 메모리 순서, `compare_exchange_strong`, `fetch_add`, `atomic<shared_ptr>`, `atomic_ref`, `wait`/`notify`

## std::atomic <Badge text="C++11" />

- **원자적 접근** (atomic access): 동기화를 더하지 않고도 동시에 읽고 써도 되는 접근
- 보통 변수의 증가는 스레드 안전하지 않음. 메모리 → 레지스터, 증가, 레지스터 → 메모리 사이에 다른 스레드가 끼어들 수 있음(1편의 데이터 경쟁)
- `<atomic>`의 `std::atomic` 클래스 템플릿으로 감싸면 증가가 **끊기지 않는 한 덩어리**가 됨 <CppRef path="cpp/atomic/atomic" />

```cpp
int counter{ 0 };                // 여러 스레드에서 ++counter: 데이터 경쟁
std::atomic<int> counter2{ 0 };  // 여러 스레드에서 ++counter2: 안전
```

- 기본 타입마다 이름 있는 별칭도 있음

| 이름 | 같은 타입 |
| --- | --- |
| `atomic_bool` | `atomic<bool>` |
| `atomic_char`, `atomic_uchar` | `atomic<char>`, `atomic<unsigned char>` |
| `atomic_int`, `atomic_uint` | `atomic<int>`, `atomic<unsigned int>` |
| `atomic_long`, `atomic_ulong` | `atomic<long>`, `atomic<unsigned long>` |
| `atomic_llong`, `atomic_ullong` | `atomic<long long>`, `atomic<unsigned long long>` |
| `atomic_wchar_t` | `atomic<wchar_t>` |
| `atomic_flag` | 해당 없음. 늘 잠금 없는 가장 단순한 원자적 불리언 |

- `atomic_flag`: `clear()`, `test()`(C++20), `test_and_set()`. 스핀락 예는 5편 <CppRef path="cpp/atomic/atomic_flag" />

### 잠금 없음

- 원자적 타입은 명시적 동기화 없이 쓰지만, **내부적으로** 뮤텍스 같은 것을 쓸 수도 있음. 예: 하드웨어에 그 연산을 원자적으로 하는 명령이 없을 때
- **잠금 없는** (lock-free): 모든 연산이 내부 동기화 없이 실행됨
  - `is_lock_free()`: 이 객체가 잠금 없는지
  - `atomic<T>::is_always_lock_free`: 늘 잠금 없는지(정적 상수) <Badge text="C++17" /> <CppRef path="cpp/atomic/atomic/is_always_lock_free" />
- 정수 말고도 `atomic<double>`, `atomic<MyType>`이 됨. 단 `MyType`이 **trivially copyable**이어야 함(복사가 메모리 복사로 되는 타입)
  - 크기에 따라 잠금 없음 여부가 다름. 예: `int` 하나짜리 구조체는 잠금 없지만, `int` 64개짜리는 보통 아님

### 메모리 순서

- 원자적 타입은 **메모리 순서**, 컴파일러 최적화 문제도 해결함
- **메모리 순서** (memory ordering): 메모리에 접근하는 순서 <CppRef path="cpp/atomic/memory_order" />
  - 원자적 연산이나 동기화가 없으면, 컴파일러와 하드웨어는 결과가 달라지지 않는 한 메모리 접근 순서를 바꿔도 됨(**as-if 규칙**). 단일 스레드에서는 문제없지만 멀티스레드에서는 문제가 됨
- 여러 스레드에서 같은 데이터를 원자적 타입이나 명시적 동기화 없이 읽고 쓰는 것은 사실상 **절대 안전하지 않음**

## 원자적 연산

### compare_exchange

```cpp
bool atomic<T>::compare_exchange_strong(T& expected, T desired);
```

- 다음을 **원자적으로** 함 <CppRef path="cpp/atomic/atomic/compare_exchange" />
  - 지금 값이 `expected`와 같으면 `desired`로 바꾸고 `true`
  - 다르면 `expected`에 지금 값을 넣고 `false`
- 처음엔 이상해 보이지만, 원자적 타입으로 복잡한 연산을 만드는 **핵심 재료**
- 예: 원자적으로 곱하기. 다른 스레드가 먼저 바꿨으면 새 값으로 다시 계산해 재시도

```cpp
void atomic_multiply(std::atomic<int>& a, int n)
{
    int expected{ a.load() };
    int desired{ expected * n };
    while (!a.compare_exchange_strong(expected, desired)) {
        desired = expected * n;   // expected는 실패 때 지금 값으로 바뀌어 있음
    }
}
```

- `compare_exchange_weak`는 값이 같아도 가끔 실패할 수 있는 대신 어떤 플랫폼에서 더 빠름. 반복문 안에서 씀

### fetch_add 등

- `fetch_add(v)`: 지금 값을 가져오고, `v`를 더하고, **더하기 전 값**을 돌려줌 <CppRef path="cpp/atomic/atomic/fetch_add" />

```cpp
std::atomic<int> value{ 10 };
int fetched{ value.fetch_add(4) };   // fetched는 10, value는 14
```

| 타입 | 원자적 연산 |
| --- | --- |
| 정수 계열 | `fetch_add`, `fetch_sub`, `fetch_and`, `fetch_or`, `fetch_xor`, `++`, `--`, `+=`, `-=`, `&=`, `^=`, <code>&#124;=</code> |
| 포인터 | `fetch_add`, `fetch_sub`, `++`, `--`, `+=`, `-=` |
| 실수 | `fetch_add`, `fetch_sub`(C++20) |

- 대부분의 원자적 연산은 메모리 순서를 추가 인수로 받음. 기본값은 `memory_order_seq_cst`
  - 그 밖에 `memory_order_relaxed`, `memory_order_consume`, `memory_order_acquire`, `memory_order_release`, `memory_order_acq_rel`
  - 기본값 말고는 이 분야의 전문가가 아니면 쓰지 않음. 어떤 척도에서 빠를 수 있지만, 조금만 잘못 써도 데이터 경쟁이나 찾기 어려운 문제가 다시 생김

## 원자적 스마트 포인터 <Badge text="C++20" />

- `<memory>`에 `atomic<shared_ptr<T>>`의 부분 특수화가 있음 <CppRef path="cpp/memory/shared_ptr/atomic2" />
- `shared_ptr`의 **참조 계수**는 원래부터 스레드 안전함(가리키는 객체가 정확히 한 번 지워짐을 보장). 그 밖은 아님
  - 같은 `shared_ptr` **인스턴스**에 여러 스레드가 `reset()`, 대입, `swap()` 같은 비`const` 멤버를 부르면 데이터 경쟁
  - 같은 `atomic<shared_ptr<T>>` 인스턴스는 그런 연산도 스레드 안전
- **가리키는 객체**의 비`const` 멤버를 부르는 것은 여전히 스레드 안전하지 않음. 따로 동기화해야 함

## atomic_ref <Badge text="C++20" />

- `std::atomic`과 같지만 **참조**로 동작함. `atomic`은 받은 값을 늘 복사해 가짐 <CppRef path="cpp/atomic/atomic_ref" />
- 보통 변수를 잠시 원자적으로 다룰 때 씀
- `atomic_ref`는 참조하는 객체보다 **짧게** 살아야 함. 복사할 수 있고, 같은 객체를 참조하는 `atomic_ref`를 몇 개든 만들 수 있음
  - `atomic_ref`를 통한 읽기·쓰기끼리는 경쟁하지 않음
  - `atomic_ref`를 **거치지 않은** 동시 읽기·쓰기는 여전히 경쟁할 수 있음
- 포인터(부분 특수화), 정수 계열과 실수(완전 특수화)에 대해 `fetch_add` 등이 있음

```cpp
int plain{ 0 };
// 여러 스레드에서:
std::atomic_ref<int> ref{ plain };
++ref;
```

## 원자적 타입 쓰기: 동기화를 줄인다

- 공유 카운터를 여러 스레드가 늘릴 때
  - 보통 `int`면 데이터 경쟁: 1000이 기대값이어도 982, 977처럼 실행마다 다른 값
  - `atomic<int>`나 `atomic_ref<int>`로 바꾸면 늘 정확함
- 그러나 **성능** 문제가 남음. 동기화(원자적이든 명시적이든)는 성능을 떨어뜨리므로 **최소한으로** 해야 함
- 이 예에서 가장 좋은 방법: 스레드마다 **지역 변수**에 세고, 반복문이 끝난 뒤 **한 번만** 공유 카운터에 더함(여전히 원자적으로)

```cpp
threads.emplace_back([&counter] {
    int local{ 0 };
    for (int i{ 0 }; i < 1000; ++i) { ++local; }
    counter += local;   // 원자적 연산은 한 번
});
```

## 원자적 변수 기다리기 <Badge text="C++20" />

- `atomic`과 `atomic_ref`에 값이 바뀌기를 **효율적으로** 기다리는 멤버가 있음 <CppRef path="cpp/atomic/atomic/wait" />

| 멤버 함수 | 하는 일 |
| --- | --- |
| `wait(old)` | 다른 스레드가 `notify_one()`이나 `notify_all()`을 부르고 값이 `old`와 달라질 때까지 막힘. 이미 다르면 막히지 않음 |
| `notify_one()` | `wait()`에서 막힌 스레드 하나를 깨움 |
| `notify_all()` | `wait()`에서 막힌 스레드를 모두 깨움 |

```cpp
std::atomic<int> flag{ 0 };
std::jthread waiter{ [&flag] {
    flag.wait(0);         // 0인 동안 잠듦
    // 깨어남
} };
flag = 1;
flag.notify_all();
```

- 볼 것
  - 스레드 여덟이 지역에서 센 값을 한 번씩만 더해 8000
  - `fetch_add`가 더하기 전 값을, `compare_exchange_strong` 반복문이 원자적 곱하기를
  - 큰 구조체 `Big`의 `atomic`은 잠금 없음이 아님
  - `atomic_ref`로 보통 변수 `plain`을 안전하게 늘림
  - `wait(0)`으로 잠든 스레드가 `notify_all()`에 깨어남

## 헷갈리기 쉬운 점

- `atomic<int> a; a = a + 1;`도 원자적이다?
  - 읽기(`a`)와 쓰기(`=`)가 따로라 사이에 끼어들 수 있음. `++a`, `a += 1`, `fetch_add`를 씀
- 원자적 타입은 늘 잠금 없이 빠르다?
  - 타입과 하드웨어에 따라 내부에서 잠글 수 있음. `is_lock_free()`로 확인
- `compare_exchange_strong`이 실패하면 `expected`는 그대로다?
  - 지금 값으로 **바뀜**. 그래서 반복문에서 다시 계산함
- `shared_ptr`는 스레드 안전하다?
  - 참조 계수만. 같은 인스턴스를 바꾸는 것은 `atomic<shared_ptr>`, 가리키는 객체는 따로 동기화
- 원자적 변수를 많이 쓸수록 안전하고 좋다?
  - 동기화는 비쌈. 지역에서 계산하고 공유 상태는 최소로

## 정리

| 요소 | 핵심 |
| --- | --- |
| `std::atomic<T>` | 끊기지 않는 읽기·쓰기·증감. `T`는 trivially copyable |
| 잠금 없음 | `is_lock_free()`, `is_always_lock_free` |
| `compare_exchange_strong` | 같으면 바꾸고 true, 다르면 `expected` 갱신. 복잡한 원자적 연산의 재료 |
| `fetch_add` 등 | 바꾸기 전 값을 돌려줌. 메모리 순서는 기본값 |
| `atomic<shared_ptr>`, `atomic_ref` | 같은 `shared_ptr` 인스턴스, 보통 변수를 원자적으로 |
| `wait`/`notify` | 값이 바뀔 때까지 효율적으로 기다림 |

<summary>`std::atomic<std::string>`은 만들 수 있는가?</summary>

- 안 됨. `std::string`은 trivially copyable이 아님(내부에 동적 메모리를 가짐). 문자열을 공유하려면 뮤텍스(5편)나 `atomic<shared_ptr<const std::string>>`

</details>
