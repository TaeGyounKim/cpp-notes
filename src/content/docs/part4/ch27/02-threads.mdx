- 다루는 것: 새 스레드를 시작하고, 끝나기를 기다리고, 멈추게 하는 법
- 이 글에서 배우는 요소: `std::thread`, `join`/`detach`, `std::ref`, `thread_local`, `std::jthread`, `stop_token`

## std::thread <Badge text="C++11" />

- `<thread>`의 `std::thread`로 새 스레드를 쉽게 시작함 <CppRef path="cpp/thread/thread" />
- 새 스레드에서 실행할 것: 함수, 함수 객체의 `operator()`, 람다, 어떤 객체의 멤버 함수

### 함수

- 운영체제 API(`CreateThread()`, `pthread_create()` 등)는 스레드 함수가 매개변수를 하나만 받게 하지만, `std::thread`에 넘기는 함수는 매개변수가 몇 개든 됨

```cpp
void count_up(int id, int times);

std::thread t1{ count_up, 1, 6 };
std::thread t2{ count_up, 2, 4 };
t1.join();
t2.join();
```

- `thread`의 생성자는 가변 인자 템플릿(26장). 첫 인수는 실행할 호출 가능 객체, 나머지는 스레드가 시작할 때 그 객체에 넘길 인수
- 두 스레드가 동시에 돌기 때문에 출력 순서는 코어 수와 운영체제의 스케줄링에 따라 실행마다 다름

### join과 detach

- **join 가능** (joinable): 시스템의 실행 중인(또는 실행했던) 스레드를 나타내는 `thread` 객체. 스레드가 끝나도 `join`하기 전까지는 join 가능 상태로 남음
  - 기본 생성한 `thread`는 join 가능하지 않음
- join 가능한 `thread`가 소멸되기 전에 둘 중 하나를 반드시 부름
  - `join()`: 그 스레드가 끝날 때까지 **기다림**(막힘) <CppRef path="cpp/thread/thread/join" />
  - `detach()`: `thread` 객체와 실제 운영체제 스레드를 떼어 냄. 스레드는 혼자 계속 돎 <CppRef path="cpp/thread/thread/detach" />
  - 둘 다 부르면 `thread`가 join 가능하지 않게 됨
- join 가능한 채로 소멸되면 소멸자가 `std::terminate()`를 불러 **프로그램 전체를 끝냄**
  - join하지 않고 스레드를 버리는 것은 거의 틀림없는 버그이므로, 라이브러리가 그것을 알리는 가장 확실한 방법

### 출력이 섞임

- `print()`, `println()`을 여러 스레드에서 불러도 데이터 경쟁은 없음
- 그러나 한 줄을 여러 번에 나눠 출력하면(`print`를 여러 번, 또는 `cout << a << b`) 스레드끼리 **섞여** 나올 수 있음. 동기화로 해결(5~6편)

:::note
스레드 함수의 인수는 스레드 내부 저장소로 **복사**된다. 참조로 넘기려면 `<functional>`의 `std::ref()`나 `std::cref()`로 감싼다.
:::

### 함수 객체

- 함수 포인터로는 인수로만 정보를 넘길 수 있지만, 함수 객체는 **데이터 멤버**로 상태를 가질 수 있음(19장)

```cpp
struct Countdown {
    int from;
    void operator()() const;
};

std::thread t1{ Countdown{ 3 } };   // 임시 객체를 넘김
Countdown c{ 5 };
std::thread t2{ c };                 // 이름 있는 객체: 복사됨
```

- 함수 객체도 스레드 안으로 **복사**됨. 특정 객체 자체에서 실행하려면 `std::ref(c)`
  - 그러면 `t2`가 끝나고 join되기 전에 메인 스레드에서 `c`를 읽고 쓰면 데이터 경쟁(정의되지 않은 동작)

### 람다

- 람다는 스레드 라이브러리와 잘 어울림

```cpp
int total{ 0 };
std::thread t{ [&total] { total = 42; } };
t.join();   // join 뒤에 total을 읽어야 안전
```

### 멤버 함수

- 멤버 함수 포인터, 객체(의 주소), 인수 순서로 넘김

```cpp
Job job{ "주문" };
std::thread t{ &Job::run, &job, 3 };   // job.run(3)을 새 스레드에서
t.join();
```

- 특정 객체의 멤버를 다른 스레드에서 실행하므로, 다른 스레드도 그 객체에 접근한다면 스레드 안전하게 해야 함(상호 배제, 5편)

## 스레드 지역 저장소

- **`thread_local`**: 스레드마다 **자기만의 복사본**을 가지는 변수. 그 스레드가 사는 동안 있고, 스레드마다 정확히 한 번 초기화됨 <CppRef path="cpp/language/storage_duration" />

```cpp
int shared{ 0 };            // 모든 스레드가 하나를 함께 씀
thread_local int mine{ 0 }; // 스레드마다 하나씩
```

- 전역 변수뿐 아니라 클래스의 정적 데이터 멤버, 함수의 정적 지역 변수에도 씀
- 함수 안에서는 `thread_local`이 `static`을 뜻하지만, 명시적으로 함께 쓰기를 권함

```cpp
static thread_local int x1;     // 됨. 내부 연결(11장)
thread_local int x2;            // 됨. 외부 연결
class Foo {
    static thread_local int x3; // 됨
    // thread_local int x4;     // 오류: 비정적 데이터 멤버는 안 됨
};
void f()
{
    static thread_local int x5; // 됨
    thread_local int x6;        // 됨. 암시적으로 static
}
```

## 스레드 취소

- 표준에는 한 스레드가 다른 실행 중인 스레드를 **강제로** 취소하는 방법이 없음
- 방법: 두 스레드가 약속한 소통 수단을 둠
  - 가장 간단한 것: **공유 깃발** 변수. 대상 스레드가 주기적으로 확인하고, 다른 스레드가 이를 켜서 간접적으로 멈추라고 알림
  - 여러 스레드가 접근하고 하나 이상이 쓰므로 **원자적 변수**(4편)나 **조건 변수**(7편)를 씀
- C++20의 `jthread`가 이것을 표준으로 제공함(부분적인 해결)

## jthread <Badge text="C++20" />

- `<thread>`의 `std::jthread`: `thread`와 거의 같지만 <CppRef path="cpp/thread/jthread" />
  - 소멸자에서 **자동으로 join**함(그 전에 멈춤도 요청함)
  - **협조적 취소** (cooperative cancellation)를 지원함

### 협조적 취소

- "협조적": 취소를 지원하는 스레드가 **스스로 주기적으로 확인**하고 멈춤
- `<stop_token>`의 두 클래스
  - `std::stop_token`: 멈춤이 요청되었는지 확인. `stop_requested()` <CppRef path="cpp/thread/stop_token" />
  - `std::stop_source`: 멈춤을 요청. `request_stop()`. 같은 상태에 묶인 모든 `stop_source`, `stop_token`에 보임 <CppRef path="cpp/thread/stop_source" />
- `jthread`의 `get_stop_token()`, `get_stop_source()`로 얻을 수 있음
- `jthread`에 넘긴 호출 가능 객체의 첫 매개변수가 **`stop_token` 타입**이면 `jthread`가 자기 토큰을 넣어 줌

```cpp
void worker(std::stop_token token, int id)
{
    while (!token.stop_requested()) {
        // 일 조금
        std::this_thread::sleep_for(20ms);
    }
}

{
    std::jthread w{ worker, 7 };
    std::this_thread::sleep_for(250ms);
    // w.request_stop();   // 생략해도 됨: 소멸자가 멈춤 요청 후 join
}
```

- `std::this_thread::sleep_for(duration)`: 지금 스레드를 잠시 재움(22장의 duration) <CppRef path="cpp/thread/sleep_for" />
- `stop_token`은 `condition_variable_any`와 함께 써서, 기다리던 스레드가 멈춤 요청에 깨어나게 할 수도 있음(7편)

- 볼 것
  - 함수, 함수 객체, 람다, 멤버 함수를 각각 새 스레드에서 실행. 예제에서는 순서를 일정하게 하려고 하나씩 join함
  - `thread_local`: 두 번째 스레드의 `mine`은 다시 0에서 시작하지만 `shared`는 이어짐
  - `std::ref`로 넘긴 `counter`만 바뀜
  - 블록을 나갈 때 `jthread` 소멸자가 멈춤을 요청하고 기다림

## 헷갈리기 쉬운 점

- `thread` 객체를 그냥 두고 함수를 끝내도 된다?
  - join 가능한 채로 소멸하면 `std::terminate()`. `join`이나 `detach`(또는 `jthread`)
- `std::thread t{ f, x }`에서 `f(int&)`가 `x`를 고친다?
  - 인수는 복사되므로 원본은 그대로(참조 매개변수면 아예 컴파일되지 않음). `std::ref(x)`
- `detach()`하면 스레드가 끝난다?
  - 떼어 낼 뿐 스레드는 계속 돎. 프로그램이 끝날 때 함께 사라지며, 지역 변수를 참조하면 위험
- `jthread`는 소멸자에서 스레드를 강제로 죽인다?
  - 멈춤을 **요청**하고 join함. 스레드가 토큰을 확인하지 않으면 끝날 때까지 기다림
- `thread_local` 비정적 데이터 멤버를 둘 수 있다?
  - 정적 멤버만 됨

## 정리

| 요소 | 핵심 |
| --- | --- |
| `std::thread{ f, args... }` | 함수, 함수 객체, 람다, 멤버 함수(`&C::m, &obj, ...`) |
| 인수 | 복사됨. 참조는 `std::ref`, `std::cref` |
| `join` / `detach` | 소멸 전에 하나는 필수. 아니면 `terminate` |
| `thread_local` | 스레드마다 하나. 함수 안에서는 암시적 `static` |
| 취소 | 강제 취소 없음. 공유 깃발(원자적) 또는 `jthread` |
| `jthread` | 자동 join, `stop_token`/`stop_source`로 협조적 취소 |
