- 다루는 것: 파일을 스트림으로 읽고 쓰기, 그리고 한 스트림으로 읽기와 쓰기를 모두 하기
- 이 글에서 배우는 요소: `std::ofstream`, `std::ifstream`, 열기 모드, 텍스트·이진 모드, `seekg`·`seekp`·`tellg`·`tellp`, `tie()`, 파일 전체 읽기, `std::fstream`

## 파일 스트림

- 파일은 읽고 쓸 때 데이터와 함께 **위치**가 늘 따라다니므로 스트림 추상화에 잘 맞음
- `<fstream>`의 `std::ofstream`(출력), `std::ifstream`(입력) <CppRef path="cpp/io/basic_fstream" />
- 파일 시스템을 다룰 때는 오류를 찾아 처리하는 것이 특히 중요함
  - 네트워크 저장소가 방금 끊겼을 수도, 디스크가 가득 찼을 수도, 권한이 없는 파일일 수도 있음
  - 1편의 오류 처리 방법을 그대로 씀
- 다른 출력 스트림과의 큰 차이: 생성자가 **파일 이름**과 **열기 모드**를 받음

### 열기 모드

- 기본 모드는 쓰기 `std::ios_base::out`. 파일 처음부터 쓰며 있던 데이터를 덮어씀
- 쓸 수 있는 상수 <CppRef path="cpp/io/ios_base/openmode" />

| 상수 | 뜻 |
| --- | --- |
| `app` | 열고, 쓸 때마다 먼저 끝으로 감(덧붙이기) |
| `ate` | 열고, 연 직후 한 번 끝으로 감 |
| `binary` | 텍스트 모드가 아닌 이진 모드로 입출력 |
| `in` | 입력용으로 열고 처음부터 읽음 |
| `out` | 출력용으로 열고 처음부터 씀. 있던 데이터를 덮어씀 |
| `trunc` | `out`의 선택지. 있던 데이터를 모두 지움 |
| `noreplace` <Badge text="C++23" /> | `out`의 선택지. 배타적으로 엶. 파일이 이미 있으면 열기 실패 |

- 모드는 `|`로 조합함. 예: 이진 모드로, 있던 데이터를 지우고 쓰기

```cpp
std::ios_base::out | std::ios_base::binary | std::ios_base::trunc
```

- `ifstream`은 `in`을, `ofstream`은 `out`을 지정하지 않아도 자동으로 포함함

### 파일에 쓰기

```cpp
int main(int argc, char* argv[])
{
    std::ofstream out{ "args.txt", std::ios_base::trunc };
    if (!out.good()) {
        std::println(std::cerr, "출력 파일을 열 수 없음");
        return 1;
    }
    out << "인수 " << argc << "개\n";
    for (int i{ 0 }; i < argc; ++i) {
        out << argv[i] << '\n';
    }
}
```

- `ifstream`과 `ofstream`의 소멸자가 파일을 자동으로 닫음. `close()`를 직접 부를 필요가 없음(RAII, 7장)

## 텍스트 모드와 이진 모드

- 파일 스트림은 기본으로 **텍스트 모드**. `binary`를 주면 **이진 모드**
- 이진 모드: 쓰라고 한 바이트가 그대로 파일에 써지고, 읽을 때도 파일의 바이트가 그대로 돌아옴
- 텍스트 모드: 숨은 변환이 있음
  - 프로그램에서 줄은 `\n`으로 끝나지만, 파일에서 줄 끝을 어떻게 저장하는지는 운영체제마다 다름. Windows는 `\r\n`
  - Windows 텍스트 모드에서는 `\n`을 쓰면 `\r\n`으로 바꿔 쓰고, 읽을 때 `\r\n`을 `\n`으로 바꿔 돌려줌
- 그림, 압축 파일처럼 바이트 그대로 다뤄야 하는 파일은 이진 모드로 염

## seek()와 tell()로 위치 옮기기

- 모든 입력·출력 스트림에 위치를 옮기고 묻는 멤버가 있음 <CppRef path="cpp/io/basic_istream/seekg" />

| | 입력 스트림 | 출력 스트림 |
| --- | --- | --- |
| 위치 옮기기 | `seekg()`(g는 get) | `seekp()`(p는 put) |
| 지금 위치 묻기 | `tellg()` | `tellp()` |

- 왜 `seek()` 하나가 아니라 둘인가? 파일 스트림처럼 입력이자 출력인 스트림이 있어서. 그런 스트림은 **읽기 위치**와 **쓰기 위치**를 따로 기억함(아래 양방향 입출력)
- `seekg()`, `seekp()`에는 오버로드가 둘씩 있음
  - 인수 하나: 절대 위치로 옮김
  - 인수 둘: 기준 위치에서 상대적으로 옮김
- 위치는 `std::streampos`, 상대 거리는 `std::streamoff` 타입. 둘 다 바이트 단위. 정수는 이 타입들로 암시적으로 바뀜
- 기준 위치 상수

| 상수 | 뜻 |
| --- | --- |
| `std::ios_base::beg` | 스트림의 처음 |
| `std::ios_base::end` | 스트림의 끝 |
| `std::ios_base::cur` | 지금 위치 |

```cpp
out.seekp(0);                          // 처음으로(절대 위치)
out.seekp(2, std::ios_base::beg);      // 처음에서 2바이트 뒤
in.seekg(-3, std::ios_base::end);      // 끝에서 3바이트 앞
std::streampos pos{ in.tellg() };      // 지금 읽기 위치
```

- `tell` 결과를 저장해 두었다가 나중에 그 위치로 돌아가거나, 특정 위치에 있는지 확인하는 데 씀

## 스트림 연결하기

- 입력 스트림과 출력 스트림을 **연결** (tie)하면, 입력 스트림에서 데이터를 요청할 때마다 연결된 출력 스트림이 자동으로 비워짐 <CppRef path="cpp/io/basic_ios/tie" />
- 모든 스트림에 쓸 수 있지만, 서로 의존하는 파일 스트림에서 특히 쓸모 있음
- 입력 스트림의 `tie()`에 출력 스트림의 **주소**를 넘김. 끊으려면 `nullptr`

```cpp
std::ifstream inFile{ "input.txt" };   // 이미 있어야 함
std::ofstream outFile{ "output.txt" };
inFile.tie(&outFile);

outFile << "안녕";       // 아직 비워지지 않음(endl 없음)
std::string token;
inFile >> token;         // 읽기 전에 outFile이 비워짐
```

- `flush()`는 `ostream`에 정의되어 있으므로 출력 스트림끼리도 연결할 수 있음: `outFile.tie(&anotherFile);`
  - 한 파일에 쓸 때마다 다른 파일에 쌓인 버퍼가 비워짐. 관련된 두 파일을 맞춰 둘 때 씀
- 표준 스트림의 연결
  - `cin`에서 입력하려 하면 `cout`이 비워짐(2편)
  - `cerr`에 출력하면 `cout`이 비워짐
  - `clog`는 `cout`과 연결되어 있지 않음
  - 넓은 문자 판도 같은 관계

## 파일 전체 읽기

- `std::getline()`의 구분 문자를 `'\0'`으로 주면 파일 전체를 한 번에 읽음. 파일 내용에 `'\0'`이 없을 때만 됨

```cpp
std::ifstream in{ "data.txt" };
if (in.fail()) {
    std::println(std::cerr, "파일을 열 수 없음");
    return 1;
}
std::string contents;
std::getline(in, contents, '\0');
```

## 양방향 입출력

- **양방향 스트림** (bidirectional stream): 입력과 출력을 모두 하는 스트림
  - `std::iostream`에서 파생함. `iostream`은 `istream`과 `ostream`을 둘 다 상속함. 쓸모 있는 다중 상속(10장)의 예
  - `>>`와 `<<`, 그리고 입력·출력 스트림의 멤버 함수를 모두 씀
- `std::fstream`: 양방향 파일 스트림. 파일 안의 데이터를 **제자리에서 바꿀** 때 알맞음
  - 맞는 위치를 찾을 때까지 읽다가 바로 쓰기로 바꿀 수 있음
- 예: 측정기 번호와 값을 담은 파일

```text
101 23.5
102 19.0
103 30.1
```

- 프로그램 시작 때 전체를 읽고 끝날 때 다시 쓰는 것이 무난하지만, 데이터가 매우 크면 메모리에 다 담을 수 없음
- 스트림을 쓰면 그럴 필요가 없음. 파일을 훑어 레코드를 찾고, 새 레코드는 덧붙이기 모드로 추가하고, 기존 레코드는 양방향 스트림으로 고침

```cpp
bool changeValue(const std::string& file, int id, std::string_view value)
{
    std::fstream io{ file };
    if (!io) { return false; }
    int idRead{ 0 };
    std::string old;
    while (io >> idRead) {
        if (idRead == id) {
            io.seekp(io.tellg());   // 쓰기 위치를 지금 읽기 위치로
            io << ' ' << value;     // 공백과 새 값으로 덮어씀
            return true;
        }
        io >> old;                  // 이 레코드의 값을 읽어 넘김
    }
    return false;
}
```

- 이 방법은 데이터의 **크기가 고정**되어 있을 때만 제대로 동작함
  - 읽다가 쓰기로 바꾸면 쓴 데이터가 파일의 다른 데이터를 덮어씀
  - 다음 레코드를 덮어쓰지 않고 형식을 유지하려면 새 값이 옛 값과 정확히 같은 크기여야 함(`19.0`과 `21.7`)
- 문자열 스트림도 `std::stringstream`으로 양방향으로 쓸 수 있음

:::caution
Windows에서 텍스트 모드로 연 파일은 줄 끝 `\r\n`이 `\n`으로 바뀌어 보이므로, `tellg()`로 얻은 위치와 실제 바이트 위치가 어긋날 수 있다. 위 `changeValue()`를 Windows의 MinGW GCC로 실행하면 102번 줄이 `102 1 21.7`처럼 깨지고 다음 줄과 붙어 버렸다. 제자리에서 고칠 파일은 이진 모드(`in`, `out`, `binary`를 함께)로 열면 Windows에서도 바르게 동작한다(같은 환경에서 확인).
:::

:::note
양방향 스트림은 읽기 위치와 쓰기 위치를 따로 가진다. 읽기와 쓰기를 바꿀 때는 알맞은 위치로 옮겨야 한다.
:::

## 헷갈리기 쉬운 점

- `ofstream`으로 열면 기존 내용 뒤에 이어 쓴다?
  - 기본은 처음부터 덮어씀. 이어 쓰려면 `std::ios_base::app`
- `ate`와 `app`은 같다?
  - `ate`는 연 직후 한 번 끝으로 감. `app`은 쓸 때마다 끝으로 감
- 파일을 다 쓰면 `close()`를 꼭 불러야 한다?
  - 소멸자가 닫음. 일찍 닫고 다시 열 때만 직접 부름
- `fstream`으로 값을 바꾸면 길이가 달라도 된다?
  - 덮어쓰기라 길이가 같아야 함. 길이가 다르면 파일 전체를 다시 씀
- 양방향 스트림은 위치가 하나다?
  - 읽기·쓰기 위치가 따로. `seekg`·`seekp`로 맞춤

## 정리

| 요소 | 핵심 |
| --- | --- |
| `ofstream` / `ifstream` | 파일 이름과 모드를 받는 출력 / 입력 스트림. 소멸자가 닫음 |
| 모드 | `app`, `ate`, `binary`, `in`, `out`, `trunc`, `noreplace`(C++23). `\|`로 조합 |
| 텍스트 / 이진 | 줄 끝 변환 있음 / 바이트 그대로 |
| 위치 | `seekg`·`seekp`(절대, 상대), `tellg`·`tellp`, `beg`·`cur`·`end` |
| `tie()` | 입력 전에 연결된 출력 스트림을 비움 |
| 파일 전체 | `std::getline(in, s, '\0')` |
| `fstream` | 양방향. 고정 크기 레코드를 제자리에서 고침 |
