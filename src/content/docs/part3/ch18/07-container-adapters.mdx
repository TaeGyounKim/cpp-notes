- 다루는 것: 먼저 온 것부터(`queue`), 중요한 것부터(`priority_queue`), 나중에 온 것부터(`stack`) 꺼내는 자료 구조
- 이 글에서 배우는 요소: 어댑터의 뜻, 각 어댑터의 연산과 바탕 컨테이너, 비교자

## 컨테이너 어댑터란

- 표준 순차 컨테이너 외에 **컨테이너 어댑터** 셋: `queue`, `priority_queue`, `stack`
- 각각 순차 컨테이너 하나를 **감싼** 것
  - 나머지 코드를 바꾸지 않고 바탕 컨테이너를 바꿔 끼울 수 있음
  - 목적: 인터페이스를 단순하게 하고, 스택·큐·우선순위 큐라는 추상화에 맞는 기능만 제공
- 바탕 컨테이너에 접근하는 길을 주지 않음. 4장의 **데이터 숨기기** 원칙의 좋은 예
  - 여러 원소를 한꺼번에 지우는 기능이 없음
  - **반복자가 없음**. 그래서 범위 기반 `for` 문이나 반복자 기반 표준 알고리즘(20장)에 쓸 수 없음
  - 다만 <Badge text="C++23" /> `std::format()`과 `print()`로 내용을 서식화·출력할 수 있음

## queue

- `<queue>`. 표준 **먼저 들어온 것이 먼저 나감** (FIFO) 의미 <CppRef path="cpp/container/queue" />

```cpp
template <typename T, typename Container = std::deque<T>> class queue;
```

- `T`: 담을 타입. `Container`: 감쌀 바탕 컨테이너
  - `queue`는 바탕 컨테이너에 `push_back()`과 `pop_front()`가 있어야 하므로 표준 선택지는 `deque`와 `list` 둘. 대부분 기본값 `deque`로 충분함

### 연산

- 멤버 함수 아홉과 생성자들, 비교 연산자뿐. 아주 단순함

| 멤버 | 하는 일 |
| --- | --- |
| `push()`, `emplace()` | 꼬리(뒤)에 넣음 |
| `push_range()` <Badge text="C++23" /> | 범위의 원소들을 꼬리에 넣음 |
| `pop()` | 머리(앞)의 원소를 지움 |
| `front()`, `back()` | 첫 원소, 마지막 원소의 참조(지우지 않음). `const` 객체면 `const` 참조 |
| `size()`, `empty()`, `swap()` | 크기, 비었는지, 맞바꾸기 |

- <Badge text="C++23" /> 반복자 쌍 [begin, end)를 받는 생성자: 그 범위의 원소들로 큐를 만듦

:::caution
`pop()`은 꺼낸 원소를 돌려주지 않는다. 값이 필요하면 먼저 `front()`로 꺼낸다.
:::

- `pop()`이 값을 돌려주지 않는 이유: 값으로 돌려주다 복사(또는 이동)에서 예외가 나면 원소는 이미 지워졌는데 값은 잃게 됨. 확인(`front()`)과 지우기(`pop()`)를 나눠 강한 예외 보장을 지킴(14장)

### 예: 인쇄 대기열

- 프린터는 들어온 순서대로 처리해야 하므로 `queue`가 알맞음
- `PrintSpooler` 클래스 템플릿: 받을 수 있는 작업 수를 제한함. 가득 차면 새 작업을 거절함
  - 운영체제가 버퍼에 쌓아 둘 수 있는 데이터를 제한하는 것과 같은 이유(메모리를 너무 쓰지 않게)
  - `next()`: 비었으면 `std::out_of_range`를 던지고, 아니면 `front()`로 복사한 뒤 `pop()`
- 실제로 쓰려면 여러 스레드가 필요함. 하지만 적어도 한 스레드가 객체를 고친다면, 명시적 동기화 없이 표준 라이브러리 객체를 여러 스레드에서 안전하게 쓸 수 없음(27장)

## priority_queue

- **우선순위 큐**: 원소를 정렬된 순서로 유지하는 큐 <CppRef path="cpp/container/priority_queue" />
  - 엄격한 FIFO 대신, 머리의 원소는 언제나 **우선순위가 가장 높은** 것. 가장 오래된 것일 수도 최근 것일 수도 있음
  - 우선순위가 같은 두 원소의 상대 순서는 정해지지 않음
- `<queue>`. 템플릿(조금 단순화)

```cpp
template <typename T, typename Container = std::vector<T>,
          typename Compare = std::less<T>>
class priority_queue;
```

- `Container`: 기본 `vector`, `deque`도 됨. 원소에 임의 접근이 필요하므로 `list`는 안 됨
- `Compare`: 두 `T`를 비교하는 것. 기본 `std::less`는 `operator<`로 비교함(19장)
  - 담을 타입에 `operator<`가 있어야 함. C++20부터는 `operator<=>`를 두면 `<`가 따라옴

:::note
`priority_queue`의 머리는 우선순위가 "가장 높은" 원소다. 기본은 `operator<`로 정하므로 다른 원소보다 "작은" 원소가 우선순위가 낮다. 즉 가장 **큰** 원소가 머리에 온다.
:::

- 가장 **작은** 원소를 머리에 두려면 비교자를 `std::greater<T>`로 바꿈. 세 번째 매개변수라 두 번째(`std::vector<T>`)도 적어야 함

```cpp
std::priority_queue<int, std::vector<int>, std::greater<int>> soonest;
```

### 연산

| 멤버 | 하는 일 |
| --- | --- |
| `push()`, `emplace()`, `push_range()` <Badge text="C++23" /> | 넣음 |
| `pop()` | 머리 원소를 지움(돌려주지 않음) |
| `top()` | 머리 원소의 **`const` 참조** |
| `size()`, `empty()`, `swap()` | 크기, 비었는지, 맞바꾸기 |

:::caution
`top()`은 `const`가 아닌 객체에 불러도 `const` 참조를 돌려준다. 원소를 고치면 순서가 바뀔 수 있는데 그것은 허용되지 않기 때문이다. 꼬리 원소를 얻는 방법은 없다. `pop()`은 꺼낸 원소를 돌려주지 않으므로 먼저 `top()`으로 꺼낸다.
:::

- `queue`와 달리 비교 연산자를 제공하지 않음
- 내부는 보통 **힙** (heap) 알고리즘(16장)으로 구현됨. 넣기와 지우기가 로그 시간

### 예: 경보 처리

- 시스템에 고장 하나가 나면 여러 구성 요소에서 오류가 쏟아질 수 있음. 좋은 오류 처리 시스템은 가장 중요한 것부터 처리함
- 경보마다 수준을 담고, `<=>`로 수준을 비교하게 하면 `priority_queue`가 가장 높은 수준부터 내줌

## stack

- `<stack>`. `queue`와 거의 같지만 **나중에 들어온 것이 먼저 나감** (LIFO, FILO) <CppRef path="cpp/container/stack" />

```cpp
template <typename T, typename Container = std::deque<T>> class stack;
```

- 바탕 컨테이너로 `vector`, `list`, `deque`를 쓸 수 있음

| 멤버 | 하는 일 |
| --- | --- |
| `push()`, `emplace()`, `push_range()` <Badge text="C++23" /> | 맨 위에 넣음. 먼저 넣은 원소들은 "아래로 밀림" |
| `pop()` | 맨 위(가장 최근에 넣은) 원소를 지움(돌려주지 않음) |
| `top()` | 맨 위 원소의 참조. `const` 객체면 `const` 참조 |
| `empty()`, `size()`, `swap()` | 비었는지, 크기, 맞바꾸기. 비교 연산자도 있음 |

- <Badge text="C++23" /> `queue`처럼 반복자 쌍 생성자가 있음
- 쓰임새: 되돌리기 기록, 괄호 짝 검사, 깊이 우선 탐색
- 앞의 경보 처리기를 "가장 최근 경보부터" 내주게 바꾸려면 `priority_queue`를 `stack`으로 바꾸기만 하면 됨. `push()`, `pop()`, `top()`, `empty()`가 둘 다에 있음

## 헷갈리기 쉬운 점

- `q.pop()`으로 꺼낸 값을 받는다?
  - `void`. 먼저 `front()`/`top()`
- `priority_queue`의 `top()`은 가장 작은 값이다?
  - 기본(`std::less`)은 가장 **큰** 값. 작은 값은 `std::greater`
- `for (auto x : q)`로 큐를 훑을 수 있다?
  - 어댑터에는 반복자가 없음. 복사본을 만들어 `pop()`하며 꺼내거나(C++23이면 출력은 `println`) 처음부터 다른 컨테이너를 씀
- `queue`의 바탕으로 `vector`를 쓸 수 있다?
  - `pop_front()`가 없어 안 됨. `deque`나 `list`
- `priority_queue`의 바탕으로 `list`를 쓸 수 있다?
  - 임의 접근이 필요해 안 됨. `vector`나 `deque`

## 정리

| 어댑터 | 의미 | 기본 바탕 | 꺼내기 |
| --- | --- | --- | --- |
| `queue` | FIFO | `deque`(또는 `list`) | `front()` 후 `pop()` |
| `priority_queue` | 우선순위 높은 것부터 | `vector`(또는 `deque`), 비교자 `std::less` | `top()`(`const`) 후 `pop()` |
| `stack` | LIFO | `deque`(또는 `vector`, `list`) | `top()` 후 `pop()` |

- 모두 반복자가 없음. `pop()`은 값을 돌려주지 않음
