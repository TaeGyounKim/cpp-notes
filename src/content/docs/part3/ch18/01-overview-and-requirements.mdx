## 컨테이너 개요

- 표준 라이브러리 컨테이너: 데이터 모음을 담는 **제네릭 자료 구조**
  - 표준 라이브러리를 쓰면 C 스타일 배열을 쓰거나, 연결 리스트를 짜거나, 스택을 설계할 일이 거의 없음
  - 클래스 템플릿이라 다음 절의 기본 조건을 만족하는 어떤 타입으로도 인스턴스화할 수 있음
- `array`와 `bitset`을 뺀 대부분은 크기가 **유연함**. 원소 수에 맞춰 알아서 커지고 줄어듦
  - 크기가 고정된 C 스타일 배열은 **넘침** (overrun)에 취약함. 가벼우면 데이터가 망가져 프로그램이 죽고, 나쁘면 보안 공격의 통로가 됨
  - 표준 컨테이너를 쓰면 이런 문제에 덜 취약해짐

| 분류 | 컨테이너 | 글 |
| --- | --- | --- |
| 순차 컨테이너 | `vector`(동적 배열), `deque`, `list`, `forward_list`, `array` | 2~5편 |
| 순차 뷰 | `span`, `mdspan` | 6편 |
| 컨테이너 어댑터 | `queue`, `priority_queue`, `stack` | 7편 |
| 정렬된 연관 컨테이너 | `map`/`multimap`, `set`/`multiset` | 8~9편 |
| 정렬되지 않은 연관 컨테이너(해시 테이블) | `unordered_map`/`unordered_multimap`, `unordered_set`/`unordered_multiset` | 10편 |
| 평평한 연관 컨테이너 어댑터 <Badge text="C++23" /> | `flat_map`/`flat_multimap`, `flat_set`/`flat_multiset` | 10편 |
| 그 밖 | 문자열, 스트림(어느 정도 컨테이너처럼 씀), `bitset`(정해진 수의 비트) | 11편 |

- 모두 `std` 네임스페이스에 있음

## 원소에 대한 요구 사항

### 값 의미론

- 표준 컨테이너는 원소에 **값 의미론** (value semantics)을 씀
  - 받은 원소의 **복사본**을 저장함
  - 대입 연산자로 원소에 대입하고, 소멸자로 원소를 없앰
  - 그래서 표준 라이브러리와 쓸 클래스는 **복사할 수 있어야** 함
- 컨테이너에서 원소를 달라고 하면 저장된 복사본에 대한 **참조**를 돌려줌

### 참조 의미론이 필요하면

- 원소 대신 **포인터**를 저장함. 컨테이너가 포인터를 복사해도 같은 원소를 가리킴
- 또는 `std::reference_wrapper`를 저장함 <CppRef path="cpp/utility/functional/reference_wrapper" />
  - 참조를 복사할 수 있게 만들려고 있는 클래스 템플릿
  - 도우미 함수 `std::ref()`, `std::cref()`로 만듦. 모두 `<functional>`
  - 값은 `get()`으로 꺼냄(2편에서 예를 더 봄)

### 이동만 되는 타입

- 복사할 수 없고 이동만 되는 타입(예: `std::unique_ptr`)도 담을 수 있음
- 다만 일부 연산(예: 컨테이너 복사)은 컴파일되지 않음

:::caution
컨테이너에 포인터를 담아야 한다면, 컨테이너가 가리키는 객체를 소유하면 `unique_ptr`, 다른 소유자와 소유권을 나누면 `shared_ptr`를 쓴다. 예전의 `auto_ptr`는 복사를 바르게 구현하지 않아 컨테이너에 쓰면 안 되었고, C++17에서 제거되었다.
:::

### 할당자와 비교자

- 표준 컨테이너의 템플릿 타입 매개변수 중 하나는 **할당자** (allocator). 원소의 메모리를 할당하고 해제함
  - 기본값이 있어 거의 늘 무시해도 됨

```cpp
template <typename T, typename Allocator = std::allocator<T>> class vector;
```

- `map` 같은 일부 컨테이너는 원소를 정렬할 **비교자** (comparator)도 템플릿 타입 매개변수로 받음
  - 기본값은 `operator<`로 비교하는 `std::less`

```cpp
template <typename Key, typename T, typename Compare = std::less<Key>,
          typename Allocator = std::allocator<std::pair<const Key, T>>>
class map;
```

- 할당자와 비교자는 이 장의 뒤에서 자세히

### 원소 타입이 갖출 것

- 기본 할당자와 기본 비교자를 쓸 때 원소 타입에 필요한 것

| 멤버 | 하는 일 | 언제 쓰임 |
| --- | --- | --- |
| 복사 생성자 | "같은" 새 원소를 만듦. 원래 원소에 영향 없이 따로 없앨 수 있어야 함 | 원소를 넣을 때마다(`emplace` 계열 멤버 함수는 빼고) |
| 이동 생성자 | 원본의 내용을 모두 옮겨 새 원소를 만듦 | 원본이 우측값이고 곧 사라질 때, `vector`가 커질 때. **`noexcept`여야** 쓰임 |
| 대입 연산자 | 원소의 내용을 원본의 복사본으로 바꿈 | 원소를 고칠 때마다 |
| 이동 대입 연산자 | 원소의 내용을 원본에서 옮겨 와 바꿈 | 원본이 우측값이고 곧 사라질 때. **`noexcept`여야** 쓰임 |
| 소멸자 | 원소를 정리함 | 원소를 지울 때, `vector`가 커질 때 |
| 기본 생성자 | 인수 없이 원소를 만듦 | 일부 연산만. 예: 인수 하나짜리 `vector::resize()`, `map::operator[]` |
| `operator==` | 두 원소가 같은지 | 정렬되지 않은 연관 컨테이너의 키, 두 컨테이너의 `==` 등 |
| `operator<` | 한 원소가 다른 것보다 작은지 | 정렬된 연관 컨테이너와 평평한 연관 컨테이너 어댑터의 키, 두 컨테이너의 `<` 등 |
| `operator>`, `<=`, `>=`, `!=` | 비교 | 두 컨테이너를 비교할 때 |

- 이런 멤버 함수를 쓰는 법은 9장

:::caution
표준 컨테이너는 원소를 자주 옮기거나 복사한다. 성능을 위해 담을 타입이 이동 의미론을 지원하게 한다(9장). 이동할 수 없다면 복사 생성자와 복사 대입 연산자를 최대한 효율적으로 만든다.
:::

- 이동 생성자에 `noexcept`가 없으면 `vector`는 커질 때 이동 대신 **복사**함
  - 옮기는 도중 예외가 나면 원래 상태로 되돌릴 수 없어서. 복사라면 원본이 그대로 남음(14장의 강한 예외 보장)

- 볼 것

  - `reference_wrapper`로 담으면 원본의 바뀐 값이 보임

## 예외와 오류 검사

- 표준 컨테이너의 오류 검사는 제한적. 쓰는 쪽이 올바르게 쓰는지 확인해야 함
- 일부 멤버 함수는 특정 조건에서 예외를 던짐. 예: 범위를 벗어난 첨자에 `at()`
- 사용자가 정한 (예외 특성을 알 수 없는) 타입으로 연산하므로, 던질 수 있는 예외를 모두 나열할 수는 없음. 이 장에서는 필요한 곳에서 언급함

## 헷갈리기 쉬운 점

- `vector`에 넣은 객체를 바꾸면 원래 변수도 바뀐다?
  - 복사본을 저장하므로 서로 독립. 같은 객체를 보려면 포인터나 `reference_wrapper`
- 이동 생성자만 있으면 `vector`가 커질 때 이동한다?
  - `noexcept`여야 이동함. 아니면 (복사할 수 있다면) 복사
- `unique_ptr`는 컨테이너에 못 넣는다?
  - 넣을 수 있음. 컨테이너 복사 같은 복사가 필요한 연산만 안 됨
- 원소 타입에 기본 생성자가 늘 필요하다?
  - `resize(n)`, `map::operator[]` 같은 일부 연산에만

## 정리

| 요소 | 핵심 |
| --- | --- |
| 분류 | 순차, 순차 뷰, 어댑터, 정렬된 연관, 해시 테이블, 평평한 연관 어댑터 |
| 값 의미론 | 복사본을 저장. 원소를 달라면 참조를 줌 |
| 참조 의미론 | 포인터(가급적 스마트 포인터), `reference_wrapper` |
| 원소 요구 | 복사·이동(`noexcept`)·대입·소멸, 연산에 따라 기본 생성자·`==`·`<` |
| 템플릿 매개변수 | 할당자(기본 `std::allocator`), 비교자(기본 `std::less`) |
| 오류 검사 | 제한적. `at()` 등 일부만 예외 |
