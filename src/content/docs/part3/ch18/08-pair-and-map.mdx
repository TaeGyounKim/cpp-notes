- 이 글에서 배우는 요소: `pair`, `map`의 생성·넣기·훑기·찾기·지우기, 노드 핸들

## 연관 컨테이너

- 표준 라이브러리의 연관 컨테이너
  - **정렬된 연관 컨테이너**: `map`, `multimap`, `set`, `multiset`(이 글과 9편)
  - **정렬되지 않은 연관 컨테이너**(해시 테이블): `unordered_map`, `unordered_multimap`, `unordered_set`, `unordered_multiset`(10편)
  - **평평한 연관 컨테이너 어댑터** <Badge text="C++23" />: `flat_map`, `flat_multimap`, `flat_set`, `flat_multiset`. 순차 컨테이너를 정렬된 연관 컨테이너처럼 동작하게 함(10편)
- 정렬된 연관 컨테이너는 순차 컨테이너와 달리 원소를 일렬로 저장하지 않고, **키를 값에 대응**시킴
  - 넣기, 지우기, 찾기 시간이 대체로 비슷함
  - 원소를 정렬된 **트리 같은** 자료 구조에 저장함

## pair

- `<utility>`의 `std::pair`: 타입이 다를 수 있는 두 값을 묶음(1장) <CppRef path="cpp/utility/pair" />
  - 공개 데이터 멤버 `first`, `second`로 접근함
  - 모든 비교 연산자를 지원하고 `first`와 `second`를 둘 다 비교함(`first` 먼저, 같으면 `second`)

```cpp
std::pair<std::string, int> a{ "사과", 3 };
std::pair<std::string, int> b;   // 기본 생성자
b.first = "사과";
b.second = 5;
bool less{ a < b };              // first가 같으므로 second로: 3 < 5
```

- 만드는 법 셋

```cpp
std::pair<int, double> p1{ std::make_pair(5, 10.1) };
auto p2{ std::make_pair(5, 10.1) };   // C++17 이전의 흔한 방법
std::pair p3{ 5, 10.1 };              // 클래스 템플릿 인수 추론(C++17)
std::pair p4{ "사과"s, 3 };           // s 리터럴이 없으면 const char*로 추론됨
```

## map

- `<map>`의 `std::map`: 값 하나가 아니라 **키-값 쌍**을 저장함 <CppRef path="cpp/container/map" />
  - 넣기, 찾기, 지우기가 모두 **키**를 기준으로 함. 값은 "따라다닐" 뿐
  - 키를 값에 "대응시킨다"(map)는 뜻에서 온 이름
- 키 기준으로 **정렬**된 상태를 유지하므로 넣기, 지우기, 찾기가 모두 **로그 시간**
  - 훑으면 키 타입의 `operator<`나 사용자 정의 비교자의 순서로 나옴
  - 보통 레드-블랙 트리 같은 균형 트리로 구현하지만, 트리 구조는 드러내지 않음
- 키로 원소를 저장하고 꺼내야 하고 일정한 순서가 필요할 때 씀

### 만들기

- 템플릿 타입 넷: 키 타입, 값 타입, 비교자 타입, 할당자 타입
  - 비교자는 `priority_queue`의 것과 비슷함. 기본 `std::less`를 쓰면 키가 `operator<`에 맞게 반응해야 함(직접 만드는 법은 19장)
- 비교자와 할당자를 무시하면 `vector`처럼 만들되 키와 값 타입을 따로 적음: `std::map<int, Data> dataMap;`
  - 내부에는 원소마다 `std::pair<const int, Data>`를 저장함
- 중괄호 초기화도 됨. 원소마다 `pair`

```cpp
std::map<std::string, int> stock{ { "사과", 3 }, { "배", 7 } };
```

- 클래스 템플릿 인수 추론은 평소처럼 되지 않음
  - `std::map m{ { "사과"s, 3 } };`은 컴파일되지 않음. `{ "사과"s, 3 }`에서 `pair<string, int>`를 추론할 수 없기 때문
  - 꼭 원한다면 원소마다 `std::pair`를 명시함

```cpp
std::map m{ std::pair{ "사과"s, 3 }, std::pair{ "배"s, 7 } };
```

- <Badge text="C++23" /> `println("{}", stock);`은 중괄호로 감싸고, 쌍은 쉼표로, 키와 값은 콜론으로 나눔

```text
{"배": 7, "사과": 3}
```

### 넣기

- 순차 컨테이너는 넣을 위치를 늘 지정해야 하지만, `map`은 내부 구현이 위치를 정함. 키와 값만 주면 됨
  - 반복자 위치를 받는 `insert()`도 있지만, 그 위치는 **힌트**일 뿐이라 그 자리에 넣지 않아도 됨
- `map`의 키는 **유일**해야 함. 같은 키에 여러 원소가 필요하면 값으로 `vector` 같은 컨테이너를 두거나 `multimap`(9편)을 씀

| 방법 | 키가 이미 있으면 | 돌려주는 것 |
| --- | --- | --- |
| `insert({ 키, 값 })` | **덮어쓰지 않음** | `pair<반복자, bool>`. `bool`은 넣었는지, 반복자는 그 키의 원소 |
| `insert_or_assign(키, 값)` <Badge text="C++17" /> | 덮어씀 | `pair<반복자, bool>`. `bool`은 새로 넣었는지 |
| `m[키] = 값` | 덮어씀 | 값의 참조 |
| `try_emplace(키, 생성자 인수...)` <Badge text="C++17" /> | 아무것도 안 함(값을 만들지도 않음) | `pair<반복자, bool>` |
| `emplace(...)`, `emplace_hint(위치, ...)` | 넣지 않음 | 제자리 생성 |
| `insert_range(범위)` <Badge text="C++23" /> | 그 원소는 넣지 않음 | |

- `insert()`의 결과는 `if` 초기화문과 구조적 바인딩(C++17)으로 한 문장에 확인할 수 있음

```cpp
if (auto [it, inserted]{ stock.insert({ "사과", 10 }) }; !inserted) {
    std::println("사과는 이미 있음: {}개", it->second);
}
```

### operator[]의 함정

- `operator[]`는 늘 성공함. 키가 없으면 그 키로 새 원소를 만들고, 있으면 값을 바꿈
- 하지만 필요 없을 때도 값 객체를 **늘 새로 만듦**
  - 그래서 값 타입에 기본 생성자가 필요하고, `insert()`보다 덜 효율적일 수 있음
- 없는 키를 **읽기만** 해도 원소가 생김: `int n{ stock["수박"] };` 뒤 `stock`에는 `"수박": 0`이 있음
- 같은 이유로 `operator[]`는 `const`가 아님. `const` `map`(또는 `const` 참조)에는 쓸 수 없음

```cpp
int stockOf(const std::map<std::string, int>& stock, const std::string& item)
{
    return stock[item];   // 오류: const map에 operator[]는 없음
}
```

- 이럴 때는 `find()`나 `at()`을 씀

### 훑기

- `map`의 반복자는 값이 아니라 **키-값 쌍**을 참조함. 값은 쌍의 `second`
- **양방향** 반복자

```cpp
for (auto it{ stock.cbegin() }; it != stock.cend(); ++it) {
    std::println("{}: {}", it->first, it->second);   // (*it).second와 같음
}
for (const auto& [name, count] : stock) {           // 구조적 바인딩(C++17)
    std::println("{}: {}", name, count);
}
```

:::caution
`const`가 아닌 반복자로 원소의 값은 고칠 수 있지만, 키를 고치려 하면 컴파일 오류가 난다. 키를 바꾸면 `map`의 정렬 순서가 깨지기 때문이다. 원소의 타입이 `pair<const 키, 값>`이다.
:::

### 찾기

- 키로 로그 시간에 찾음

| 방법 | 키가 없으면 | `const` `map` |
| --- | --- | --- |
| `m[키]` | 새 원소를 만듦 | 안 됨 |
| `m.find(키)` | `end()`를 돌려줌 | 됨 |
| `m.at(키)` | `std::out_of_range` 예외 | 됨 |
| `m.count(키)` | 0(`map`은 0 아니면 1) | 됨 |
| `m.contains(키)` <Badge text="C++20" /> | `false` | 됨 |

- 키가 있다고 확실하고 `const`가 아니면 `operator[]`가 가장 간단함. 값의 참조를 돌려주므로 `pair`에서 꺼낼 필요 없이 바로 쓰고 고침: `stock["배"] += 1;`
- 있는지 모르거나 `const`면 `find()` 또는 `at()`
- 키가 있는지만 알고 싶으면 `contains()`. 모든 연관 컨테이너(정렬된, 정렬되지 않은, 평평한)에 있음. `count()`로 확인할 필요가 없어짐

### 지우기

- 반복자 위치의 원소 하나(분할 상환 상수 시간), 반복자 범위의 원소들을 지움. 순차 컨테이너의 `erase()`와 같음
- `map`만의 좋은 기능: **키로** 지우기. `stock.erase("수박");`(로그 시간). 지운 원소 수를 돌려줌

## 노드

- 정렬된·정렬되지 않은 연관 컨테이너는 모두 **노드 기반** 자료 구조
- **노드 핸들** (node handle) <Badge text="C++17" />: 노드에 직접 접근함 <CppRef path="cpp/container/node_handle" />
  - 정확한 타입은 정해지지 않았고, 컨테이너마다 별칭 `node_type`이 있음
  - **이동만** 됨. 노드에 담긴 원소를 소유함. 키와 값 모두 읽고 쓸 수 있음
- `extract(반복자)` 또는 `extract(키)`: 노드를 노드 핸들로 꺼냄. 핸들이 원소의 유일한 소유자가 되므로 컨테이너에서는 빠짐
- 노드 핸들을 받는 `insert()` 오버로드로 다른 컨테이너에 넣음
  - 원소를 **복사하지도 이동하지도 않고** 한 연관 컨테이너에서 다른 것으로 옮김
  - `map`에서 `multimap`으로, `set`에서 `multiset`으로도 옮길 수 있음

```cpp
std::map<std::string, int> sold;
auto node{ stock.extract("딸기") };
sold.insert(std::move(node));
// 한 줄로
sold.insert(stock.extract("딸기"));
```

- `merge(다른 컨테이너)`: 모든 노드를 옮김. 대상이 중복을 허용하지 않아 옮길 수 없는 노드(같은 키가 이미 있는 것)는 원래 컨테이너에 남음

- 볼 것
  - `pair`는 `first`부터 비교함("배" < "사과"는 가나다순)
  - `insert`는 이미 있는 "사과"를 덮어쓰지 않고, `insert_or_assign`은 덮어씀
  - `try_emplace("귤", 99)`와 `insert_range`의 "감"은 이미 있어 무시됨
  - 범위 기반 `for` 문에서 값을 두 배로 만듦. 키는 고칠 수 없음
  - `stock["수박"]`을 읽기만 했는데 크기가 하나 늘어남
  - `extract`로 "딸기" 노드를 옮기고, `merge`에서 겹치는 "배"는 `extra`에 남음

## 헷갈리기 쉬운 점

- `insert()`로 같은 키를 다시 넣으면 값이 바뀐다?
  - 바뀌지 않음. 결과의 `bool`이 `false`. 바꾸려면 `insert_or_assign()`이나 `operator[]`
- `if (m[key] == 0)`으로 키가 있는지 확인한다?
  - 없으면 원소가 생겨 버림. `contains()`나 `find()`
- `const std::map&` 매개변수에 `m[key]`를 쓸 수 있다?
  - `operator[]`는 `const`가 아님. `find()`나 `at()`
- 범위 기반 `for` 문에서 키를 고칠 수 있다?
  - 키는 `const`. 바꾸려면 `extract()`로 꺼내 핸들의 `key()`를 고친 뒤 다시 `insert()`(또는 지우고 다시 넣기)
- `std::map m{ { "a"s, 1 } };`처럼 인수 추론이 된다?
  - 안 됨. `std::pair{ ... }`를 명시하거나 타입을 적음

## 정리

| 요소 | 핵심 |
| --- | --- |
| `pair` | `first`, `second`, 사전식 비교, `make_pair`, 인수 추론 |
| `map` | 키로 정렬된 키-값 쌍. 로그 시간. 키는 유일 |
| 넣기 | `insert`(안 덮음), `insert_or_assign`/`[]`(덮음), `try_emplace`, `insert_range` |
| 훑기 | 원소는 `pair<const 키, 값>`. 구조적 바인딩 |
| 찾기 | `find`, `at`, `contains`, `count`. `[]`는 없으면 만듦, `const` 불가 |
| 지우기 | 반복자, 범위, 키 |
| 노드 | `extract`, 노드 핸들 `insert`, `merge`. 복사·이동 없이 옮김 |
