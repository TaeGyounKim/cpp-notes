- 다루는 것: 반복자로 `vector`를 훑고, 아무 위치에나 원소를 넣고 지우는 법
- 이 글에서 배우는 요소: `iterator`와 `const_iterator`, 반복자 안전성, `reference_wrapper`, `insert`/`erase`, `std::erase`, `emplace`, 반복자 무효화

## vector 반복자

- 범위 기반 `for` 문은 반복자로 바꿔 쓸 수 있음(17장)

```cpp
for (std::vector<double>::iterator it{ std::begin(scores) };
     it != std::end(scores); ++it) {
    *it /= top;
}
// auto로 줄이면
for (auto it{ std::begin(scores) }; it != std::end(scores); ++it) { *it /= top; }
```

- 각 부분
  - 컨테이너마다 반복자 타입 `iterator`가 있고, `begin()`은 첫 원소를 참조하는 그 타입의 반복자를 돌려줌
  - `it != end`: 끝 다음 위치에 다다르면 멈춤. 늘 `!=`를 씀. `<`는 모든 반복자가 지원하지 않음
  - `++it`: 다음 원소로
  - `*it`: 참조하는 원소. 읽고 고칠 수 있음
- 전위 `++it`를 쓸 수 있으면 후위 `it++`보다 전위를 씀. 후위는 새 반복자 객체를 돌려줘야 하므로 적어도 같거나 대개 더 느림(15장)
- 반복자를 얻는 멤버: `begin()`/`end()`, `rbegin()`/`rend()`(역방향), `cbegin()`/`cend()`/`crbegin()`/`crend()`(`const`)

:::tip
모든 원소를 훑는다면 반복자보다 범위 기반 `for` 문을 쓴다. 읽고 쓰기 쉽고 실수가 적다. 반복자는 일부 범위만 훑거나 루프 안에서 반복자가 필요할 때 쓴다.
:::

### 객체 원소의 멤버

- 원소가 객체면 반복자에 `->`로 멤버 함수를 부르거나 데이터 멤버에 접근함: `it->append("!");`
- 범위 기반 `for` 문으로 쓰면 더 깔끔한 경우가 많음: `for (auto& s : rooms) { s.append("!"); }`

### const_iterator

- 보통의 `iterator`는 읽고 쓸 수 있음
- `const` 객체에 `begin()`/`end()`를 부르거나 `cbegin()`/`cend()`를 부르면 `const_iterator`를 받음. 읽기 전용이라 참조하는 원소를 고칠 수 없음
  - `iterator`는 언제나 `const_iterator`로 바뀔 수 있음. 반대는 안 됨
- `auto`와 함께 쓰면 컴파일러는 `vector`가 `const`가 아닌 한 `begin()`의 반환형인 `iterator`로 추론함. 읽기 전용을 원하면 `cbegin()`/`cend()`를 씀
- 범위 기반 `for` 문은 `for (const auto& s : rooms)`로 읽기 전용이 됨

:::tip
원소를 고칠 필요가 없으면 `const_iterator`를 쓴다. 코드가 올바름을 보장하기 쉽고 컴파일러가 더 잘 최적화할 수 있다.
:::

### 반복자 안전성

- 반복자는 대체로 포인터만큼 안전함. 즉 **매우 안전하지 않음**. 반복자는 아무 검증도 하지 않아도 됨

```cpp
std::vector<int> v;
auto it{ std::end(v) };
*it = 10;   // 버그! end()는 마지막 원소가 아니라 끝 다음
```

- 짝이 맞지 않는 반복자: 다른 `vector`의 반복자끼리 비교하면 의도대로 되지 않고 끝나지 않을 수도 있음

```cpp
for (auto it{ std::begin(b) }; it != std::end(a); ++it) { /* ... */ }   // 버그
```

- 어떤 구현은 디버그 빌드에서 이런 문제를 실행 시간에 잡아 줌(GCC는 `-D_GLIBCXX_DEBUG`). 릴리스 빌드에서는 성능 때문에 보통 검사하지 않음

### 그 밖의 반복자 연산

- `vector` 반복자는 **임의 접근**이라 앞뒤로 움직이고 건너뛸 수 있음: `it += 5; --it; *it = 4;`

### 반복자를 쓰는 이유

- 인덱스와 `size()`로도 훑을 수 있는데 반복자를 쓰는 이유
  - 컨테이너의 아무 위치에나 원소나 원소 범위를 넣고 지울 수 있음(아래)
  - 표준 라이브러리 알고리즘을 쓸 수 있음(20장)
  - 원소를 차례로 접근할 때 인덱스로 하나씩 꺼내는 것보다 효율적인 경우가 많음. `vector`에는 해당하지 않지만 `list`, `map`, `set`에는 해당함

## 참조를 담는 vector

- 1편에서 말한 대로 `std::reference_wrapper`를 담으면 컨테이너에 참조를 저장할 수 있음
  - `std::ref()`, `std::cref()`로 `const`가 아닌 / `const` `reference_wrapper`를 만들고, `get()`으로 감싼 객체에 접근함. 모두 `<functional>`

```cpp
std::string first{ "거실" };
std::string second{ "부엌" };
std::vector<std::reference_wrapper<std::string>> refs{ std::ref(first) };
refs.push_back(std::ref(second));
refs[1].get() += "(수리 중)";   // second가 바뀜
```

## 원소 넣기와 지우기

- `push_back()`: 끝에 더함. `pop_back()`: 마지막 원소를 지움

:::caution
`pop_back()`은 지운 원소를 돌려주지 않는다. 필요하면 먼저 `back()`으로 꺼낸다.
:::

- `insert()`: 반복자로 지정한 위치(**앞**)에 원소를 하나 이상 넣음. 뒤의 원소들을 밀어 자리를 만듦 <CppRef path="cpp/container/vector/insert" />

| 오버로드 | 넣는 것 |
| --- | --- |
| `insert(pos, x)` | `x` 하나(복사) |
| `insert(pos, std::move(x))` | `x` 하나(이동) |
| `insert(pos, n, x)` | `x`를 n개 |
| `insert(pos, first, last)` | 반복자 범위 [first, last)의 원소들 |
| `insert(pos, { ... })` | 초기화 리스트의 원소들 |

- `push_back()`과 `insert()`에는 좌측값을 받는 판(복사)과 우측값을 받는 판(이동)이 있음. 둘 다 필요하면 메모리를 잡음
- `insert()`는 넣은 (첫) 원소를 참조하는 반복자를 돌려줌
- <Badge text="C++23" /> `assign_range()`(모두 바꿈), `insert_range()`(위치에 넣음), `append_range()`(끝에 더함): 범위를 받음(17장)
- `erase(pos)`: 한 원소, `erase(first, last)`: 범위를 지움. `clear()`: 모두 지움
- 다른 `vector` 전체를 끝에 넣으려면 `insert(v.cend(), other.cbegin(), other.cend())`. 넣는 위치의 **앞**에 넣으므로 끝 반복자를 주면 끝에 붙음. C++23이면 `v.append_range(other)`가 더 분명함

:::caution
반복자 범위를 받는 `insert()`, `erase()` 등은 시작과 끝 반복자가 **같은 컨테이너**의 원소를 참조하고 끝이 시작보다 앞서지 않는다고 가정한다. 이 전제가 깨지면 제대로 동작하지 않는다.
:::

### 조건에 맞는 원소 모두 지우기

- 원소를 훑으며 맞는 것마다 `erase()`하면 **이차** 시간이 걸려 느림
  - 선형 시간인 **지우기-제거 관용구** (remove-erase idiom)가 있음(20장)
- <Badge text="C++20" /> 모든 표준 컨테이너에 정의된 비멤버 함수 `std::erase()`, `std::erase_if()` <CppRef path="cpp/container/vector/erase2" />

```cpp
std::erase(temps, -99);                                  // -99를 모두 지움
std::erase_if(temps, [](int t) { return t > 22; });     // 조건자가 참인 것을 지움
```

- 조건자로는 함수 포인터, 함수 객체, 람다 표현식을 줄 수 있음(19장)

### 이동

- `names.push_back(label);`: `label`이 임시 객체가 아니므로 **복사**해서 넣음
- `push_back(T&&)`도 있음. `names.push_back(std::move(label));`로 복사를 피함
  - 그 뒤 `label`은 유효하지만 정해지지 않은 상태. `clear()` 등으로 상태를 정하기 전에는 쓰지 않음
- `names.push_back(std::string(3, 'a'));`: 생성자 호출 결과가 임시 객체라 이동 판이 불림

### 제자리 생성

- **제자리 생성** (emplace): 대부분의 표준 컨테이너에 있음. 복사도 이동도 하지 않고 컨테이너 안에 공간을 만들어 그 자리에서 객체를 생성함 <CppRef path="cpp/container/vector/emplace_back" />

```cpp
names.emplace_back(3, 'b');   // std::string(3, 'b')를 제자리에서 만듦
```

- 인수를 가변 인수 템플릿(26장)으로 받아 원소 타입의 생성자에 그대로 넘김
- 이동하는 `push_back()`과의 성능 차이는 구현에 따라 다름. 대부분은 문법이 마음에 드는 쪽을 고르면 됨
- `emplace_back()`은 넣은 원소의 참조를 <Badge text="C++17" />, `emplace(pos, ...)`는 넣은 원소를 참조하는 반복자를 돌려줌

## 복잡도와 반복자 무효화

- 넣거나 지우면 뒤의 원소들을 모두 한 칸씩 밀거나 당겨야 하므로 **선형 시간**
- 넣거나 지운 위치와 그 뒤를 참조하던 반복자는 모두 **무효**가 됨
  - 반복자는 밀리고 당겨지는 원소를 "알아서" 따라가지 않음. 따라가게 하는 것은 쓰는 쪽의 몫
- 내부 **재할당**이 일어나면 넣거나 지운 위치와 상관없이 그 `vector`의 원소를 참조하던 **모든** 반복자가 무효가 됨(4편)

<StepViz client:load data={invViz} />

- 대처: 넣거나 지운 뒤에는 반복자를 다시 얻음. `insert()`와 `erase()`가 돌려주는 반복자를 쓰면 편함

- 볼 것
  - `cbegin()`으로 얻은 반복자로는 원소를 고칠 수 없음
  - `reference_wrapper`를 통해 고친 것이 `second`에 반영됨
  - `insert`, 범위 `insert`, `append_range`, `erase`, `pop_back`의 결과
  - `std::erase`와 `std::erase_if`로 한 줄에 걸러 지움
  - `insert()`가 돌려준 반복자로 새 원소와 그 다음 원소를 읽음

## 이전 표준에서는

| 이 글에서 쓴 것 | 들어온 표준 | 그 이전에는 |
| --- | --- | --- |
| `append_range`, `insert_range`, `assign_range` | C++23 | 범위 `insert(pos, first, last)`, `assign(first, last)` |
| `std::erase`, `std::erase_if` | C++20 | 지우기-제거 관용구 `v.erase(std::remove(...), v.end())` |
| `emplace_back`이 참조를 돌려줌 | C++17 | `emplace_back` 뒤 `back()` |

## 헷갈리기 쉬운 점

- `auto it{ v.begin() }`는 `v`가 `const`가 아니어도 읽기 전용이다?
  - `iterator`로 추론됨. 읽기 전용은 `cbegin()`
- `pop_back()`은 마지막 원소를 돌려준다?
  - 돌려주지 않음(`void`). 먼저 `back()`
- `insert(pos, x)`는 `pos` 뒤에 넣는다?
  - `pos`의 **앞**에 넣음. 끝 반복자를 주면 맨 끝
- 원소를 넣어도 앞쪽을 가리키던 반복자는 늘 안전하다?
  - 재할당이 일어나면 모든 반복자가 무효. 재할당이 없어도 넣은 위치와 그 뒤는 무효
- 루프 안에서 맞는 원소마다 `erase()`하면 된다?
  - 이차 시간이고, 지운 뒤 반복자가 무효가 되는 것도 처리해야 함. `std::erase_if`를 씀

## 정리

| 요소 | 핵심 |
| --- | --- |
| 반복자 | `begin`/`end`, `!=`, 전위 `++`, `*`, `->` |
| `const_iterator` | `cbegin`/`cend`. 읽기 전용. `iterator`에서 바뀔 수 있음 |
| 안전성 | 검증 없음. `end()` 역참조, 다른 컨테이너의 반복자 섞기 금지 |
| 참조 담기 | `std::reference_wrapper`, `std::ref`, `get()` |
| 넣기·지우기 | `push_back`, `pop_back`, `insert`(위치 앞), `erase`, `clear`, C++23 `*_range` |
| 조건 지우기 | C++20 `std::erase`, `std::erase_if`(선형 시간) |
| 이동·제자리 | `push_back(std::move(x))`, `emplace_back(생성자 인수...)` |
| 무효화 | 넣거나 지운 위치와 그 뒤, 재할당이면 전부. 반복자를 다시 얻음 |

<details>
<summary>`auto it{ v.begin() }; v.push_back(1); *it = 0;`이 위험한 이유는?</summary>

- `push_back`이 용량을 넘으면 재할당되어 `it`가 해제된 옛 버퍼를 가리킴. 역참조는 정의되지 않은 동작. `push_back` 뒤에 `it`를 다시 얻음

</details>

<details>
<summary>`std::vector<Point>`에 `Point{ 1, 2 }`를 넣을 때 `push_back`과 `emplace_back`은 어떻게 다르게 쓰는가?</summary>

- `v.push_back(Point{ 1, 2 });`는 임시 `Point`를 만들어 이동함
- `v.emplace_back(1, 2);`는 생성자 인수를 넘겨 제자리에서 만듦(C++20부터는 집합체도 소괄호 초기화가 되어 `emplace_back`이 됨)

</details>
