## 클래스 정의

- 클래스를 쓴다는 것은 두 가지를 정하는 일
  - 그 클래스의 객체에 적용할 **행동**: 멤버 함수
  - 객체마다 담을 **속성**: 데이터 멤버
- 작업은 두 부분: 클래스 자체를 정의하기, 멤버 함수를 정의하기

```cpp
class Temperature
{
public:
    void setCelsius(double celsius);
    double getCelsius() const;

private:
    double m_celsius;
};
```

- **클래스 정의** (class definition): `class` 키워드와 클래스 이름으로 시작함 <CppRef path="cpp/language/class" />
  - 클래스 정의는 선언이므로 **세미콜론**으로 끝남. 빠뜨리기 쉬움
- 파일 구성
  - 클래스 정의는 보통 클래스 이름을 딴 파일에 둠
  - 모듈을 쓴다면 모듈 인터페이스 파일(예: `Temperature.cppm`)에 두고, 모듈 밖에서 쓸 수 있게 `export class Temperature`처럼 `export`를 붙임. 확장자는 컴파일러에 따라 정해진 것을 써야 할 수도 있음
  - 모듈과 헤더 파일: 11장. 이 사이트의 실행 예제는 한 파일에 모두 넣음

### 클래스 멤버

- 클래스가 가질 수 있는 **멤버** (member)

| 종류 | 예 |
| --- | --- |
| 멤버 함수 | 보통 함수, 생성자, 소멸자 |
| 데이터 멤버 (멤버 변수) | `m_celsius` |
| 그 밖에 | 멤버 열거형, 타입 별칭, 중첩 클래스 등 |

- 함수 원형처럼 생긴 줄: 클래스가 지원하는 멤버 함수의 선언
  - 객체를 바꾸지 않는 멤버 함수에는 `const`를 붙일 것(1장). `getCelsius() const`
- 변수 선언처럼 생긴 줄: 데이터 멤버의 선언
- 클래스는 **개념**을 정의하고, 객체는 **실제 데이터**를 담음
  - 객체마다 자기 `m_celsius` 값을 따로 가짐
  - 멤버 함수의 구현은 모든 객체가 함께 씀
  - 예외: `static` 멤버(9장)
- 데이터 멤버와 멤버 함수에 같은 이름을 줄 수 없음
  - GCC: `'int T::value' conflicts with a previous declaration`

### 접근 제어

- 모든 멤버는 세 **접근 지정자** (access specifier) 가운데 하나의 적용을 받음: `public`, `private`, `protected` <CppRef path="cpp/language/access" />
  - `protected`는 상속과 함께 10장에서 다룸
- 접근 지정자는 그 뒤에 오는 모든 멤버 선언에 적용됨. 다음 접근 지정자가 나올 때까지
- `class`의 기본 접근은 `private`: 첫 접근 지정자 앞의 멤버는 모두 `private`

### class와 struct

- C++에서 `struct`도 `class`처럼 멤버 함수를 가질 수 있음
- 차이는 **딱 하나**: 기본 접근이 `struct`는 `public`, `class`는 `private`
- 관례
  - `struct`는 공개된 데이터 멤버만 모으고 멤버 함수가 없을 때 씀. 예: 2차원 좌표 `Point`
  - 멤버 함수가 있고 데이터를 숨기는 타입은 `class`

- 해 볼 것: `counter.m_count = 100;`의 주석을 풀면 컴파일 오류: `'int Counter::m_count' is private within this context`

### 선언 순서

- 멤버와 접근 지정자를 어떤 순서로 적든 됨
  - 멤버 함수를 데이터 멤버보다 먼저, `public`을 `private`보다 먼저 같은 제약이 없음
  - 같은 접근 지정자를 여러 번 적어도 됨
- 그래도 읽기 쉽도록 접근 지정자별로 묶고, 그 안에서 멤버 함수와 데이터 멤버를 묶을 것

### 클래스 안 멤버 초기화

- 데이터 멤버를 클래스 정의 안에서 바로 초기화할 수 있음 <Badge text="C++11" /> <CppRef path="cpp/language/data_members" />

```cpp
private:
    double m_celsius{ 0.0 };
```

- 그 객체를 만들 때 따로 값을 주지 않으면 이 값으로 시작함

:::tip
클래스의 데이터 멤버는 언제나 초기화한다.
:::

## 멤버 함수 정의하기

- 위의 클래스 정의만으로도 객체를 만들 수는 있음
- 그러나 `setCelsius()`를 부르면 **링커**가 불평함. 원형만 있고 구현이 없기 때문
  - GCC: `undefined reference to 'Temperature::setCelsius(double)'`
- 멤버 함수를 정의하는 두 자리

| 자리 | 모습 |
| --- | --- |
| 클래스 정의 안 | `void setCelsius(double celsius) { m_celsius = celsius; }` |
| 클래스 정의 밖 | 아래처럼 `클래스이름::`을 붙여 따로 정의 |

```cpp
void Temperature::setCelsius(double celsius)
{
    m_celsius = celsius;
}
```

- `::`는 **범위 지정 연산자** (scope resolution operator). 여기서는 "이 `setCelsius()`는 `Temperature` 클래스의 것"이라고 컴파일러에 알림
- 밖에서 정의할 때는 접근 지정자(`public` 등)를 다시 적지 않음
- 모듈로 나눈다면
  - 클래스 정의는 모듈 인터페이스 파일에
  - 멤버 함수 정의는 인터페이스 파일에 함께 두거나, 첫 줄에 `module 모듈이름;`을 적은 **모듈 구현 파일**에 둠
  - 헤더 파일과 달리 모듈에서는 인터페이스 파일에 정의를 둬도 해가 없음(11장). 다만 인터페이스를 깔끔하게 유지하려고 구현 파일로 빼는 경우가 많음

### 데이터 멤버에 접근하기

- `static`이 아닌 멤버 함수는 언제나 그 클래스의 **특정 객체**를 위해 실행됨
- 멤버 함수 안에서는 그 객체의 모든 데이터 멤버에 접근할 수 있음
  - `m_celsius = celsius;`는 이 멤버 함수를 부른 바로 그 객체의 `m_celsius`를 바꿈
  - 두 객체에서 각각 부르면, 같은 코드 한 줄이 서로 다른 두 객체의 변수를 바꿈

### 다른 멤버 함수 부르기

- 멤버 함수 안에서 같은 클래스의 다른 멤버 함수를 부를 수 있음. 객체 이름 없이 그냥 이름으로
- 예: `Temperature`를 넓혀 화씨와 문자열로도 읽고 쓰게 함
  - 저장은 섭씨(`double`) 하나로만 함
  - 화씨로 정하면 섭씨로 바꿔 저장함: `setFahrenheit()`가 `setCelsius()`를 부름
  - 문자열로 정하면 숫자로 바꿔 저장함. 숫자가 아니면 0
  - 바꾸는 일은 `private` **도우미 멤버 함수** `format()`과 `parse()`에 맡김. 밖에서 부를 일이 없으므로 숨김

- 볼 것
  - `setText("hot")`: `from_chars`가 숫자를 읽지 못하면 `value`를 건드리지 않음. `parse()`는 처음 넣어 둔 0을 돌려주고, 온도는 36.5에서 0이 됨
  - `std::format("{:.1f}C", ...)`: 소수점 한 자리로 표시. 형식화는 2장, `from_chars`도 [2장](../../../part1/ch02/03-numeric-conversions/)

## 헷갈리기 쉬운 점

- 클래스 정의 끝의 세미콜론
  - `}` 뒤에 `;`가 필요함. 빠뜨리면 그 뒤 엉뚱한 줄에서 오류가 날 수 있음
- `class`와 `struct`는 전혀 다른 것이다?
  - 기본 접근만 다름. 관례상 데이터만 모을 때 `struct`
- 멤버 함수를 선언만 해도 쓸 수 있다?
  - 컴파일은 되지만 부르면 링크 단계에서 `undefined reference` 오류. 정의가 있어야 함
- 멤버 함수를 밖에서 정의할 때 `public`도 다시 적는다?
  - 적지 않음. 접근 지정은 클래스 정의 안에서만
- 멤버 함수는 객체마다 따로 있다?
  - 코드는 하나를 모든 객체가 함께 씀. 따로 있는 것은 데이터 멤버의 값

## 정리

| 요소 | 핵심 |
| --- | --- |
| 클래스 정의 | `class 이름 { ... };` 세미콜론 필수 |
| 멤버 | 멤버 함수, 데이터 멤버, 열거형, 타입 별칭, 중첩 클래스 |
| 접근 지정자 | `public`, `private`, `protected`. 다음 지정자까지 적용 |
| `class` / `struct` | 기본 접근 `private` / `public` |
| 클래스 안 멤버 초기화 | `double m_celsius{ 0.0 };` 데이터 멤버는 언제나 초기화 |
| 멤버 함수 정의 | 클래스 안에서, 또는 밖에서 `클래스::이름` |
| 데이터 멤버 접근 | 멤버 함수를 부른 그 객체의 멤버 |
| 도우미 멤버 함수 | 밖에서 쓸 일 없으면 `private` |

## 복습 질문

<details>
<summary>`class A { int x; public: int y; };`에서 `x`와 `y`의 접근 수준은? `struct`였다면?</summary>

- `class`: `x`는 `private`(기본), `y`는 `public`
- `struct`: `x`도 `public`(기본), `y`는 `public`

</details>

<details>
<summary>멤버 함수 `void Box::resize(int size)`를 클래스 밖에서 정의할 때 `Box::`를 빼면 어떻게 되는가?</summary>

- `Box`의 멤버가 아닌 그냥 함수 `resize`를 정의한 것이 됨
- 그 안에서 `Box`의 데이터 멤버를 쓰면 컴파일 오류. 멤버 함수 `Box::resize`는 여전히 정의가 없어 링크 오류

</details>

<details>
<summary>`Temperature` 객체 둘에 `setCelsius()`를 각각 부르면 왜 서로 영향을 주지 않는가?</summary>

- 멤버 함수는 그것을 부른 객체의 데이터 멤버를 다루기 때문
- 코드는 하나지만 데이터 멤버는 객체마다 따로 있음

</details>

<details>
<summary>`format()`과 `parse()`를 `private`으로 둔 이유는?</summary>

- 클래스 안에서만 쓰는 도우미라 인터페이스에 드러낼 필요가 없음
- 구현을 바꿔도 클래스를 쓰는 코드가 영향을 받지 않음

</details>

<details>
<summary>클래스 안 멤버 초기화가 없던 시절 `double m_celsius;`만 적고 객체를 만들어 `getCelsius()`를 부르면?</summary>

- `m_celsius`가 초기화되지 않아 알 수 없는 값을 읽음(지역 객체라면)
- 그래서 데이터 멤버는 언제나 초기화함

</details>
