## 소멸자

- 객체가 사라질 때 두 가지 일이 일어남
  1. 객체의 **소멸자** (destructor) 멤버 함수가 불림 <CppRef path="cpp/language/destructor" />
  2. 객체가 차지하던 메모리가 풀림
- 소멸자는 객체의 뒷정리를 할 기회. 예: 동적으로 잡은 메모리 돌려주기, 파일 핸들 닫기
- 문법
  - 이름은 클래스 이름 앞에 물결표 `~`를 붙인 것: `~Probe()`
  - 반환 타입도 매개변수도 없음. 그래서 하나만 있을 수 있음(오버로딩 불가)
- 직접 쓰지 않으면 컴파일러가 만들어 줌. 멤버들을 차례로 소멸시키는 소멸자

```cpp
class Probe
{
public:
    ~Probe();
};

Probe::~Probe()
{
    std::println("소멸");
}
```

### 소멸되는 때와 순서

- 스택의 객체: **범위를 벗어날 때** 소멸
  - 함수나 블록이 끝날 때, 즉 닫는 중괄호 `}`를 만날 때, 그 중괄호 안에서 만든 스택 객체들이 소멸됨
  - 중괄호 한 쌍으로 프로그램 어디서든 새 블록을 열 수 있음
- 순서: 스택 객체는 선언(생성)의 **역순**으로 소멸
  - 먼저 만든 것이 나중에 사라짐. 나중에 만든 객체가 먼저 만든 객체에 기대고 있을 수 있기 때문
- 데이터 멤버도 같은 규칙
  - 멤버는 클래스에 선언된 순서대로 초기화됨(앞 글)
  - 그러니 선언 순서의 역순으로 소멸됨
- 자유 저장소의 객체: 스마트 포인터 없이 만들었다면 저절로 소멸되지 **않음**
  - `delete`를 불러야 소멸자가 불리고 메모리가 풀림

  - `Station`의 멤버: 실내 → 실외 순으로 생성, 실외 → 실내 순으로 소멸

## 대입 연산자

- `int` 값을 다른 `int`에 대입하듯, 객체도 다른 객체에 대입할 수 있음: `b = a;`
- 용어 구별
  - C++에서 **복사**는 객체를 **초기화할 때만** 일어나는 일. 그 도구가 복사 생성자
  - 이미 값이 있는 객체에 덮어쓰는 것은 **대입**
  - 복사 생성자는 생성자라서 객체를 만들 때만 쓸 수 있음. 그 뒤의 대입에는 쓸 수 없음
- 그래서 클래스마다 대입을 맡는 멤버 함수가 따로 있음: **대입 연산자** (assignment operator) <CppRef path="cpp/language/copy_assignment" />
  - 이름은 `operator=`. 그 클래스에 대해 `=` 연산자를 오버로딩한 것
  - `b = a;`는 `b`의 `operator=`를 `a`를 인수로 부르는 것
  - 오른쪽 객체에서 왼쪽 객체로 데이터를 복사하므로 **복사 대입 연산자** (copy assignment operator)라고도 함. 9장에서 데이터를 옮기는 이동 대입 연산자를 배움
- 직접 쓰지 않으면 컴파일러가 만들어 줌. 복사 생성자와 거의 같게, 데이터 멤버를 하나씩 대입함

### 선언

```cpp
Temperature& operator=(const Temperature& rhs);
```

- 매개변수: 복사 생성자처럼 원본을 `const` 참조로 받음
  - 이름 `rhs`는 등호의 오른쪽(right-hand side)이라는 뜻. 이름은 자유
  - 이 연산자를 부른 객체(`this`)가 등호의 왼쪽
- 반환: 복사 생성자와 달리 **자기 자신의 참조**를 돌려줌. 대입을 이어 쓸 수 있게 하려고
  - `a = b = c;`는 실제로 `a.operator=(b.operator=(c));`
  - 안쪽 `b.operator=(c)`가 돌려준 값이 바깥 대입의 인수가 됨. 그러니 대입 결과인 `b` 자신을 돌려줘야 함

:::caution
대입 연산자는 문법상 `void`를 포함해 아무 타입이나 돌려줄 수 있다. 그래도 사용자가 기대하는 대로 언제나 이 객체의 참조를 돌려준다.
:::

### 정의

- 복사 생성자와 비슷하지만 두 가지가 다름
  - 복사 생성자는 초기화에만 쓰이므로 대상 객체에 아직 값이 없음. 대입 연산자는 **이미 있는 값**을 덮어씀. 객체가 동적 메모리 같은 자원을 가질 때 중요해짐(9장)
  - **자기 대입** (self-assignment)이 문법상 허용됨: `t = t;`. 이것을 고려해야 함
- 그래서 대입 연산자는 보통 자기 대입인지부터 확인하고, 그렇다면 바로 돌아감

```cpp
Temperature& Temperature::operator=(const Temperature& rhs)
{
    if (this == &rhs) {   // 자기 대입
        return *this;
    }
    m_celsius = rhs.m_celsius;
    return *this;
}
```

- `this == &rhs`의 뜻
  - 두 객체가 같은 객체인지는 같은 메모리 자리에 있는지, 즉 가리키는 포인터가 같은지로 알 수 있음
  - `this`는 왼쪽 객체를, `&rhs`는 오른쪽 객체를 가리키는 포인터
- `return *this;`
  - `this`는 이 객체를 가리키는 포인터이고 `*this`는 객체 자체. 반환 타입이 참조이므로 이 객체의 참조가 돌아감
  - 자기 대입일 때도 반환 타입에 맞는 값을 돌려줘야 하므로 똑같이 `*this`

- 볼 것
  - `a = b = c;`: 오른쪽 `b = c`가 먼저, 그다음 `a = (b의 결과)`
  - `a = a;`: 자기 대입을 알아채고 바로 돌아감
- 이 클래스는 `double` 하나뿐이라 자기 대입을 확인하지 않아도 문제가 없음. 동적 메모리를 가진 클래스에서는 반드시 필요함(9장)
- 이 대입 연산자도 보여 주려고 쓴 것. 컴파일러가 만든 것(멤버별 대입)으로 충분함
- 복사 생성자와 대입 연산자에 "멤버를 모두 복사하는" 코드가 겹침. 9장의 **복사 후 교환** (copy-and-swap) 관용구로 해결함

:::caution
복사에 특별한 처리가 필요한 클래스라면 복사 생성자와 복사 대입 연산자를 언제나 둘 다 직접 쓴다.
:::

### = default, = delete, 그리고 폐기 예정 규칙

- 대입 연산자도 명시적으로 기본 정의를 요청하거나 지울 수 있음 <Badge text="C++11" />

```cpp
Temperature& operator=(const Temperature& rhs) = default;
Temperature& operator=(const Temperature& rhs) = delete;
```

- C++11에서 **폐기 예정**(deprecated)이 된 규칙
  - 복사 대입 연산자나 소멸자를 직접 선언한 클래스에서 컴파일러가 복사 생성자를 만들어 주는 것
  - 복사 생성자나 소멸자를 직접 선언한 클래스에서 컴파일러가 복사 대입 연산자를 만들어 주는 것
  - 지금은 여전히 만들어 주지만 앞으로 바뀔 수 있음. 필요하면 `= default`로 직접 요청할 것
  - GCC는 `-Wextra`에서 한쪽 경우를 경고함: `implicitly-declared 'constexpr A::A(const A&)' is deprecated`

## 복사와 대입 구별하기

- 규칙: **선언처럼 보이면 복사 생성자, 대입문처럼 보이면 대입 연산자**

| 코드 | 불리는 것 | 이유 |
| --- | --- | --- |
| `Temperature b{ a };` | 복사 생성자 | `b`를 새로 만드는 선언 |
| `Temperature c = a;` | 복사 생성자 | `=`가 있어도 선언. `c{ a }`를 달리 쓴 것 |
| `b = c;` | 대입 연산자 | `b`는 이미 있음 |

### 값으로 돌려줄 때

- 함수가 객체를 값으로 돌려주면 복사와 대입이 섞여 헷갈리기 쉬움
- `s = f();` (이미 있는 `s`에 받기)
  - `f()`가 돌려준 값으로 이름 없는 **임시 객체**가 생기고, 그것을 `s`에 **대입**함. 그 뒤 임시 객체는 사라짐
- `T s = f();` (새로 선언하며 받기)
  - 대입 연산자는 불리지 않음. 원칙적으로는 임시 객체로부터 복사 생성자가 불림
  - 실제로는 컴파일러가 복사를 아예 없앰: **복사 생략** (copy elision) <CppRef path="cpp/language/copy_elision" />
  - `return Temperature{ 28.5 };`처럼 임시 객체를 바로 돌려주면 C++17부터는 생략이 **보장**됨 <Badge text="C++17" />. 1장에서 본 내용
- 이동 의미론(9장)이 있으면 복사 대신 더 싼 이동이 쓰이기도 함

- 볼 것
  - `Temperature c = a;`는 복사 생성자. 대입 연산자가 아님
  - `Temperature d = makeNoon();`: 아무 메시지도 없음. 복사 생략으로 `d` 자리에 바로 만들어짐
  - `d = makeNoon();`: 임시 객체를 `d`에 대입
- 무엇이 언제 불리는지 헷갈리면 이 예처럼 출력을 잠시 넣어 보거나 디버거로 한 줄씩 따라가 봄

## 복사 생성자 안의 멤버 객체

- 컴파일러가 만든 복사 생성자는 멤버 객체마다 그 복사 생성자를 부름
- 직접 쓸 때도 생성자 초기화 목록을 쓰면 같은 일이 됨
- 초기화 목록에서 멤버를 빠뜨리면
  - 본문 실행 전에 그 멤버는 기본 초기화됨(객체라면 기본 생성자)
  - 그 뒤 본문에서 `m_unit = src.m_unit;`으로 값을 넣으면 그것은 **대입**
  - 즉 "기본 생성 + 대입" 두 단계가 되어, "복사 생성" 한 단계보다 일이 많음

## 헷갈리기 쉬운 점

- 스택 객체는 만든 순서대로 사라진다?
  - 역순. 데이터 멤버도 선언의 역순
- `new`로 만든 객체도 함수가 끝나면 사라진다?
  - 포인터 변수만 사라지고 객체는 남음. `delete`나 스마트 포인터가 필요
- `T c = a;`는 대입이다?
  - 선언이므로 복사 생성자
- 대입 연산자는 `void`를 돌려줘도 된다?
  - 컴파일은 되지만 `a = b = c;`가 안 됨. `*this`의 참조를 돌려줌
- 자기 대입 확인은 늘 필요 없다?
  - 기본 타입 멤버뿐이면 문제없지만, 자원을 가진 클래스에서는 빠뜨리면 자기 자원을 먼저 지워 버릴 수 있음(9장)
- 복사 생성자 본문에서 `m_x = src.m_x;`로 써도 결과는 같다?
  - 값은 같지만 기본 생성 후 대입이 됨. 초기화 목록이 바른 방법

## 정리

| 요소 | 핵심 |
| --- | --- |
| 소멸자 | `~T()`. 반환 타입·매개변수 없음. 뒷정리 |
| 소멸 시점 | 스택: 범위 끝. 자유 저장소: `delete` 때 |
| 소멸 순서 | 생성의 역순. 멤버는 선언의 역순 |
| 대입 연산자 | `T& operator=(const T& rhs)`. 이미 있는 객체에 덮어씀 |
| 반환값 | `*this`. 대입을 이어 쓰기 위해 |
| 자기 대입 | `if (this == &rhs) return *this;` |
| 복사와 대입 | 선언이면 복사 생성자, 대입문이면 대입 연산자 |
| 값으로 돌려주기 | `s = f();`는 대입, `T s = f();`는 복사(대개 생략됨) |

- `T y = x;`: 복사 생성자(선언)
- `y = x;`: 대입 연산자

</details>

<details>
<summary>대입 연산자 안의 `this == &rhs`는 무엇을 비교하는가?</summary>

- 왼쪽 객체의 주소(`this`)와 오른쪽 객체의 주소(`&rhs`)
- 같으면 같은 객체에 대입하는 자기 대입

</details>

<details>
<summary>`void f() { auto* p{ new T{} }; }`에서 `T`의 소멸자는 언제 불리는가?</summary>

- 불리지 않음. 함수가 끝나면 포인터 `p`만 사라지고 객체는 남아 메모리가 샘
- `delete p;`를 부르거나 `std::make_unique<T>()`를 씀

</details>
