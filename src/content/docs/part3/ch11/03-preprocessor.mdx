- 다루는 것: 1장에서 본 `#include` 말고도 쓸 수 있는 전처리기 지시자들, 그리고 전처리기 매크로
- 이 글에서 배우는 요소: `#define`, `#undef`, `#if`, `#ifdef`, `#ifndef`, `#elifdef`, `#pragma`, `#error`, `#warning`, 매크로의 위험

## 전처리기 지시자

- **전처리기** (preprocessor): 컴파일 전에 소스 코드를 글자 그대로 바꾸는 단계. `#`으로 시작하는 줄이 **전처리기 지시자** (preprocessor directive) <CppRef path="cpp/preprocessor" />

| 지시자 | 하는 일 | 흔한 쓰임 |
| --- | --- | --- |
| `#include [파일]` | 그 자리에 파일의 내용을 넣음 | 다른 곳에 정의된 기능을 쓰려고 헤더 포함 |
| `#define [id] [값]` | 이후 나오는 `id`를 모두 `값`으로 바꿈 | C에서 상수나 매크로를 정의할 때. C++에는 더 나은 수단이 있음 |
| `#undef [id]` | `#define`으로 정의한 `id`를 없앰 | 정의한 식별자를 코드의 좁은 범위에서만 쓸 때 |
| `#if [식]` … `#elif` … `#else` … `#endif` | 식의 결과에 따라 코드 블록을 넣거나 뺌 | 플랫폼별 코드 |
| `#ifdef [id]`, `#ifndef [id]` … `#endif` | `id`가 정의되었는지에 따라 넣거나 뺌 | 헤더를 여러 번 포함하지 않게 막기(포함 가드, 5편) |
| `#elifdef [id]`, `#elifndef [id]` | `#elif defined(id)`, `#elif !defined(id)`의 줄임 <Badge text="C++23" /> | 줄여 쓰기 |
| `#pragma [xyz]` | 컴파일러마다 다른 동작을 제어 | 대부분 `#pragma once` 지원(5편) |
| `#error [메시지]` | 그 메시지와 함께 컴파일을 멈춤 | 지원하지 않는 플랫폼에서 컴파일하려 할 때 |
| `#warning [메시지]` | 그 메시지를 경고로 내고 컴파일은 계속 <Badge text="C++23" /> | 결과에 영향 없이 알릴 것이 있을 때 |

- `#ifdef id`는 `#if defined(id)`와, `#ifndef id`는 `#if !defined(id)`와 같음
- `#error`와 `#warning`의 모습(GCC)
  - `#error "지원하지 않는 플랫폼"` → `error: #error "지원하지 않는 플랫폼"`, 컴파일 멈춤
  - `#warning "실험적 기능"` → `warning: #warning "실험적 기능" [-Wcpp]`, 컴파일 계속

  - `#undef` 뒤에는 정의되어 있지 않음
  - `__cplusplus`: 컴파일러가 미리 정의한 매크로. 컴파일 중인 표준 버전(예: C++23은 `202302L`)

## 전처리기 매크로

- 전처리기로 작은 함수처럼 생긴 **매크로** (macro)를 쓸 수 있음

```cpp
#define SQUARE(x) ((x) * (x))   // 매크로 정의 끝에 세미콜론을 붙이지 않음
std::println("{}", SQUARE(5));
```

- C에서 물려받은 것으로 인라인 함수와 비슷하지만 두 가지가 다름
  - 타입 검사를 하지 않음
  - 전처리기가 부르는 곳을 그 정의로 **글자 그대로** 바꿀 뿐. 진짜 함수 호출처럼 동작하지 않음
- 이 때문에 뜻밖의 결과가 나옴

### 괄호를 빠뜨리면

```cpp
#define SQUARE(x) (x * x)
SQUARE(2 + 3)
```

- 25를 기대하지만 결과는 11
  - 본문의 `x`가 모두 `2 + 3`으로 글자 그대로 바뀌어 `(2 + 3 * 2 + 3)`이 됨
  - 연산자 우선순위대로 곱셈부터 하므로 `2 + 6 + 3 = 11`

### 인수를 여러 번 계산함

```cpp
SQUARE(expensive())
```

- `((expensive()) * (expensive()))`로 바뀜. 비싼 함수를 **두 번** 부름
- 함수라면 인수를 한 번 계산해 매개변수로 넘김

### 그 밖의 문제

- 디버깅이 어려움. 내가 쓴 코드와 컴파일러가 보는 코드(디버거에 보이는 코드)가 다름
- 그래서 매크로는 아예 피하고 인라인 함수(또는 `constexpr` 함수, 9장)를 씀
- 그래도 알아야 함. 매크로를 쓰는 C++ 코드가 아직 많아서 읽고 고치려면 필요함

- 볼 것
  - `SQUARE_BAD(2 + 3)`이 11
  - 매크로는 `expensive()`를 두 번, 함수는 한 번 부름

:::note
대부분의 컴파일러는 전처리한 결과를 파일이나 표준 출력으로 내보낼 수 있다. 전처리기가 파일을 어떻게 바꾸는지 직접 볼 수 있다. Microsoft Visual C++은 `/P`, GCC는 `-E` 옵션이다. 예: GCC로 `int v = SQUARE_BAD(2 + 3);`을 전처리하면 `int v = (2 + 3 * 2 + 3);`이 나온다.
:::

## 이전 표준에서는

| 이 글에서 쓴 것 | 들어온 표준 | 그 이전에는 |
| --- | --- | --- |
| `#elifdef`, `#elifndef` | C++23 | `#elif defined(id)`, `#elif !defined(id)` |
| `#warning` | C++23 | 많은 컴파일러가 확장으로 지원했지만 표준은 아님 |
| `constexpr` 함수 | C++11 | 인라인 함수 또는 매크로 |

- 나머지 지시자와 매크로는 C에서 물려받아 처음부터 있음

## 헷갈리기 쉬운 점

- 매크로는 함수처럼 인수를 먼저 계산한다?
  - 글자 그대로 바꿀 뿐. 괄호를 빠뜨리면 우선순위가 바뀌고, 인수가 여러 번 계산됨
- 매크로 정의 끝에도 세미콜론을 붙인다?
  - 붙이지 않음. 붙이면 바뀐 자리마다 세미콜론이 들어감
- `#ifdef X`는 `X`의 값이 참인지 본다?
  - 정의되어 있는지만 봄. 값을 보려면 `#if X`

## 정리

| 요소 | 핵심 |
| --- | --- |
| `#define` / `#undef` | 식별자를 정의하고 없앰. 상수와 매크로는 C++의 더 나은 수단으로 |
| `#if`, `#ifdef`, `#ifndef` | 조건에 따라 코드를 넣거나 뺌 |
| `#elifdef`, `#elifndef`, `#warning` | C++23에 추가 |
| `#error` | 컴파일을 멈춤 |
| 매크로 | 글자 그대로 바뀜. 타입 검사 없음, 여러 번 계산, 디버깅 어려움 |
| 대안 | 인라인 함수, `constexpr` 함수 |
| 전처리 결과 보기 | GCC `-E`, MSVC `/P` |

<summary>`SQUARE(i++)`를 매크로로 쓰면 왜 위험한가?</summary>

- `((i++) * (i++))`로 바뀌어 `i`가 두 번 증가하고, 결과도 기대와 다름(한 식에서 같은 변수를 두 번 바꾸는 정의되지 않은 동작)
