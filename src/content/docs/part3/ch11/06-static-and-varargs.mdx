## static의 여러 쓰임

- `static`은 쓰이는 곳마다 뜻이 다름. 새 키워드를 늘리지 않으려고 한 키워드에 여러 뜻을 실은 것
- 하나는 4편의 내부 링크. 나머지를 여기서 봄

### 정적 데이터 멤버와 정적 멤버 함수

- 9장에서 다룸. 요점만 다시
- **정적 데이터 멤버**: 객체마다 있지 않음. 클래스에 하나만 있고 어떤 객체에도 속하지 않음
- **정적 멤버 함수**: 객체가 아니라 클래스 수준. 특정 객체를 두고 실행되지 않으므로 숨은 `this` 포인터가 없음
  - 그래서 `const`를 붙일 수 없음

### 함수 안의 정적 변수

- 함수 안의 `static` 지역 변수: 범위를 나갔다 다시 들어와도 값이 남는 변수 <CppRef path="cpp/language/storage_duration" />
  - 그 함수 안에서만 쓸 수 있는 전역 변수와 비슷함
  - 처음 그 선언을 지날 때 한 번만 초기화됨
- 흔한 쓰임: 어떤 초기화를 이미 했는지 "기억하기"

```cpp
void runJob()
{
    static bool prepared{ false };
    if (!prepared) {
        std::println("준비 중");
        // 준비 작업
        prepared = true;
    }
    // 원래 할 일
}
```

- 하지만 정적 변수는 헷갈리기 쉽고, 보통 더 나은 구조가 있음. 위 예라면 생성자가 준비 작업을 하는 클래스를 만드는 편이 나음
- 쓸모 있는 경우도 있음. 예: 마이어스 싱글턴 (Meyers' singleton) 디자인 패턴(33장)

:::caution
홀로 떨어진 정적 변수는 피하고, 상태는 객체 안에 둔다.
:::

:::note
위 `runJob()`은 스레드에 안전하지 않다. 경쟁 상태(race condition)가 있다. 여러 스레드에서 쓰려면 아토믹이나 다른 동기화 수단이 필요하다(27장). 참고로 정적 지역 변수의 **초기화** 자체는 C++11부터 여러 스레드가 동시에 지나가도 한 번만 일어나도록 보장된다. 위 코드의 문제는 초기화 뒤에 `prepared`를 읽고 쓰는 부분이다.
:::

## 비지역 변수의 초기화 순서

- 프로그램의 전역 변수와 정적 변수(비지역 변수)는 모두 `main()`이 시작하기 전에 초기화됨 <CppRef path="cpp/language/initialization" />
- **한 소스 파일 안**에서는 나온 순서대로 초기화됨
  - 위 예제에서 `Station::s_created`가 `g_after`보다 먼저 초기화되는 것이 보장됨
- **서로 다른 소스 파일** 사이의 순서는 정해져 있지 않음
  - 한 파일의 전역 `x`와 다른 파일의 전역 `y` 중 어느 것이 먼저인지 알 방법이 없음
  - 보통은 상관없지만, 한 전역·정적 변수가 다른 것에 의존하면 문제가 됨
  - 객체의 초기화는 생성자 실행. 한 전역 객체의 생성자가 다른 파일의 전역 객체가 이미 만들어졌다고 가정하고 쓰면, 그 가정은 보장되지 않음
  - 순서는 컴파일러마다, 같은 컴파일러의 버전마다 다를 수 있고, 프로젝트에 파일 하나를 더하는 것만으로 바뀔 수도 있음

:::danger
서로 다른 소스 파일에 있는 비지역 변수의 초기화 순서는 정해져 있지 않다.
:::

- 흔한 우회책: 다른 파일의 전역 객체 대신, 함수 안의 정적 변수를 돌려주는 함수를 부름. 처음 부를 때 초기화되므로 "아직 안 만들어짐" 문제가 사라짐(위 마이어스 싱글턴이 이 방식)

## 비지역 변수의 소멸 순서

- 비지역 변수는 초기화된 순서의 **반대로** 소멸됨
- 다른 파일 사이의 초기화 순서가 정해져 있지 않으므로, 소멸 순서도 정해져 있지 않음

## C 스타일 가변 인자

- 기존 코드에서 **C 스타일 가변 인자 목록** (variadic arguments)을 만날 수 있음 <CppRef path="cpp/language/variadic_arguments" />
- 새 코드에서는 쓰지 말고, 타입에 안전한 **가변 인자 템플릿** (variadic template, 26장)을 씀
- 대표 예: `<cstdio>`의 `printf()`. 인수를 몇 개든 받음

```cpp
std::printf("정수 %d\n", 5);
std::printf("문자열 %s, 정수 %d\n", "hello", 5);
std::printf("%d %d %d %d\n", 1, 2, 3, 4);
```

### 직접 만들기

- 매개변수 목록 끝의 `...`(줄임표): 개수와 타입이 정해지지 않은 인수들
- 이름 있는 매개변수가 **적어도 하나** 있어야 함
- 인수에 접근하는 도구는 `<cstdarg>`의 매크로 <CppRef path="cpp/utility/variadic" />

| 도구 | 하는 일 |
| --- | --- |
| `va_list` | 인수 목록을 가리키는 변수의 타입 |
| `va_start(목록, 마지막이름)` | 목록을 초기화. 둘째 인수는 매개변수 목록의 **가장 오른쪽 이름 있는 매개변수** |
| `va_arg(목록, 타입)` | 다음 인수를 그 타입으로 해석해 꺼냄 |
| `va_end(목록)` | 접근을 끝냄. `va_start` 뒤에는 **반드시** 부름 |

- 이 도구들은 매크로라서 `import std;`로는 들어오지 않음. `#include <cstdarg>`가 따로 필요함(`stderr`, `stdout`도 `<cstdio>`의 매크로)
- 목록을 통째로 넘길 수도 있음: `vprintf()`, `vfprintf()` 같은 `v`로 시작하는 표준 함수가 `va_list`를 받음

- 볼 것
  - `logLine()`은 `vprintf()`에 목록을 그대로 넘겨 `printf()`처럼 동작함
  - `sumInts()`는 첫 인수로 받은 개수만큼 `va_arg()`로 꺼냄

### 끝을 알 방법이 없음

- `va_arg()`로 꺼낼 때, 목록이 어디서 끝나는지 알 방법이 없음. 끝을 알려 줄 약속이 따로 필요함
  - 첫 매개변수를 인수 개수로 함(위 `sumInts()`)
  - 포인터 목록이라면 마지막을 `nullptr`로 함
  - 어느 방법이든 쓰는 사람의 부담

### 쓰지 말아야 하는 이유

- **개수를 모름**
  - `sumInts()`는 호출하는 쪽이 첫 인수에 개수를 맞게 넣었다고 믿을 수밖에 없음
  - `logLine()`은 서식 문자열의 `%` 개수만큼 인수를 넣었다고 믿을 수밖에 없음
- **타입을 모름**
  - `va_arg()`는 받은 타입으로 그 자리의 값을 해석할 뿐, 맞는지 확인할 수 없음
  - 예: `sumInts(2, 1.5, 2.5)`처럼 `double`을 넘기면 `int`로 잘못 읽는 정의되지 않은 동작. 컴파일러는 막지 못함

:::caution
C 스타일 가변 인자는 피한다. 값들을 `std::array`나 `std::vector`로 넘기거나, 초기화 리스트(1장)를 쓰거나, 타입에 안전한 가변 인자 템플릿(26장)을 쓴다.
:::

## 헷갈리기 쉬운 점

- 함수 안의 `static` 변수는 부를 때마다 초기화된다?
  - 처음 그 선언을 지날 때 한 번만. 이후에는 이전 값을 이어 감
- 전역 변수는 파일 순서대로 초기화된다?
  - 한 파일 안에서만 나온 순서대로. 파일 사이의 순서는 정해져 있지 않음
- `va_arg()`가 인수의 타입을 확인해 준다?
  - 받은 타입으로 해석할 뿐. 틀리면 정의되지 않은 동작
- `import std;`만 하면 `va_start`를 쓸 수 있다?
  - 매크로는 모듈로 들어오지 않음. `#include <cstdarg>`

## 정리

| 요소 | 핵심 |
| --- | --- |
| 정적 데이터 멤버 | 클래스에 하나. 객체에 속하지 않음 |
| 정적 멤버 함수 | `this` 없음, `const` 불가 |
| 함수 안의 `static` 변수 | 한 번 초기화, 값이 남음. 되도록 객체 안의 상태로 |
| 비지역 변수 초기화 | `main()` 전. 파일 안에서는 순서대로, 파일 사이는 정해지지 않음 |
| 비지역 변수 소멸 | 초기화의 반대 순서 |
| C 스타일 가변 인자 | `...`, `va_list`, `va_start`, `va_arg`, `va_end`. 개수·타입을 모름 |
| 대안 | `std::array`, `std::vector`, 초기화 리스트, 가변 인자 템플릿 |
