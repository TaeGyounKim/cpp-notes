- 다루는 것: C++ 프로그래머가 가장 많이 쓰는 라이브러리인 **C++ 표준 라이브러리** (Standard Library)의 전체 모습
  - 표준의 일부라서 표준을 따르는 모든 컴파일러가 함께 제공함
  - 직접 만들고 디버깅하는 대신 표준 컨테이너와 알고리즘을 쓰면 시간과 노력을 크게 아낌
- 이 장(16장)은 무엇이 있는지 훑어보는 장. 컨테이너, 반복자, 알고리즘, 함수 객체, 정규식, 난수 등은 이어지는 장들에서 자세히 다룸
- 표준 라이브러리는 너무 커서 모든 멤버와 함수를 다루지는 못함. 전체 목록은 cppreference 같은 참고 자료를 봄 <CppRef path="cpp/standard_library" />

## C 헤더

- C 표준 라이브러리도 C++에 들어 있음
  - C의 `<stdio.h>` 같은 헤더는 C++에서 `<cstdio>`처럼 `c`를 붙이고 `.h`를 뺀 이름으로 씀
  - `<cxxx>` 판은 모든 것을 `std` 네임스페이스에 둠. `<xxx.h>` 판은 전역 네임스페이스에도 둘 수 있음
- C++에 없는 C 헤더
  - C11의 `<stdnoreturn.h>`, `<threads.h>`와 그 `<c...>` 판은 C++ 표준에 없음
  - C11의 `<stdatomic.h>`는 C++23부터 쓸 수 있지만 `<cstdatomic>`은 없음
- C++17에서 권장하지 않게 되고 C++20에서 제거된 C 헤더
  - `<ccomplex>`, `<ctgmath>`: `<complex>`나 `<cmath>`를 씀
  - `<ciso646>`, `<cstdalign>`, `<cstdbool>`: C++에서는 비어 있거나 키워드인 것을 매크로로 정의할 뿐이라 쓸모가 없었음
- C 헤더는 `import`할 수 있다는 보장이 없음. `#include`로 씀

:::tip
C 헤더가 주는 기능에 C++ 대응 기능이 있으면 C++ 쪽을 쓴다.
:::

## 코딩 원칙

- 표준 라이브러리는 **템플릿**과 **연산자 오버로딩**을 많이 씀
- 템플릿(12장): 제네릭 프로그래밍을 가능하게 함. 템플릿 코드를 쓰는 사람이 미처 몰랐던 객체에도 동작함
  - 템플릿을 쓰는 사람의 의무: 그 객체의 클래스에 필요한 요구 사항(비교 연산자, 복사 생성자 등)을 밝히고, 코드에서는 그 기능만 씀
  - 객체를 만드는 사람의 의무: 템플릿이 요구하는 연산자와 멤버 함수를 제공함
  - 템플릿을 직접 쓰지 않더라도 표준 라이브러리를 쓰려면 문법과 기능을 이해해야 함
- 연산자 오버로딩(9장, 15장): 이어지는 장들을 이해하는 데는 9장의 기초면 충분함

## 무엇이 있는가

- 설계 관점에서 구성 요소를 훑음. 코드 세부는 각 장에서

### 문자열과 서식

- `<string>`의 `std::string`: C 스타일 문자 배열보다 거의 모든 면에서 나음(2장)
  - 메모리 관리, 어느 정도의 범위 검사, 대입 의미, 비교, 이어 붙이기·부분 문자열·치환 같은 조작
  - 정확히는 `std::basic_string` 클래스 템플릿의 `char` 인스턴스에 대한 타입 별칭. 템플릿이 아닌 진짜 클래스처럼 써도 됨
- `<string_view>`의 `std::string_view`: 어떤 문자열 표현이든 읽기 전용으로 보는 뷰. `const std::string&` 대신 쓸 수 있으면서 부담이 없음. 문자열을 절대 복사하지 않음
- 유니코드와 지역 설정(`<locale>`): 숫자·날짜를 나라나 지역의 규칙에 맞게 서식화(21장)
- `<format>`의 `std::format()`: 타입에 안전하고 확장 가능한 서식 라이브러리. C++23의 `std::print()`, `std::println()`이 콘솔 출력을 쉽게 함

### 정규식, 스트림, 스마트 포인터, 예외

| 기능 | 헤더 | 장 |
| --- | --- | --- |
| 정규식: 문자열에서 패턴을 찾고 바꿈 | `<regex>` | 21장 |
| 입출력 스트림: 파일, 콘솔, 문자열, 고정 버퍼 | `<iostream>`, `<fstream>`, `<sstream>`, `<spanstream>` 등 | 13장 |
| 스마트 포인터 `unique_ptr`, `shared_ptr`, `weak_ptr` | `<memory>` | 7장 |
| 예외 클래스 계층 | `<exception>`, `<stdexcept>`, `<system_error>` | 14장 |

- 스마트 포인터가 막는 문제 셋
  - **메모리 누수**: 객체를 지우지 않아 공간이 쌓임
  - **허상 포인터** (dangling pointer): 다른 코드가 이미 지운(또는 다른 용도로 재할당된) 메모리를 계속 가리킴
  - **이중 해제** (double deletion): 같은 메모리를 두 번 해제함
  - 이런 오류는 대개 찾기도 고치기도 어려움

### 정수 타입과 수치

- `<cstdint>`: `std::int8_t`, `std::uint32_t`처럼 크기가 정해진 정수 타입(`intN_t`, `uintN_t`, N은 8·16·32·64)과 최솟값·최댓값 매크로(34장)
- 수학 함수(`<cmath>`, 일부 `<cstdlib>`): `abs()`, `remainder()`, `fma()`, `exp()`, `log()`, `pow()`, `sqrt()`, `sin()`, `atan2()`, `sinh()`, `erf()`, `tgamma()`, `ceil()`, `floor()` 등
  - 르장드르 다항식, 베타 함수, 타원 적분, 베셀 함수 같은 수학 특수 함수도 있음
  - `std::lerp(a, b, t)` <Badge text="C++20" />: 선형 보간·외삽. `a + t(b - a)`
  - C++23부터 상당수가 `constexpr`이라 컴파일할 때 계산할 수 있음
- `<numeric>`: `std::gcd()`(최대공약수), `std::lcm()`(최소공배수) <Badge text="C++17" />, `std::midpoint()`(두 값의 중점) <Badge text="C++20" />
- `<complex>`의 `std::complex`: 실수부와 허수부를 가진 복소수
- `<ratio>`의 `std::ratio`: 컴파일 시간 유리수 산술(22장)
- `<valarray>`의 `std::valarray`: 수치 계산에 최적화된 `vector` 비슷한 것. 행렬 클래스는 표준에 없음(이 사이트에서는 더 다루지 않음)
- `<numbers>`의 수학 상수 <Badge text="C++20" />, `std::numbers` 네임스페이스

| 상수 | 뜻 | 근삿값 |
| --- | --- | --- |
| `pi` | 원주율 | 3.141592653589793 |
| `inv_pi` | 원주율의 역수 | 0.3183098861837907 |
| `sqrt2` | 2의 제곱근 | 1.4142135623730951 |
| `e` | 자연로그의 밑 | 2.718281828459045 |
| `phi` | 황금비 | 1.618033988749895 |

### 정수 비교

- `<utility>`의 `std::cmp_equal()`, `cmp_not_equal()`, `cmp_less()`, `cmp_less_equal()`, `cmp_greater()`, `cmp_greater_equal()` <Badge text="C++20" /> <CppRef path="cpp/utility/intcmp" />
  - 부호 있는 정수와 부호 없는 정수를 섞어 비교해도 안전함
- `-1 > 0u`는 **참**. `-1`이 먼저 부호 없는 정수로 바뀌어 4294967295 같은 큰 수가 되기 때문. GCC는 부호가 다른 정수 비교라고 경고함
- `std::cmp_greater(-1, 0u)`는 바르게 거짓

### 비트 다루기

- `<bit>` <Badge text="C++20" />. 모두 첫 인수로 **부호 없는** 정수 타입을 받음 <CppRef path="cpp/header/bit" />

| 함수 | 하는 일 |
| --- | --- |
| `has_single_bit()` | 비트가 하나만 켜져 있는지(2의 거듭제곱인지) |
| `bit_ceil()` / `bit_floor()` | 주어진 값 이상의 가장 작은 / 이하의 가장 큰 2의 거듭제곱 |
| `bit_width()` | 값을 저장하는 데 필요한 비트 수 |
| `rotl()` / `rotr()` | 비트를 왼쪽 / 오른쪽으로 회전 |
| `countl_zero()`, `countl_one()` | 왼쪽(최상위 비트)부터 연속한 0 / 1 비트 수 |
| `countr_zero()`, `countr_one()` | 오른쪽(최하위 비트)부터 연속한 0 / 1 비트 수 |
| `popcount()` | 켜진(1) 비트 수 |
| `byteswap()` <Badge text="C++23" /> | 정수의 바이트 순서를 뒤집음 |

| 난수: 엔진, 엔진 어댑터, 분포 <Badge text="C++11" /> | `<random>` | 23장 |
| 초기화 리스트 | `<initializer_list>` | 1장 |
| `pair`(두 값), `tuple`(정해진 개수의 값) | `<utility>`, `<tuple>` | 1장, 24장 |
| 어휘 타입 `optional`, `variant`, `any`, `expected` <Badge text="C++23" /> | 각 이름의 헤더 | 24장 |
| 함수 객체와 그것을 만드는 도구 | `<functional>` | 19장 |
| 파일 시스템 | `<filesystem>` | 13장 |
| 멀티스레딩: `thread`, `jthread`, 아토믹, 뮤텍스, 조건 변수, 세마포어, 래치, 배리어, `async`/`future` | `<thread>`, `<atomic>`, `<mutex>` 등 | 27장 |
| 타입 특성: 컴파일할 때 타입 정보 | `<type_traits>` | 26장 |
| 소스 위치 | `<source_location>` | 14장 |

- `rand()`/`srand()`는 오래전부터 있었지만 품질이 낮고 분포를 바꿀 수 없음. `<random>`을 씀
- **어휘 타입** (vocabulary type): `int`, `double`처럼 늘 쓰게 되는 타입. 코드를 더 안전하고 효율적이고 읽기 쉽게 함. `vector`, `optional`, `string`, `unique_ptr`, `shared_ptr` 등
  - 표준 컨테이너는 모든 원소가 같은 타입(**동질** 원소). `pair`와 `tuple`은 서로 다른 타입의 값(**이질** 원소)을 담음
  - `expected` <Badge text="C++23" />: 원하는 값 또는 (다를 수 있는 타입의) 오류 값을 담음. 함수가 결과나 실패 이유를 돌려줄 때 유용함

## 표준 라이브러리 기능 검사 매크로

- 11장의 언어 기능 검사 매크로처럼, 표준 라이브러리 구현이 어떤 기능을 지원하는지 알아내는 매크로 <CppRef path="cpp/utility/feature_test" />
  - 모두 `__cpp_lib_`로 시작. 예: `__cpp_lib_concepts`, `__cpp_lib_ranges`, `__cpp_lib_filesystem`, `__cpp_lib_constexpr_vector`
  - 값은 기능이 들어오거나 바뀐 연월(YYYYMM). 예: `__cpp_lib_filesystem`은 201703(2017년 3월)
- 언어 기능 검사 매크로와 다른 점: `<version>`에 정의됨. 헤더를 포함해야 함
  - 매크로는 모듈로 내보내지지 않으므로 `import std;`로는 들어오지 않음(11장). `#include <version>` 또는 `import <version>;`
- `<version>`은 그 밖에 구현마다 다른 정보(버전 번호, 출시일, 저작권 표시 등)를 줄 수 있음

:::note
여러 플랫폼·여러 컴파일러용 코드가 아니라면 기능 검사 매크로는 거의 필요 없다. 그런 코드라면 표준 라이브러리 구현이 기능을 지원하지 않을 때 대신할 코드를 넣는 데 쓴다(34장).
:::

## 헷갈리기 쉬운 점

- `-1 < 0u`는 당연히 참이다?
  - 부호 없는 쪽으로 바뀌어 거짓. `std::cmp_less(-1, 0u)`는 참
- `<bit>` 함수에 `int`를 넘겨도 된다?
  - 부호 없는 정수 타입만
- `import std;`만 하면 `__cpp_lib_...` 매크로를 쓸 수 있다?
  - 매크로는 모듈로 들어오지 않음. `<version>`을 포함
- `<stdio.h>`와 `<cstdio>`는 같다?
  - 기능은 같지만 `<cstdio>`는 `std`에 두는 것이 보장됨. C++에서는 `<cxxx>`를 씀

## 정리

| 요소 | 핵심 |
| --- | --- |
| 원칙 | 템플릿과 연산자 오버로딩을 많이 씀 |
| C 헤더 | `<cxxx>` 판. C++ 대응 기능이 있으면 그쪽 |
| 문자열 | `string`, `string_view`, `format`, `print` |
| 수치 | `<cmath>`, `<numeric>`(`gcd`, `lcm`, `midpoint`), `<numbers>`, `<complex>` |
| 정수 비교 | `cmp_less` 등. 부호가 섞여도 안전 |
| 비트 | `<bit>`: `popcount`, `rotl`, `bit_ceil`, `byteswap`(C++23) 등 |
| 어휘 타입 | `optional`, `variant`, `any`, `tuple`, `expected`(C++23) |
| 기능 검사 | `__cpp_lib_...`, `<version>` |
