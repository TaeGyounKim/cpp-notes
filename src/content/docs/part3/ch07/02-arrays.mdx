## 기본 타입의 배열

- **배열** (array): 같은 타입의 변수 여러 개를 번호(인덱스)로 묶은 것 <CppRef path="cpp/language/array" />
- 메모리에서도 머릿속 그림과 거의 같음: 원소 하나 크기의 칸이 **이어진** 메모리에 나란히 놓임

### 스택의 배열

```cpp
int a[5];                 // 원소는 초기화되지 않음. 값을 알 수 없음
int b[5]{ 1, 2, 3, 4, 5 };
int c[5]{ 1, 2 };         // 나머지는 0: 1, 2, 0, 0, 0
int d[5]{};               // 모두 0
int e[]{ 1, 2, 3 };       // 크기를 초기화 목록에서 정함: 3
```

- 스택에 만드는 배열의 크기는 **컴파일할 때 정해진 상수**여야 함
- 일부 컴파일러는 실행할 때 정한 크기의 배열을 스택에 만드는 것을 허락함(**가변 길이 배열**, VLA). C++ 표준이 아님. GCC도 `-pedantic`을 주면 "ISO C++ forbids variable length array"라고 경고함. 보이면 조심스럽게 물러설 것

### 자유 저장소의 배열

- 포인터로 그 위치를 가리킨다는 것만 다름

```cpp
int* ptr{ new int[5] };                  // 초기화되지 않은 int 다섯 개
int* filled{ new int[5]{ 1, 2, 3 } };    // 나머지는 0
int* deduced{ new int[]{ 1, 2, 3 } };    // 크기 생략 (C++20)
```

- `ptr`은 배열의 0번 원소를 가리킴
- `new[]`도 `std::nothrow`를 받아 실패 시 `nullptr`을 돌려주게 할 수 있음
- 장점: 크기를 **실행할 때** 정할 수 있음
- `new[]`로 잡은 것은 반드시 `delete[]`로 돌려줌. 빈 대괄호 `[]`에 주의 <CppRef path="cpp/language/delete" />

### 동적으로 잡은 배열은 동적 배열이 아님

- 자유 저장소에 잡은 배열의 문제
  - 크기를 모름. 이 배열을 돌려받은 쪽은 원소가 몇 개인지 알 수 없음. 크기를 따로 전해야 함
  - 돌려받은 쪽이 `delete[]`를 잊지 않아야 함
- 혼동 주의
  - **동적으로 잡은 배열**: 크기를 실행할 때 정해서 자유 저장소에 잡은 배열. 한번 잡으면 크기가 바뀌지 않음
  - **동적 배열**: 데이터에 맞춰 크기가 스스로 늘고 줄며 자기 크기를 아는 자료 구조. 예: `std::vector`
- C의 `realloc()`: 새 크기의 메모리를 잡고, 옛 데이터를 **비트 단위로 복사**하고, 옛 메모리를 지워 크기를 바꾸는 함수
  - C++에서는 절대 쓰지 말 것. 사용자 정의 객체는 비트 단위 복사를 견디지 못함(생성자와 소멸자를 거치지 않으므로)

## 객체의 배열

- 기본 타입의 배열과 다른 점은 원소가 초기화되는 방식뿐
  - `new T[N]`: N개의 객체가 들어갈 이어진 메모리를 잡고, 원소마다 **기본 생성자**(인수 없는 생성자)를 부름
  - 기본 타입의 배열은 기본으로 초기화되지 않지만, 객체의 배열은 완전히 만들어진 객체들의 배열이 됨

### 배열 지우기

- `new[]`로 잡은 것은 `delete[]`로. 원소마다 소멸자를 부르고 메모리를 돌려줌
- `delete[]` 대신 `delete`를 쓰면 이상하게 동작함(정의되지 않은 동작)
  - 어떤 컴파일러에서는 첫 원소의 소멸자만 불리고 나머지는 버려짐
  - 다른 컴파일러에서는 메모리가 망가짐. `new`와 `new[]`가 완전히 다른 할당 방식을 쓸 수 있기 때문
  - GCC는 짝이 맞지 않는 경우를 잡아 경고함: "called on pointer returned from a mismatched allocation function"

:::caution
`new`로 잡은 것은 언제나 `delete`로, `new[]`로 잡은 것은 언제나 `delete[]`로 돌려준다.
:::

### 포인터의 배열

- 원소가 객체가 아니라 **포인터**라면, `delete[]`는 포인터들만 지우고 그것들이 가리키는 객체는 지우지 않음
- 객체를 하나씩 `new`로 만들었다면 하나씩 `delete`해야 함

- 볼 것
  - 객체의 배열: 생성자가 세 번, 소멸자가 세 번. 소멸은 생성의 **반대 순서**(3, 2, 1)
  - 포인터의 배열: `new Seat*[size]`는 포인터만 잡음. 객체는 반복문에서 하나씩 만들고, 하나씩 지운 뒤, 마지막에 포인터 배열을 지움

:::

## 다차원 배열

- 여러 번호로 원소를 찾는 배열. 예: 3×3 틱택토 판

```cpp
char board[3][3]{};
board[0][0] = 'X';
board[2][1] = 'O';
```

- 첫 번호가 가로인지 세로인지는 중요하지 않음. 일관되게만 쓰면 됨

### 스택의 다차원 배열

- 메모리에는 축이 둘이 아님. 주소는 한 줄로 이어질 뿐
- 그래서 컴퓨터는 2차원 배열을 **1차원 배열처럼** 놓음. 다른 것은 크기와 접근 방법
  - 크기: 모든 차원을 곱하고 원소 하나의 크기를 곱함. 3×3 `char` 판은 3 × 3 × 1 = 9바이트
  - 접근: `board[0]`은 0번 행 전체(부분 배열), `board[0][2]`는 그 부분 배열의 2번 원소
- 4차원 이상도 같은 원리지만 머릿속에 그리기 어렵고 거의 쓰지 않음

### 자유 저장소의 다차원 배열

- 차원을 실행할 때 정해야 하면 자유 저장소에 잡음. 1차원처럼 포인터로 다룸
  - 2차원이면 포인터의 포인터, N차원이면 N단계의 포인터
- 다음처럼 쓰고 싶지만 컴파일되지 않음

```cpp
char** board{ new char[rows][columns] };   // 오류
```

- GCC: "array size in new-expression must be constant". 자유 저장소의 다차원 배열은 스택의 것처럼 동작하지 않음
- 실제 방법: 첫째 차원으로 **포인터 배열**을 잡고, 각 포인터가 가리킬 **행을 하나씩** 따로 잡음. 컴파일러는 행을 대신 잡아 주지 않음
- 돌려줄 때도 `delete[]`가 행까지 지워 주지 않음. 잡은 코드를 거울처럼 뒤집어서 씀

### 결론: 표준 컨테이너를 쓸 것

- C 스타일 배열은 메모리 안전성을 전혀 제공하지 않음. 기존 코드에서 만나기 때문에 배울 뿐
- 새 코드에서는

| 필요한 것 | 쓸 것 |
| --- | --- |
| 크기가 고정된 배열 | `std::array` |
| 1차원 동적 배열 | `std::vector<T>` |
| 2차원 동적 배열 | `std::vector<std::vector<T>>`. 또는 방법 2를 감싼 `Matrix<T>` 같은 클래스 템플릿 |

- 2차원 데이터를 자주 다룬다면, 메모리 할당과 원소 접근을 숨기는 쉬운 인터페이스의 클래스를 만들거나 재사용할 것(6장의 재사용). 클래스 템플릿을 쓰는 법은 12장

:::caution
C 스타일 배열 대신 `std::array`, `std::vector` 같은 C++ 표준 라이브러리 컨테이너를 쓴다.
:::

## 헷갈리기 쉬운 점

- `delete`와 `delete[]`는 아무거나 써도 된다?
  - `new`에는 `delete`, `new[]`에는 `delete[]`. 섞으면 정의되지 않은 동작
- `delete[]`는 포인터 배열이 가리키는 객체까지 지운다?
  - 배열의 원소(포인터)만 지움. 포인터가 가리키는 객체는 따로 `delete`해야 함
- 자유 저장소에 잡은 배열은 크기를 바꿀 수 있다?
  - "동적으로 잡은" 것일 뿐 크기는 고정. 크기가 바뀌는 것은 `std::vector`
- 자유 저장소의 2차원 배열도 스택처럼 한 줄로 이어져 있다?
  - 행마다 따로 잡으면 흩어짐. 이어진 메모리가 필요하면 한 덩어리로 잡고 번호를 계산함
- `int a[5];`는 0으로 채워진다?
  - 지역 변수라면 초기화되지 않음. `int a[5]{};`처럼 중괄호를 붙여야 0

## 정리

| 요소 | 핵심 |
| --- | --- |
| 스택의 배열 | 크기는 컴파일할 때 상수. `{}`로 0 초기화 |
| 자유 저장소의 배열 | `new T[n]`으로 실행할 때 크기를 정함. `delete[]`로 돌려줌 |
| 객체의 배열 | 원소마다 기본 생성자와 소멸자. 소멸은 반대 순서 |
| 포인터의 배열 | 객체는 하나씩 `delete`, 배열은 마지막에 `delete[]` |
| 스택의 다차원 배열 | 한 줄로 이어진 메모리 |
| 자유 저장소의 다차원 배열 | 포인터 배열 + 행마다 따로. 해제는 거꾸로 |
| 권장 | `std::array`, `std::vector`. C 스타일 배열과 `realloc`은 쓰지 않음 |
