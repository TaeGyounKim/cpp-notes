## 원본과 대상

- 바꾸는 알고리즘 중 일부는 **원본 범위**와 **대상 범위**를 씀. 원본에서 읽어 대상에 씀. 예: `copy()`
- 다른 일부는 **제자리에서** 일함. 범위 하나만 필요함. 예: `generate()`

:::caution
바꾸는 알고리즘은 대상에 원소를 **넣지** 못한다. 대상에 이미 있는 원소를 덮어쓰거나 고칠 뿐이다. 그래서 대상은 미리 충분히 커야 한다. 정말 넣으려면 17장의 삽입 반복자(`std::back_inserter` 등)를 쓴다.
:::

:::note
`map`과 `multimap`의 범위는 바꾸는 알고리즘의 대상이 될 수 없다. 원소(키-값 쌍) 전체를 덮어써야 하는데 키가 `const`라 대입할 수 없기 때문이다. `set`, `multiset`도 마찬가지다. 대신 삽입 반복자를 쓴다.
:::

- 바꾸는 알고리즘의 전체 목록은 16장 3편. 여기서는 일부를 예제로

## generate

- `std::generate(first, last, gen)`: 범위의 값을 콜백이 돌려준 값으로 바꿈 <CppRef path="cpp/algorithm/generate" />

```cpp
std::vector<int> v(6);
int seed{ 1 };
std::generate(v.begin(), v.end(), [&seed] { return seed *= 2; });   // 2, 4, 8, ...
```

- 1편에서 말한 대로 `generate`는 상태 있는 콜백을 받을 수 있음. 여기서는 바깥 변수를 참조로 캡처해 상태를 둠

## transform

- 오버로드가 여럿 <CppRef path="cpp/algorithm/transform" />
- 하나: 범위의 각 원소에 콜백을 적용해 나온 새 원소를 대상 범위에 저장함
  - 매개변수: 원본의 시작·끝, 대상의 시작, 콜백
  - 원본과 대상이 같으면 **제자리**에서 바꿈

```cpp
std::transform(v.begin(), v.end(), v.begin(), [](int i) { return i + 100; });
```

- 다른 하나: 두 범위의 같은 위치 원소 쌍에 이항 함수를 적용함
  - 매개변수: 첫 범위의 시작·끝, 두 번째 범위의 시작, 대상의 시작, 콜백
  - 두 번째 범위는 첫 범위보다 짧으면 안 됨

```cpp
std::transform(a.cbegin(), a.cend(), b.cbegin(), a.begin(),
               [](int x, int y) { return x + y; });   // a[i] += b[i]
```

- `transform()`을 비롯한 바꾸는 알고리즘은 대상 범위의 끝 다음 위치를 가리키는 반복자를 돌려주는 경우가 많음

## copy 계열

- `std::copy(first, last, dest)`: 첫 원소부터 마지막 원소까지 다른 범위로 복사함 <CppRef path="cpp/algorithm/copy" />
  - 원본과 대상은 달라야 하지만, 제한적으로 겹칠 수 있음: `copy(b, e, d)`에서 `d`가 `b`보다 앞이면 괜찮고, `d`가 `[b, e)` 안이면 정의되지 않은 동작
  - 대상에 넣지 않고 덮어씀. `vector`라면 `resize()`로 미리 크기를 맞추거나 삽입 반복자를 씀
- `copy_backward(first, last, destEnd)`: 원본의 마지막 원소부터 대상의 마지막 위치로 거꾸로 복사함
  - 세 번째 인수는 대상의 **끝**(`end(dst)`)
  - `copy_backward(b, e, d)`에서 `d`가 `e`보다 뒤면 겹쳐도 괜찮고, `d`가 `(b, e]` 안이면 정의되지 않은 동작
- `copy_if(first, last, dest, pred)`: 조건자를 만족하는 원소만 복사함
  - 대상에 복사한 마지막 원소의 다음 위치를 돌려줌. 이것으로 대상의 남는 자리를 지움

```cpp
std::vector<int> high(src.size());
auto copiedEnd{ std::copy_if(src.cbegin(), src.cend(), high.begin(),
                             [](int r) { return r >= 7; }) };
high.erase(copiedEnd, high.end());
```

- `copy_n(first, n, dest)`: 원본에서 n개를 복사함
  - **범위 검사를 하지 않음**. 시작 반복자 + n이 원본의 끝을 넘지 않게 직접 확인해야 함(`std::min(n, src.size())` 등)

## move

- `std::move(first, last, dest)`, `std::move_backward(first, last, destEnd)`: 이동 의미론(9장)으로 원소를 옮김 <CppRef path="cpp/algorithm/move" />
  - 직접 만든 원소 클래스에는 이동 대입 연산자가 있어야 함
  - 원본과 대상의 겹침 규칙은 `copy()`, `copy_backward()`와 같음
- `std::move`가 둘: 인수 하나짜리(`<utility>`)는 좌측값을 우측값으로 바꾸고, 인수 셋짜리(`<algorithm>`)는 원소들을 옮기는 알고리즘

:::note
이동 연산의 원본 객체는 유효하지만 정해지지 않은 상태가 된다(9장). 이동한 뒤의 원본 원소는 `setString()`처럼 전제 조건이 없는 멤버 함수로 상태를 정하기 전에는 쓰지 않는다.
:::

## replace

- `replace(first, last, old, new)`, `replace_if(first, last, pred, new)`: 값이 같거나 조건자가 참인 원소를 새 값으로 바꿈 <CppRef path="cpp/algorithm/replace" />

```cpp
std::replace_if(v.begin(), v.end(),
                [](int r) { return r > 15; }, 15);   // 상한 15
```

- `replace_copy()`, `replace_copy_if()`: 결과를 다른 대상 범위에 복사함. `copy()`처럼 대상이 충분히 커야 함

## 지우기

### std::erase와 std::erase_if

- <Badge text="C++20" /> 18장에서 본 `std::erase()`, `std::erase_if()`: 거의 모든 표준 컨테이너를 지원함. 정식 이름은 **균일한 컨테이너 지우기** (uniform container erasure)
  - 반복자 범위가 아니라 **컨테이너의 참조**를 받음
  - 컨테이너에서 원소를 지우는 가장 좋은 방법

```cpp
std::erase_if(notes, [](const std::string& s) { return s.empty(); });
```

:::note
`std::erase()`는 정렬된·정렬되지 않은 연관 컨테이너에는 쓰지 않는다. 그 컨테이너들에는 훨씬 빠른 멤버 `erase(key)`가 있다. `std::erase_if()`는 모든 컨테이너에 된다.
:::

### C++20 이전: 지우기-제거 관용구

- 오래된 코드에서 볼 수 있으므로 알아 둠
- 처음 떠오르는 방법: 원소를 훑으며 조건에 맞으면 멤버 `erase()`
  - `vector`에서는 매우 비효율적. 연속 메모리를 유지하려고 매번 원소를 옮겨 **이차** 시간(원소 수의 제곱에 비례)
  - 실수하기 쉬움. `erase()` 뒤 반복자를 다시 얻어야 함(`it = v.erase(it)`)
- 선형 시간인 **지우기-제거 관용구** (remove-erase idiom)를 씀
- `remove()`, `remove_if()` 알고리즘은 반복자만 다루고 컨테이너에는 접근하지 못하므로 원소를 **실제로 지울 수 없음** <CppRef path="cpp/algorithm/remove" />
  - 대신 지울 원소 자리를 지우지 않을 다음 원소로 (이동 대입으로) 채움. 남길 원소가 모두 범위 앞쪽으로 모임
  - 범위가 남길 원소들과 지울 원소들로 나뉘고, 지울 원소들의 첫 위치를 돌려줌
  - 그 뒤쪽 원소는 옮겨졌을 수 있으니 쓰지 않음. 할 일은 그 범위를 컨테이너에서 지우는 것뿐

<StepViz client:load data={reViz} />

```cpp
auto it{ std::remove_if(v.begin(), v.end(),
                        [](const std::string& s) { return s.empty(); }) };
v.erase(it, v.end());
```

:::caution
지우기-제거 관용구에서 `erase()`의 두 번째 인수 `v.end()`를 빼먹지 않는다. 빼먹으면 첫 인수가 가리키는 원소 **하나만** 지워진다.
:::

- `remove_copy()`, `remove_copy_if()`: 원본을 바꾸지 않고 남길 원소를 다른 대상 범위에 복사함
- `remove()` 계열은 **안정적**: 남는 원소의 순서를 지킴

:::tip
지우기-제거 관용구보다 `std::erase_if()`, `std::erase()`(연관 컨테이너는 멤버 `erase(key)`)를 쓴다. 손으로 짠 반복문은 더더욱 피한다.
:::

## 헷갈리기 쉬운 점

- 빈 `vector`를 대상으로 `std::copy`하면 알아서 늘어난다?
  - 덮어쓸 뿐이라 범위를 넘어 씀(정의되지 않은 동작). `resize()`나 `back_inserter`
- `std::remove`를 부르면 크기가 준다?
  - 크기는 그대로. 남길 원소를 앞으로 모으기만 함. `erase`까지 해야 함
- `v.erase(std::remove(...))`처럼 인수 하나로 충분하다?
  - 원소 하나만 지워짐. `v.end()`까지 넘김
- `copy_n`은 원본이 짧으면 알아서 멈춘다?
  - 범위 검사가 없음. n을 직접 제한
- `set`을 `std::transform`의 대상으로 쓸 수 있다?
  - 원소가 `const`라 안 됨. `std::inserter`(17장)

## 정리

| 알고리즘 | 핵심 |
| --- | --- |
| `generate` | 콜백이 만든 값으로 채움 |
| `transform` | 원소마다(또는 두 범위 짝마다) 콜백 결과를 대상에. 제자리 가능 |
| `copy`, `copy_backward`, `copy_if`, `copy_n` | 대상은 미리 충분히 크게. 겹침 규칙. `copy_if`는 끝을 돌려줌 |
| `move`, `move_backward` | 이동 대입으로 옮김. 원본은 쓰지 않음 |
| `replace`, `replace_if`, `..._copy` | 값/조건으로 바꿈 |
| `std::erase`, `std::erase_if` | C++20. 컨테이너를 받아 실제로 지움 |
| 지우기-제거 관용구 | `v.erase(std::remove_if(...), v.end())`. 선형 시간 |

<summary>다음 코드의 문제는? `v.erase(std::remove(v.begin(), v.end(), 0));`</summary>
