- 다루는 것: 순서와 관련된 알고리즘. 나누고, 정렬하고, 정렬된 범위에서 빠르게 찾고, 집합처럼 다루고, 가장 작거나 큰 것을 고름
- 이 글에서 배우는 요소: 분할, 정렬, `nth_element`, 이진 탐색, 집합 알고리즘, `merge`, 최소·최대, `clamp`

## 분할

- `partition_copy(first, last, destTrue, destFalse, pred)`: 원소를 조건자 결과에 따라 **두 대상**에 나눠 복사함 <CppRef path="cpp/algorithm/partition_copy" />
  - 두 대상 각각에서 마지막으로 복사한 원소의 다음 위치를 반복자 `pair`로 돌려줌
  - 3편의 `copy_if()`처럼 이 반복자로 대상의 남는 자리를 `erase()`함(또는 삽입 반복자를 씀)

```cpp
auto [passEnd, failEnd]{ std::partition_copy(
    scores.cbegin(), scores.cend(), pass.begin(), fail.begin(),
    [](int s) { return s >= 70; }) };
pass.erase(passEnd, pass.end());
fail.erase(failEnd, fail.end());
```

- `partition(first, last, pred)`: 조건자가 참인 원소를 모두 거짓인 원소 앞에 오게 다시 놓음 <CppRef path="cpp/algorithm/partition" />
  - 각 부분 안의 원래 순서는 **지키지 않음**(지키려면 `stable_partition()`)
  - 두 번째 부분의 첫 위치(분할점)를 돌려줌
- 그 밖의 분할 알고리즘(`is_partitioned`, `partition_point` 등)은 16장 3편

## 정렬

- 정렬 알고리즘: 컨테이너의 내용을 이웃한 원소끼리 순서가 유지되게 다시 놓음. 그래서 **순차** 컬렉션에만 해당함
  - 정렬된 연관 컨테이너는 이미 정렬되어 있고, 정렬되지 않은 연관 컨테이너에는 순서 개념이 없음
  - `list`, `forward_list`는 일반 정렬보다 효율적인 멤버 `sort()`를 가짐(18장)
  - 그래서 일반 정렬 알고리즘은 `vector`, `deque`, `array`, C 스타일 배열에 가장 유용함
- `std::sort(first, last)`: 보통 O(N log N) 시간에 정렬함 <CppRef path="cpp/algorithm/sort" />
  - 결과는 `operator<` 기준 **감소하지 않는** 순서(작은 것부터)
  - 다른 순서는 비교자로: `std::sort(v.begin(), v.end(), std::greater<>{});`
- `stable_sort()`: 같은 원소들의 상대 순서를 지킴. `sort()`보다 덜 효율적
- `is_sorted()`: 정렬되었는지. `is_sorted_until()`: 그 앞까지 정렬된 위치를 돌려줌

### nth_element

- 강력한 **선택** 알고리즘 <CppRef path="cpp/algorithm/nth_element" />
  - 범위와 그 안의 n번째 위치 반복자를 받아, 전체를 정렬했을 때 n번째에 올 원소를 그 자리에 놓음
  - 그 앞의 원소들은 모두 n번째보다 작고(크지 않고), 뒤의 원소들은 모두 크게(작지 않게) 다시 놓음
  - 이 모든 일을 **선형 시간** O(n)에 함. 전체를 정렬하면 O(n log n)

```cpp
// 세 번째로 큰 값
std::nth_element(v.begin(), v.begin() + 2, v.end(), std::greater<>{});
int third{ v[2] };
// 가장 큰 다섯을 정렬된 순서로: 나눈 뒤 앞부분만 정렬
std::nth_element(v.begin(), v.begin() + 4, v.end(), std::greater<>{});
std::sort(v.begin(), v.begin() + 5, std::greater<>{});
```

- `partial_sort()`로도 앞부분만 정렬할 수 있음(16장 3편)

## 이진 탐색

- 정렬된(적어도 찾는 원소에 대해 분할된) 범위에서만 동작하는 탐색: `binary_search()`, `lower_bound()`, `upper_bound()`, `equal_range()`
  - `map`, `set` 같은 연관 컨테이너에는 같은 일을 하는 멤버 함수가 있으니 그것을 씀(18장)
- `lower_bound(first, last, value)`: 정렬된 범위에서 값보다 **작지 않은**(같거나 큰) 첫 원소 <CppRef path="cpp/algorithm/lower_bound" />
  - 정렬을 유지하며 새 값을 넣을 위치를 찾을 때 흔히 씀

```cpp
auto pos{ std::lower_bound(sorted.begin(), sorted.end(), 80) };
sorted.insert(pos, 80);   // 여전히 정렬됨
```

- `binary_search(first, last, value)`: 값이 있으면 `true`. 선형이 아니라 **로그** 시간 <CppRef path="cpp/algorithm/binary_search" />
  - 범위의 가운데 원소와 먼저 비교하고, 찾는 값이 더 작으면 왼쪽 절반, 크면 오른쪽 절반의 가운데와 비교함. 매번 범위가 절반으로 줄어 로그 시간

## 집합 알고리즘

- **정렬된** 범위라면 어떤 것에든 씀 <CppRef path="cpp/algorithm/set_union" />
- `includes()`: 한 정렬된 범위의 모든 원소가 다른 정렬된 범위에 들어 있는지(부분집합)

| 알고리즘 | 결과 | 결과의 최대 크기 |
| --- | --- | --- |
| `set_union()` | 합집합: 어느 한쪽에라도 있는 원소 | 두 크기의 합 |
| `set_intersection()` | 교집합: 양쪽 모두에 있는 원소 | 작은 쪽의 크기 |
| `set_difference()` | 차집합: 첫째에는 있고 둘째에는 없는 원소 | 첫째의 크기 |
| `set_symmetric_difference()` | 대칭차집합(배타적 OR): 한쪽에만 있는 원소 | 두 크기의 합 |

- 모두 결과의 끝 다음 위치를 돌려줌. `std::ranges::subrange(begin, end)`로 반복자 쌍을 범위로 바꿔 바로 출력할 수 있음(17장)

:::caution
결과 범위가 결과를 담을 만큼 충분히 큰지 확인한다(위 표의 최대 크기). 또는 `std::back_inserter`를 쓴다. 연관 컨테이너(`set` 포함)의 공통 범위는 키를 바꿀 수 없으므로 결과 저장에 쓸 수 없다. `std::inserter`를 쓴다.
:::

### merge

- `std::merge()`: 두 정렬된 범위를 정렬 순서를 유지하며 합침. 결과는 두 원본의 모든 원소를 담은 정렬된 범위. **선형** 시간 <CppRef path="cpp/algorithm/merge" />
  - 매개변수: 첫 범위의 시작·끝, 둘째 범위의 시작·끝, 대상의 시작, (선택) 비교자
  - 두 범위를 이어 붙이고 `sort()`해도 같은 결과지만 O(N log N)으로 덜 효율적
  - 중복은 그대로 둠(합집합과 다름)

:::caution
병합 결과를 담을 대상이 충분히 큰지 늘 확인한다.
:::

## 최소와 최대

- `min()`, `max()`: 둘 이상의 값을 `operator<`나 비교자로 비교해 가장 작은 / 큰 것의 `const` 참조를 돌려줌 <CppRef path="cpp/algorithm/max" />
  - 셋 이상은 초기화 리스트로: `std::max({ 3, 9, 4 })`
- `minmax()`: 최솟값과 최댓값을 `pair`로. 구조적 바인딩으로 받으면 편함
  - 이 셋은 반복자 범위가 아니라 **값**들을 받음
- `min_element()`, `max_element()`, `minmax_element()`: 반복자 범위를 받아 가장 작은·큰 원소의 **반복자**(또는 그 `pair`)를 돌려줌

```cpp
auto [lo, hi]{ std::minmax_element(v.cbegin(), v.cend()) };
std::println("{} ~ {}", *lo, *hi);
```

:::caution
표준이 아닌 최소·최대 **매크로**를 만날 수 있다(예: glibc의 `MIN()`, `MAX()`, `Windows.h`의 `min()`, `max()`). 매크로는 인수를 두 번 평가할 수 있지만 `std::min()`, `std::max()`는 한 번만 평가한다. 늘 C++ 판을 쓴다.
:::

- 그런 매크로가 `std::min()`, `std::max()`를 방해할 때의 해결책
  - 문제 헤더를 포함한 뒤 `#undef min`, `#undef max`
  - `Windows.h`를 포함하기 전에 `#define NOMINMAX`
  - 괄호를 한 겹 더: `(std::max)(1, 2)`. 함수형 매크로는 이름 바로 뒤에 `(`가 와야 펼쳐지므로 피해 감

### clamp

- `std::clamp(v, lo, hi)` <Badge text="C++17" />: 값이 최솟값과 최댓값 사이에 있게 함. `<algorithm>` <CppRef path="cpp/algorithm/clamp" />
  - `v < lo`면 `lo`, `v > hi`면 `hi`, 아니면 `v`의 참조
  - `std::clamp(-3, 1, 10)`은 1, `std::clamp(3, 1, 10)`은 3, `std::clamp(22, 1, 10)`은 10

- 볼 것
  - `partition_copy`로 합격·불합격 나누기, `partition`은 각 부분의 순서를 섞을 수 있음
  - `nth_element`로 세 번째로 큰 점수, 그 앞부분만 정렬해 상위 셋
  - `lower_bound`로 찾은 자리에 80을 넣어도 정렬 유지
  - 이틀 다 출석(교집합)과 하루만 출석(대칭차집합), `merge`는 중복 3과 5를 둘 다 둠
  - `minmax_element`, 초기화 리스트를 받는 `max`, `clamp`

## 헷갈리기 쉬운 점

- `partition`은 각 부분의 원래 순서를 지킨다?
  - 지키지 않음. `stable_partition`
- `nth_element` 뒤에는 앞부분도 정렬되어 있다?
  - n번째만 제자리이고, 앞은 모두 작다는 것만 보장. 정렬이 필요하면 따로 `sort`
- 정렬되지 않은 `vector`에 `binary_search`를 써도 된다?
  - 결과가 틀림. 먼저 정렬
- `set_union`의 대상은 빈 `vector`의 `begin()`이어도 된다?
  - 덮어쓰므로 충분히 커야 함. 또는 `back_inserter`
- `std::max(a, b)`가 컴파일되지 않는다(Windows)?
  - `Windows.h`의 `max` 매크로. `NOMINMAX` 또는 `(std::max)(a, b)`

## 정리

| 분류 | 알고리즘 |
| --- | --- |
| 분할 | `partition`(순서 비보장), `stable_partition`, `partition_copy` |
| 정렬 | `sort`, `stable_sort`, `is_sorted`, `partial_sort`, `nth_element`(선형) |
| 이진 탐색 | `lower_bound`, `upper_bound`, `equal_range`, `binary_search`. 정렬된 범위 |
| 집합 | `includes`, `set_union`, `set_intersection`, `set_difference`, `set_symmetric_difference`. 대상 크기 주의 |
| 병합 | `merge`(선형, 중복 유지) |
| 최소·최대 | `min`, `max`, `minmax`(값), `min_element` 등(범위), `clamp`(C++17) |
