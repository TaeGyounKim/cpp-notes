## 함수 템플릿

- **함수 템플릿** (function template): 독립 함수의 템플릿. 문법은 클래스 템플릿과 비슷함 <CppRef path="cpp/language/function_template" />
- 예: 배열에서 값을 찾아 그 인덱스를 돌려주는 범용 함수

```cpp
template <typename T>
std::optional<std::size_t> indexOf(const T& value, const T* arr,
                                   std::size_t size)
{
    for (std::size_t i{ 0 }; i < size; ++i) {
        if (arr[i] == value) { return i; }   // 찾음: 인덱스
    }
    return {};                               // 못 찾음: 빈 optional
}
```

- `int` 배열에서 `int`를, `Reading` 배열에서 `Reading`을 찾는 등 어떤 타입의 배열에도 씀
- 부르는 방법 두 가지
  - 꺾쇠괄호로 템플릿 타입 인수를 **직접 지정**: `indexOf<int>(30, ids, 4)`
  - 생략하고 컴파일러가 인수에서 **추론**하게 함: `indexOf(30, ids, 4)`

### 추론이 엇갈리면

```cpp
double ratios[]{ 0.5, 1.0, 2.5 };
indexOf(1, ratios, 3);           // 컴파일 오류
indexOf<double>(1, ratios, 3);   // T를 double로 정하면 1이 1.0으로 바뀜
```

- 첫 인수에서는 `T`가 `int`, 둘째 인수에서는 `double`로 추론되어 엇갈림
- GCC: ``deduced conflicting types for parameter 'const T' ('int' and 'double')``
- 직접 지정하면 추론하지 않으므로 보통의 변환이 일어남

### 배열 크기도 추론하기

- 스택의 배열처럼 컴파일러가 크기를 아는 배열이라면 크기를 넘기지 않아도 되게 할 수 있음
- 함수 템플릿도 클래스 템플릿처럼 **타입이 아닌 매개변수**를 받을 수 있음

```cpp
template <typename T, std::size_t N>
std::optional<std::size_t> indexOf(const T& value, const T (&arr)[N])
{
    return indexOf(value, arr, N);   // 앞의 판에 넘김
}
```

- `const T (&arr)[N]`: 원소 `N`개짜리 배열에 대한 참조. 모양은 낯설지만 쓰기는 간단함
  - 예: `indexOf(25, ids)`
- 함수 템플릿의 **정의**(원형만이 아니라)도 쓰는 모든 소스 파일에서 보여야 함(2편). 여러 파일에서 쓰면 모듈 인터페이스 파일에 두고 내보냄
- 함수 템플릿의 템플릿 매개변수도 기본값을 가질 수 있음

:::note
표준 라이브러리의 `std::find()`는 여기의 `indexOf()`보다 훨씬 강력한 함수 템플릿이다(20장).
:::

## 오버로드냐 템플릿이냐

- 여러 타입에 쓸 함수를 만드는 방법은 두 가지: 함수 **오버로드**, 함수 **템플릿**
- 함수 본문이 모든 타입에서 **같으면** 함수 템플릿
- 본문이 타입마다 **다르면** 함수 오버로드

## 함수 템플릿 오버로드

- 이론상 함수 템플릿도 클래스 템플릿처럼 특수화할 수 있음. 그러나 함수 템플릿 특수화는 **오버로드 결정에 참여하지 않아** 뜻밖의 동작을 할 수 있으므로 거의 쓰지 않음
- 대신 템플릿이 아닌 함수나 다른 함수 템플릿으로 **오버로드**함
- 예: C 문자열(`const char*`)용 `indexOf()`. `==`는 포인터만 비교하므로 `std::strcmp()`(2장)로 내용을 비교함

```cpp
std::optional<std::size_t> indexOf(const char* value, const char** arr,
                                   std::size_t size)
{
    for (std::size_t i{ 0 }; i < size; ++i) {
        if (std::strcmp(arr[i], value) == 0) { return i; }
    }
    return {};
}
```

```cpp
const char word[]{ "습도" };   // 리터럴과 주소가 다른 배열(2장의 리터럴 풀링 참고)
const char* names[]{ "온도", "습도", "기압" };
indexOf(word, names, 3);                 // 템플릿이 아닌 판: 1
indexOf<const char*>(word, names, 3);    // 템플릿(T = const char*): 못 찾음
```

- 템플릿 타입 인수를 직접 지정하면 템플릿이 불림. 포인터만 비교하므로 내용이 같아도 찾지 못함
- 오버로드 결정 결과 후보가 둘이고 하나는 함수 템플릿, 하나는 템플릿이 아닌 함수라면, 컴파일러는 언제나 **템플릿이 아닌 함수**를 고름

## 함수 템플릿을 클래스 템플릿의 friend로

- 클래스 템플릿에 연산자를 오버로드할 때 함수 템플릿이 쓸모 있음
- 예: 값 목록을 담는 `Bin<T>` 둘을 더하는 `operator+`. 결과 길이는 짧은 쪽에 맞추고, 같은 위치끼리 더함

```cpp
template <typename T>
Bin<T> operator+(const Bin<T>& a, const Bin<T>& b)
{
    std::size_t n{ std::min(a.m_items.size(), b.m_items.size()) };
    std::vector<T> sum(n);
    for (std::size_t i{ 0 }; i < n; ++i) {
        sum[i] = a.m_items[i] + b.m_items[i];
    }
    return Bin<T>{ sum };
}
```

- 원소 타입에 `+`가 있기만 하면 어떤 `Bin`에도 쓸 수 있음
- 문제: private 멤버 `m_items`에 접근함. public 멤버로 바꾸는 것이 가장 간단하지만, 여기서는 함수 템플릿을 클래스 템플릿의 **friend**(9장)로 만드는 법을 봄
- 원하는 것: `T`로 인스턴스화한 `operator+`가, 같은 `T`로 인스턴스화한 `Bin`의 friend가 되는 것

```cpp
template <typename T> class Bin;
template <typename T> Bin<T> operator+(const Bin<T>& a, const Bin<T>& b);

template <typename T>
class Bin
{
public:
    friend Bin operator+ <T>(const Bin& a, const Bin& b);
    // 나머지 생략
};
```

- `T` 타입의 클래스 템플릿 인스턴스에는 `T` 인스턴스의 `operator+`가 friend라는 뜻. 클래스 인스턴스와 함수 인스턴스가 **일대일**로 짝지어짐
- `operator+` 뒤의 `<T>`가 핵심. `operator+`가 그 자체로 템플릿이라고 컴파일러에게 알림
- 그래서 friend 선언보다 앞에 함수 템플릿 선언이 보여야 함(위 앞쪽 선언 두 줄)

## 템플릿 타입 매개변수 추론 더 보기

- 컴파일러는 함수 템플릿에 넘긴 **인수**로 템플릿 매개변수를 추론함. 추론할 수 없는 것은 직접 지정해야 함
- 예: 반환 타입과 두 피연산자 타입을 받는 `addAs()`

```cpp
template <typename RetType, typename T1, typename T2>
RetType addAs(const T1& a, const T2& b) { return a + b; }

auto x{ addAs<long long, int, int>(1, 2) };   // 모두 지정
auto y{ addAs<long long>(1, 2) };             // T1, T2는 인수에서 추론
```

- 추론할 매개변수가 목록의 **뒤쪽**에 있을 때만 이렇게 줄일 수 있음
  - `template <typename T1, typename RetType, typename T2>`였다면, 추론할 수 없는 `RetType`이 둘째라 앞의 `T1`까지 지정해야 함: `addAs<int, long long>(1, 2)`
- 반환 타입에 기본값을 주면 아무것도 지정하지 않아도 됨

```cpp
template <typename RetType = long long, typename T1, typename T2>
RetType addWide(const T1& a, const T2& b) { return a + b; }

auto z{ addWide(1, 2) };   // long long
```

## 함수 템플릿의 반환 타입

- 반환 타입도 컴파일러가 정하게 하고 싶음. 그런데 반환 타입이 `a + b`의 타입이고, 이는 `T1`, `T2`에 따라 달라짐
- <Badge text="C++14" /> 반환 타입 추론(1장)으로 간단히 해결

```cpp
template <typename T1, typename T2>
auto add(const T1& a, const T2& b) { return a + b; }
```

### auto와 decltype(auto)

- `auto`로 식의 타입을 추론하면 **참조와 `const`가 벗겨짐**. `decltype`은 벗기지 않음 <CppRef path="cpp/language/decltype" />
  - `add()`는 `+`가 어차피 새 객체를 돌려주므로 괜찮지만, 벗겨지면 안 되는 함수 템플릿도 있음
- 템플릿이 아닌 예로 차이를 봄

```cpp
const std::string g_unit{ "kPa" };
const std::string& unit() { return g_unit; }

auto s1{ unit() };                   // std::string: 복사됨
const auto& s2{ unit() };            // const std::string&: 직접 붙임
decltype(unit()) s3{ unit() };       // const std::string&: 식을 두 번 씀
decltype(auto) s4{ unit() };         // const std::string&
```

- `decltype(auto)` <Badge text="C++14" />: `decltype`처럼 아무것도 벗기지 않으면서 식을 두 번 쓰지 않아도 됨
- 그래서 참조와 `const`를 지켜야 하는 함수 템플릿은 `decltype(auto)`를 반환 타입으로 씀

```cpp
template <typename F>
decltype(auto) callKeep(F f) { return f(); }   // f()의 참조·const 그대로
```

### C++14 이전의 방법

- 반환 타입 추론과 `decltype(auto)`가 없던 때는 C++11의 `decltype(식)`을 씀
- 이렇게 쓰고 싶지만 틀림

```cpp
template <typename T1, typename T2>
decltype(a + b) add(const T1& a, const T2& b) { return a + b; }
```

- 원형의 맨 앞에서는 `a`와 `b`가 아직 알려지지 않음. 매개변수 목록 끝까지 읽어야 알려짐. GCC는 `a`가 선언되지 않았다고 함(`not declared in this scope`)
- 해결 1: **뒤에 오는 반환 타입** (trailing return type, 1장). 앞에 `auto`를 쓰고 실제 반환 타입은 매개변수 목록 뒤에 씀. 이때는 매개변수 이름과 타입이 알려져 있음

```cpp
template <typename T1, typename T2>
auto add(const T1& a, const T2& b) -> decltype(a + b)
{
    return a + b;
}
```

- 해결 2: **`std::declval<T>()`** <Badge text="C++11" />: 요청한 타입의 우측값 참조를 돌려줌 <CppRef path="cpp/utility/declval" />
  - 생성자를 부르지 않으므로 완전히 만들어진 객체가 아님. 실행 시간에 쓸 수 없고, `decltype()` 안에서만 씀
  - 제네릭 코드에서 모르는 타입의 객체가 필요할 때 유용함. 어떤 생성자가 있는지 모르니 생성자를 부를 수 없기 때문

```cpp
template <typename T1, typename T2>
decltype(std::declval<T1>() + std::declval<T2>()) add(const T1& a,
                                                      const T2& b)
{
    return a + b;
}
```

:::tip
지금은 `auto` 반환 타입 추론과 `decltype(auto)`가 있으므로 그쪽을 쓴다. 뒤에 오는 반환 타입이나 `declval`은 C++11까지 내려가야 할 때 쓴다.
:::

## 헷갈리기 쉬운 점

- `indexOf(1, ratios, 3)`처럼 `int`와 `double`을 섞어 넘기면 알아서 바뀐다?
  - 추론이 엇갈려 오류. `indexOf<double>(...)`로 지정해야 변환됨
- 템플릿과 템플릿이 아닌 함수가 똑같이 맞으면 템플릿을 고른다?
  - 템플릿이 아닌 함수를 고름. 템플릿 인수를 직접 지정하면 템플릿
- 함수 템플릿 특수화로 특정 타입을 따로 처리한다?
  - 오버로드 결정에 참여하지 않아 뜻밖의 동작을 할 수 있음. 오버로드를 씀
- friend 선언에서 `operator+ <T>`의 `<T>`는 빼도 된다?
  - 빼면 템플릿이 아닌 함수를 friend로 선언하는 것이 됨
- `auto` 반환 타입은 참조를 그대로 돌려준다?
  - 참조와 `const`가 벗겨짐. 지키려면 `decltype(auto)`

## 정리

| 요소 | 핵심 |
| --- | --- |
| 함수 템플릿 | `template <typename T> R f(...)` |
| 인수 | 추론하거나 `f<int>(...)`로 지정. 추론이 엇갈리면 오류 |
| 배열 크기 | `template <typename T, std::size_t N> f(const T (&arr)[N])` |
| 오버로드 vs 템플릿 | 본문이 같으면 템플릿, 다르면 오버로드 |
| 고르는 순서 | 똑같이 맞으면 템플릿이 아닌 함수 |
| friend 함수 템플릿 | 앞쪽 선언 + `friend Bin operator+ <T>(...)` |
| 추론 불가 매개변수 | 목록 앞에 두거나 기본값 |
| 반환 타입 | `auto`(벗김), `decltype(auto)`(그대로). C++11은 `-> decltype(식)`, `declval` |
