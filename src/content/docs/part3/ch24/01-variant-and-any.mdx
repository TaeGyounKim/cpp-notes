## 어휘 타입

- **어휘 타입** (vocabulary type): `int`, `double` 같은 기본 타입만큼 자주 쓰는 타입
  - 더 복잡한 타입을 만드는 재료가 됨
  - 코드를 더 안전하고 효율적으로, 쓰고 읽고 고치기 쉽게 만듦
  - 앞에서 본 예: `vector`, `optional`, `string`, `unique_ptr`, `shared_ptr`
- 이 장에서 볼 것: `variant`, `any`(1편), `tuple`(2편), `optional`의 모나드 연산과 `expected`(3편)

## variant <Badge text="C++17" />

- 주어진 타입들 중 **하나의 값**을 담음. `<variant>` <CppRef path="cpp/utility/variant" />

```cpp
std::variant<int, std::string, float> v;   // int, string, float 중 하나만
```

- 템플릿 타입 인수는 서로 달라야 함. `variant<int, int>`는 안 됨
- 기본 생성하면 **첫 번째 타입**의 기본값을 담음. 위의 `v`는 `int` 0
  - 그래서 기본 생성하려면 첫 타입이 기본 생성 가능해야 함
  - 어느 타입도 기본 생성할 수 없으면 맨 앞에 **`std::monostate`**(값이 없음을 나타내는 빈 타입)를 둠 <CppRef path="cpp/utility/variant/monostate" />

```cpp
struct Foo { Foo(int) {} };      // 기본 생성자 없음
struct Bar { Bar(int) {} };
// std::variant<Foo, Bar> bad;   // 오류
std::variant<std::monostate, Foo, Bar> ok;   // 됨. monostate를 담음
```

- 대입으로 값을 넣음. 한 번에 값 하나만 담으므로, 새로 대입하면 이전 값은 사라짐

```cpp
v = 12;            // int
v = 12.5f;         // 이제 float
v = "text"s;       // 이제 string
```

### 무엇이 들었는지 묻고 꺼내기

| 함수 | 하는 일 |
| --- | --- |
| `v.index()` | 지금 담긴 타입의 0부터 시작하는 번호 |
| `std::holds_alternative<T>(v)` | 지금 `T`를 담고 있는지 <CppRef path="cpp/utility/variant/holds_alternative" /> |
| `std::get<i>(v)`, `std::get<T>(v)` | 번호나 타입으로 값을 꺼냄. 맞지 않으면 `bad_variant_access` 예외 <CppRef path="cpp/utility/variant/get" /> |
| `std::get_if<i>(&v)`, `std::get_if<T>(&v)` | `variant`의 **포인터**를 받아 값의 포인터를 돌려줌. 맞지 않으면 `nullptr` <CppRef path="cpp/utility/variant/get_if" /> |

```cpp
if (auto* s{ std::get_if<std::string>(&v) }) {
    std::println("문자열 {}", *s);
}
```

### visit

- `std::visit(방문자, v)`: 지금 담긴 값을 방문자에게 넘겨 호출. **방문자 패턴** <CppRef path="cpp/utility/variant/visit" />
  - 방문자: 담길 수 있는 **모든 타입**을 받을 수 있는 호출 가능 객체(함수, 람다, 함수 객체)
- 제네릭 람다 하나로 모든 타입을 같은 방식으로 처리

```cpp
std::visit([](const auto& value) { std::println("값 = {}", value); }, v);
```

- 타입마다 다르게 처리하려면 호출 연산자를 오버로드한 클래스를 씀

```cpp
struct Show {
    static void operator()(int i) { std::println("int {}", i); }
    static void operator()(float f) { std::println("float {}", f); }
    static void operator()(const std::string& s)
    {
        std::println("string {}", s);
    }
};
std::visit(Show{}, v);
```

- `static operator()` <Badge text="C++23" />: 멤버에 접근하지 않는 호출 연산자를 정적으로 둘 수 있음. 그 전에는 보통 `const` 멤버로 씀
- 흔한 기법: 람다 여러 개를 상속해 한 방문자로 묶는 `Overloaded` 도우미(예제 참고)

:::note
`variant`에는 배열과 참조를 담을 수 없다(`optional`과 같다). 포인터나 `reference_wrapper<T>`, `reference_wrapper<const T>`(18장)를 담는다. C++23부터 `variant`는 `constexpr` 클래스라 컴파일 시간에도 쓸 수 있다.
:::

## any <Badge text="C++17" />

- **아무 타입**의 값 하나를 담음. `<any>` <CppRef path="cpp/utility/any" />
- 만들기: 생성자 또는 `std::make_any<T>(...)` <CppRef path="cpp/utility/any/make_any" />
- 멤버
  - `has_value()`: 값이 있는지
  - `type()`: 담긴 값의 `type_info`. `name()`이 돌려주는 문자열은 컴파일러마다 다름
- 꺼내기: **`any_cast<T>`** <CppRef path="cpp/utility/any/any_cast" />
  - 값이나 참조 버전은 타입이 맞지 않으면 `bad_any_cast` 예외
  - 포인터 버전(`any_cast<T>(&a)`)은 맞지 않으면 `nullptr`

```cpp
std::any something{ 3 };            // int
something = "text"s;                // 같은 객체에 이제 string
std::string s{ std::any_cast<std::string>(something) };
```

- 표준 컨테이너에 담아 서로 다른 타입의 값을 한 컨테이너에 둘 수 있음
  - 꺼낼 때마다 `any_cast`를 해야 하는 것이 단점

```cpp
std::vector<std::any> bag;
bag.push_back(42);
bag.push_back("text"s);
std::println("{}", std::any_cast<std::string>(bag[1]));
```

- `optional`, `variant`처럼 참조를 담을 수 없음. 포인터나 `reference_wrapper`를 담음

### variant와 any 중 무엇을

| | `variant<A, B, C>` | `any` |
| --- | --- | --- |
| 담을 수 있는 타입 | 컴파일 시간에 정한 목록 | 아무 타입 |
| 타입 검사 | 컴파일 시간(목록에 없는 타입은 오류) | 실행 시간(`any_cast` 실패) |
| 처리 | `visit`로 모든 경우를 빠짐없이 | 타입마다 직접 `any_cast` |
| 메모리 | 가장 큰 타입 크기 + 번호. 힙 할당 없음 | 작은 값 말고는 보통 힙 할당 |

- 가능한 타입을 알면 `variant`를 씀. `any`는 정말 미리 알 수 없을 때만

- 볼 것
  - 기본 생성된 `variant`는 첫 타입 `int`(번호 0)
  - 지금 담긴 것과 다른 타입으로 `get`하면 예외, `get_if`는 `nullptr`
  - `Describe` 클래스 방문자와 `Overloaded`로 묶은 람다 방문자
  - `any`에 다른 타입을 대입하고, 맞지 않는 `any_cast`는 예외

## 이전 표준에서는

| 이 글에서 쓴 것 | 들어온 표준 | 그 이전에는 |
| --- | --- | --- |
| `static operator()` | C++23 | `const` 멤버 함수 |
| `variant`, `visit`, `any` | C++17 | 태그와 값을 담은 구조체, 공용체(`union`), 외부 라이브러리 |
| `Overloaded`를 추론 가이드 없이 쓰기(집합체 CTAD) | C++20 | C++17에서는 `template <class... Fs> Overloaded(Fs...) -> Overloaded<Fs...>;`를 덧붙임 |

- 아래 코드는 C++11 옵션으로 컴파일됨. 태그(`enum class`)로 무엇이 들었는지 나타내는 구조체
  - 잘못된 태그로 읽어도 컴파일러가 막지 못함. `variant`가 주는 안전함이 없음

## 헷갈리기 쉬운 점

- `variant<int, string>`은 `int`와 `string`을 함께 담는다?
  - 둘 중 **하나**만. 둘 다는 `tuple`이나 `pair`(2편)
- 기본 생성한 `variant`는 비어 있다?
  - 첫 타입의 기본값. 비어 있음을 나타내려면 `monostate`를 첫 타입으로
- `get_if<T>(v)`처럼 `variant`를 바로 넘긴다?
  - 포인터 `&v`를 넘김
- `visit`의 방문자는 일부 타입만 처리해도 된다?
  - 모든 타입을 받을 수 있어야 컴파일됨
- `any`가 더 유연하니 늘 `any`를 쓴다?
  - 타입 검사가 실행 시간으로 밀리고 보통 더 느림. 타입 목록을 알면 `variant`

## 정리

| 요소 | 핵심 |
| --- | --- |
| `variant<Ts...>` | 정해진 타입 중 하나. 기본은 첫 타입. `monostate` |
| 묻기 | `index()`, `holds_alternative<T>` |
| 꺼내기 | `get`(예외), `get_if`(포인터, `nullptr`) |
| `visit` | 모든 타입을 받는 방문자로 처리 |
| `any` | 아무 타입 하나. `has_value()`, `type()` |
| `any_cast` | 값은 예외, 포인터는 `nullptr` |

## 복습 질문

<details>
<summary>도형이 `Circle` 또는 `Rect`일 때 넓이를 구하는 코드를 `variant`로 쓰려면?</summary>

```cpp
struct Circle { double r; };
struct Rect { double w, h; };
using Shape = std::variant<Circle, Rect>;

double area(const Shape& s)
{
    return std::visit(Overloaded{
        [](const Circle& c) { return 3.14159 * c.r * c.r; },
        [](const Rect& r) { return r.w * r.h; } }, s);
}
```

- `Overloaded`는 예제의 도우미 템플릿

</details>

<details>
<summary>`std::variant<std::string, bool> v{ "hi" };`는 무엇을 담는가?</summary>

- 지금 규칙에서는 `std::string`(번호 0)을 담음
- 처음 C++17 규칙에서는 `const char*`에서 `bool`로 가는 표준 변환이 `string`으로 가는 사용자 정의 변환보다 앞서 `bool`을 담았음
  - 이를 고친 변경이 결함 보고로 처리되어, 최근 컴파일러는 C++17 모드에서도 `string`을 담음(GCC 16에서 확인). 오래된 컴파일러에서는 `bool`이 될 수 있음
- 헷갈리지 않게 `std::string{ "hi" }`처럼 타입을 분명히 씀

</details>

<details>
<summary>`std::any a{ 3.0 };`에서 `std::any_cast<int>(a)`는 무엇을 하는가?</summary>

- `bad_any_cast` 예외. `any_cast`는 담긴 타입(`double`)과 정확히 같아야 하며 변환하지 않음

</details>
