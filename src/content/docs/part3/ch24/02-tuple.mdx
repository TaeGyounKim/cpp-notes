## pair 다시 보기

- `std::pair`(`<utility>`): 값 정확히 **둘**을 담음. 각 타입은 컴파일 시간에 정해짐(1장, 18장)

```cpp
std::pair<int, std::string> p1{ 16, "hello" };
std::pair p2{ true, 0.25f };                 // CTAD
std::println("({}, {})", p1.first, p1.second);
std::println("{}", p1);                      // C++23: (16, "hello")
```

- C++23부터 `format()`과 `print()` 계열이 `pair`와 `tuple`을 바로 출력함. 문자열 원소는 큰따옴표로 감싸짐

## tuple <Badge text="C++11" />

- `pair`의 일반화: 값을 **몇 개든** 담고, 각자 타입이 다름. `<tuple>` <CppRef path="cpp/utility/tuple" />
- `pair`처럼 크기와 원소 타입이 컴파일 시간에 고정됨

```cpp
using Record = std::tuple<int, std::string, bool>;
Record r1{ 16, "test", true };
std::println("{}", r1);                      // (16, "test", true)
```

### 원소 꺼내기

- `std::get<i>(t)`: 0부터 시작하는 i번째 원소. 그 원소의 타입으로 돌려줌 <CppRef path="cpp/utility/tuple/get" />
  - `i`는 **컴파일 시간 상수**여야 함. 그래서 `for`로 `get<i>`를 돌며 원소를 훑을 수 없음(템플릿 메타프로그래밍이 필요. 26장)
- `std::get<T>(t)`: 타입으로 꺼냄 <Badge text="C++14" />. 그 타입의 원소가 여러 개면 컴파일 오류

```cpp
int n{ std::get<0>(r1) };
std::string& s{ std::get<std::string>(r1) };
```

- `typeid(std::get<1>(r1)).name()`(`<typeinfo>`)으로 타입을 확인해 볼 수 있음. 문자열은 컴파일러마다 다름

### 크기와 원소 타입

- **인스턴스가 아니라 타입**을 받음
  - `std::tuple_size<Record>::value`: 원소 수 <CppRef path="cpp/utility/tuple/tuple_size" />
  - `std::tuple_element<2, Record>::type`: 2번 원소의 타입 <CppRef path="cpp/utility/tuple/tuple_element" />
- 인스턴스만 있으면 `decltype`으로 타입을 얻음: `std::tuple_size<decltype(r1)>::value`
- C++17부터 `_v`, `_t` 별칭: `std::tuple_size_v<Record>`, `std::tuple_element_t<2, Record>`

### CTAD와 참조

- 클래스 템플릿 인수 추론(CTAD)으로 타입을 생략할 수 있음 <Badge text="C++17" />
  - 문자열 리터럴은 `const char*`로 추론되므로, `std::string`이 필요하면 `"test"s`

```cpp
std::tuple r2{ 16, "test"s, true };          // tuple<int, string, bool>
```

- CTAD에서는 `&`를 쓸 수 없으므로, 참조를 담으려면 `std::ref()`, `std::cref()`(`<functional>`) <CppRef path="cpp/utility/functional/ref" />
  - `reference_wrapper<T>`, `reference_wrapper<const T>`를 만들고, `tuple`은 이를 `T&`, `const T&`로 담음

```cpp
double d{ 3.14 };
// tuple<int, double&, const double&>
std::tuple t{ 16, std::ref(d), std::cref(d) };
std::get<1>(t) *= 2;          // d가 6.28
// std::get<2>(t) *= 2;       // 오류: const 참조
```

- CTAD 이전에는 함수 템플릿 `std::make_tuple()`로 타입을 추론함 <CppRef path="cpp/utility/tuple/make_tuple" />

```cpp
auto t2{ std::make_tuple(16, std::ref(d), std::cref(d)) };
```

## 분해하기

### 구조적 바인딩 <Badge text="C++17" />

- `tuple`을 변수 여러 개로 나눔 <CppRef path="cpp/language/structured_binding" />

```cpp
std::tuple r{ 16, "test"s, true };
auto [i, str, b] { r };            // 복사
auto& [i2, str2, b2] { r };        // 참조: 고치면 r이 바뀜
i2 *= 2;
```

- C++23까지는 원소 일부를 건너뛸 수 없음. 원소가 셋이면 이름도 셋

### tie

- `std::tie(a, b, c)`: 변수들의 **참조로 이뤄진 tuple**을 만듦 <CppRef path="cpp/utility/tuple/tie" />
- 여기에 `tuple`을 대입하면 원소가 각 변수에 들어감
- 필요 없는 원소는 `std::ignore` 자리에 둠 <CppRef path="cpp/utility/tuple/ignore" />

```cpp
int i{ 0 };
bool b{ false };
std::tie(i, std::ignore, b) = r;   // 문자열은 버림
```

- 구조적 바인딩과 달리 이미 있는 변수에 넣고, 일부를 건너뛸 수 있음

## 이어 붙이기와 비교

- `std::tuple_cat(t1, t2, ...)`: 여러 `tuple`을 하나로 <CppRef path="cpp/utility/tuple/tuple_cat" />

```cpp
auto t3{ std::tuple_cat(std::tuple{ 16, "a"s }, std::tuple{ 3.14 }) };
// tuple<int, string, double>
```

- 비교 연산자를 모두 지원함. 원소 타입도 그 비교를 지원해야 함
  - **사전식**: 첫 원소부터 비교하고, 같으면 다음 원소로
  - `tuple{ 123, "def"s } < tuple{ 123, "abc"s }`는 `false`

:::caution
문자열 리터럴을 CTAD로 담으면 `const char*`가 되어, 비교할 때 문자열 내용이 아니라 **포인터 값**을 비교한다. 비교할 `tuple`에는 `std::string`(`"abc"s`)을 담는다.
:::

### tie로 비교 연산자 만들기

- 모든 데이터 멤버를 비교하려면 `operator<=>`를 `= default`로 두면 됨(9장)
- **일부 멤버만** 비교하는 연산자도 `tie`와 `<=>`로 한 줄에 씀

```cpp
class Item {
public:
    auto operator<=>(const Item& rhs) const
    {
        return std::tie(m_id, m_name) <=> std::tie(rhs.m_id, rhs.m_name);
    }
private:
    int m_id;
    std::string m_name;
    bool m_cached;   // 비교에서 뺌
};
```

- `<=>`를 직접 정의하면 `==`는 자동으로 생기지 않음. 필요하면 `operator==`도 같은 방식으로 정의

## make_from_tuple과 apply <Badge text="C++17" />

- `std::make_from_tuple<T>(t)`: `t`의 원소들을 `T`의 생성자 인수로 넘겨 `T`를 만듦 <CppRef path="cpp/utility/make_from_tuple" />
  - `t`가 꼭 `tuple`일 필요는 없음. `std::get<>()`과 `tuple_size`를 지원하면 됨: `std::array`, `pair`도 됨

```cpp
class Account {
public:
    Account(std::string owner, int balance);
};
auto acc{ std::make_from_tuple<Account>(std::tuple{ "kim"s, 100 }) };
```

- `std::apply(f, t)`: `t`의 원소들을 인수로 넘겨 `f`를 부름 <CppRef path="cpp/utility/apply" />

```cpp
int add(int a, int b) { return a + b; }
std::println("{}", std::apply(add, std::tuple{ 39, 3 }));   // 42
```

## 헷갈리기 쉬운 점

- `for (int i = 0; i < 3; ++i) std::get<i>(t)`로 훑는다?
  - `i`가 컴파일 시간 상수가 아니라 안 됨
- `tuple_size<decltype(t)>` 대신 `tuple_size<t>`라고 쓴다?
  - 인스턴스가 아니라 타입을 넘김
- 구조적 바인딩에서 `_`로 원소를 건너뛴다?
  - C++23까지는 건너뛸 수 없음(`_`를 자리 표시자로 쓰는 기능은 C++26). 건너뛰려면 `tie`와 `ignore`
- `std::tuple t{ "a", 1 }`의 첫 원소는 `std::string`이다?
  - `const char*`. 비교하면 포인터를 비교함
- `tie(a, b) <=> tie(c, d)`만 정의하면 `==`도 된다?
  - `<=>`를 직접 정의하면 `==`는 따로 정의해야 함

## 정리

| 요소 | 핵심 |
| --- | --- |
| `tuple<Ts...>` | 개수와 타입이 고정된 여러 값. 출력은 C++23 |
| `get<i>`, `get<T>` | 원소 꺼내기. `i`는 컴파일 시간 상수 |
| `tuple_size`, `tuple_element` | 타입을 받음 |
| `ref`, `cref` | 참조 원소 |
| 분해 | 구조적 바인딩, `tie` + `ignore` |
| `tuple_cat`, 비교 | 이어 붙이기, 사전식 비교. `tie`로 비교 연산자 |
| `apply`, `make_from_tuple` | 원소를 함수 인수, 생성자 인수로 |
