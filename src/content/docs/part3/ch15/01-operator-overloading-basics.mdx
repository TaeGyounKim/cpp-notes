- 다루는 것: 직접 만든 클래스에서 연산자의 동작을 정의하는 **연산자 오버로딩** (operator overloading). 9장에서 기초를 보았고, 이 장에서 모든 연산자로 넓힘
- 이 글에서 배우는 요소: 오버로딩하는 이유, 제약, 멤버 함수냐 전역 함수냐, 매개변수·반환 타입·동작 고르기, 오버로드하지 말아야 할 연산자

## 연산자 오버로딩이란

- 1장: C++의 연산자는 `+`, `<`, `*`, `<<` 같은 기호. `int`, `double` 같은 기본 타입에 산술, 논리 등의 연산을 함
  - 포인터를 역참조하는 `->`, `*`도 연산자
  - `[]`(배열 첨자), `()`(함수 호출), 캐스트, 메모리 할당·해제까지 연산자 개념이 넓음
- **연산자 오버로딩**: 내 클래스에 대해 언어 연산자의 동작을 바꿈 <CppRef path="cpp/language/operators" />. 규칙, 제약, 선택지가 따름

### 왜 오버로드하는가

- 연산자마다 이유가 다르지만, 기본 원칙은 **내 클래스가 기본 타입처럼 동작하게** 하는 것
  - 기본 타입에 가까울수록 쓰는 쪽이 쓰기 쉬움
  - 예: 분수 클래스라면 `+`, `-`, `*`, `/`가 그 객체에 대해 무엇을 뜻하는지 정의할 수 있으면 매우 편함
- 프로그램의 동작을 더 세밀하게 제어하려고도 씀
  - 예: 메모리 할당·해제 연산자를 오버로드해 객체마다 메모리를 어떻게 나눠 주고 거둘지 정함(7편)
- 연산자 오버로딩은 클래스를 **만드는 사람**이 아니라 **쓰는 사람**을 편하게 하는 것이 주된 목적

## 제약

- 다음은 할 수 없음
  - **새 연산자 기호를 만들 수 없음**. 언어에 이미 있는 연산자의 뜻만 다시 정의함. 오버로드할 수 있는 연산자 목록은 2편
  - 몇몇 연산자는 오버로드할 수 없음: `.`, `.*`(객체의 멤버 접근), `::`(범위 지정), `?:`(조건 연산자) 등. 어차피 오버로드할 일이 거의 없는 것들
  - **인수 개수** (arity, 피연산자 수)를 바꿀 수 없음. 예외는 함수 호출 `()`, `new`, `delete`, 그리고 C++23부터 첨자 `[]`
    - 단항 연산자(`++` 등)는 피연산자 하나, 이항 연산자(`/` 등)는 둘
    - GCC: 전역 `operator/`에 인수를 셋 주면 ``must have exactly two arguments``
  - **우선순위와 결합 방향**을 바꿀 수 없음
    - 우선순위: 어느 연산자를 먼저 계산할지. 결합 방향: 같은 우선순위끼리 왼쪽부터인지 오른쪽부터인지
    - 대개 문제가 안 되지만 분야에 따라 조심해야 함. 예: 수학 벡터에 `^`를 거듭제곱으로 오버로드하면, `^`는 `+`보다 우선순위가 낮아 `x ^ 3 + y`가 `x ^ (3 + y)`로 계산됨
  - **기본 타입의 연산자를 다시 정의할 수 없음**
    - 연산자는 클래스의 멤버이거나, 전역 함수라면 인수 중 적어도 하나가 사용자 정의 타입(클래스, 열거형)이어야 함
    - 그래서 `int`의 `+`를 뺄셈으로 바꾸는 엉뚱한 일은 못 함. GCC는 인수에 클래스나 열거형이 있어야 한다고 알림
    - 예외: 메모리 할당·해제 연산자는 프로그램 전체의 전역 연산자를 바꿀 수 있음
- 뜻이 둘인 연산자도 있음. 두 뜻을 모두 오버로드할 수 있음
  - `-`: 이항(`x = y - z;`)과 단항(`x = -y;`)
  - `*`: 곱셈과 포인터 역참조
  - `<<`: 스트림 삽입과 왼쪽 시프트

## 선택지

- 연산자를 오버로드한다는 것은 이름이 `operatorX`인 전역 함수나 멤버 함수를 쓰는 것. `X`는 연산자 기호이고, `operator`와 `X` 사이에 공백이 있어도 됨
  - 예(9장): `Cell operator+(const Cell& lhs, const Cell& rhs);`

### 멤버 함수냐 전역 함수냐

- 전역 함수는 클래스의 `friend`로 만들 수도 있지만 최후의 수단. `friend`는 private 데이터에 바로 접근해 데이터 숨기기를 우회하므로 되도록 줄임
- 차이: 연산자가 **멤버**면 연산자 식의 **왼쪽**은 반드시 그 클래스의 객체. **전역**이면 왼쪽이 다른 타입이어도 됨
- 연산자는 세 부류

| 부류 | 설명 |
| --- | --- |
| 멤버여야 하는 것 | 클래스 밖에서는 뜻이 없는 것. 예: `operator=`는 클래스와 너무 밀접해 다른 곳에 있을 수 없음. 목록은 2편 |
| 전역이어야 하는 것 | 왼쪽이 내 클래스가 아닌 타입이어야 할 때. 스트림의 `<<`, `>>`(왼쪽이 스트림 객체), `2 * v`처럼 교환 법칙이 있는 이항 연산자. 왼쪽 피연산자에 암시적 변환을 허용하려면 전역이어야 함(9장) |
| 어느 쪽이든 되는 것 | 의견이 갈리지만, **전역이어야 하는 경우가 아니면 멤버로** 하기를 권함. 멤버는 `virtual`이 될 수 있어 상속 계층에서 유리함 |

- 멤버 연산자가 객체를 바꾸지 않으면 `const`로 표시함. 그래야 `const` 객체에도 쓸 수 있음
- 전역 연산자는 그 클래스와 **같은 네임스페이스**에 둠

### 매개변수 타입

- 대부분의 연산자는 인수 개수를 바꿀 수 없어 선택이 좁음
  - 예: `operator/`는 전역이면 인수 둘, 멤버면 하나. 다르면 컴파일 오류
  - 보통 함수는 매개변수 개수가 다르게 얼마든지 오버로드할 수 있다는 점과 다름
  - 타입도 대개 그 클래스로 정해짐. `T`의 덧셈을 구현하는데 `std::string` 둘을 받는 `operator+`를 쓰지는 않음
- 실제 선택은 값이냐 참조냐, `const`냐
  - 기본 타입이 아니면 **참조**로 받음. 함수가 어차피 복사본을 만든다면 값으로(9장)
  - 실제로 바꾸지 않으면 `const`로 표시

### 반환 타입

- C++은 반환 타입으로 오버로드를 결정하지 않으므로 반환 타입은 자유. 하지만 비교 연산자가 포인터를, 산술 연산자가 `bool`을 돌려주는 식의 혼란스러운 코드는 쓰지 않음
- **기본 타입에서 그 연산자가 돌려주는 것과 같은 타입**을 돌려줌
  - 비교 연산자는 `bool`, 산술 연산자는 결과를 나타내는 객체
  - 바로 알기 어려운 것도 있음. 예: `operator=`는 연쇄 대입을 위해 호출된 객체의 참조를 돌려줌(8장)
- 값이냐 참조냐의 원칙: **참조로 돌려줄 수 있으면 참조, 아니면 값**
  - `bool`을 돌려주는 비교 연산자, 반환 타입이 없는 변환 연산자, 무엇이든 돌려줄 수 있는 함수 호출 연산자에는 해당 없음
  - 연산자가 **새 객체를 만들면** 그 객체를 **값으로** 돌려줘야 함
  - 새 객체를 만들지 않으면 호출된 객체나 인수 중 하나의 참조를 돌려줄 수 있음
- `const`: 좌측값(대입식 왼쪽 등)으로 바꿀 수 있어야 하는 반환값은 `const`가 아니어야 함. 모든 대입 연산자(`=`, `+=`, `-=` 등)가 여기에 해당

### 동작

- 오버로드한 연산자 안에 무엇이든 구현할 수는 있음. `operator+`가 끝말잇기 게임을 시작하게 할 수도 있음
- 하지만 쓰는 쪽이 기대하는 동작으로 한정함(6장). `operator+`는 덧셈, 또는 문자열 이어 붙이기처럼 덧셈 비슷한 일을 함
- 예외적인 경우가 아니면 이 장에서 보이는 표준 패턴을 따름

## 오버로드하지 말아야 할 연산자

- 허용되지만 오버로드하지 말아야 할 것들
- **주소 연산자** `operator&`
  - 변수의 주소를 얻는 언어의 기본 동작을 뜻밖의 방식으로 바꿔 혼란을 줌. 연산자 오버로딩을 많이 쓰는 표준 라이브러리 전체도 이것은 오버로드하지 않음
- **이항 논리 연산자** `operator&&`, `operator||`
  - C++의 **단락 평가** (short-circuit evaluation)가 사라짐. 오버로드한 연산자 함수에 넘기려면 두 피연산자를 모두 먼저 계산해야 하기 때문
  - 클래스에 논리 연산이 필요하면 `operator&`, `operator|`를 제공함
- **쉼표 연산자** `operator,`
  - C++에는 정말 쉼표 연산자가 있음. **순차 연산자** (sequencing operator)라고도 함. 한 문장에서 두 식을 나누고 왼쪽부터 계산하는 것을 보장함
  - 오버로드할 좋은 이유는 거의 없음

```cpp
int n{ 1 };
std::println("{}", (++n, 2 * n));   // n을 2로 늘린 뒤 두 배: 4
```

- 볼 것
  - `2 * a`는 왼쪽이 `double`이라 전역 `operator*`가 필요함
  - `(a ^ 2) + 1`에서 괄호를 빼면 `a ^ (2 + 1)`로 계산됨. 이 예제에서는 컴파일도 되고 결과만 5로 달라져 알아채기 어려움
  - 기본 `bool`의 `&&`는 왼쪽이 거짓이면 오른쪽을 계산하지 않지만, 오버로드한 `&&`는 양쪽을 모두 계산함

## 이전 표준에서는

- 연산자 오버로딩의 규칙과 선택지는 C++98부터 같음
- 바뀐 점: C++23에서 첨자 연산자 `[]`가 인수를 여러 개 받을 수 있게 됨(4편)
- 이 글의 예제에서 C++11 이후에 들어온 것은 `std::println`뿐. `std::cout`으로 바꾸면 C++11에서 그대로 컴파일됨

## 헷갈리기 쉬운 점

- `**`처럼 새 연산자를 만들 수 있다?
  - 없음. 있는 연산자만 다시 정의함
- `^`를 거듭제곱으로 오버로드하면 거듭제곱의 우선순위를 가진다?
  - 우선순위와 결합 방향은 원래 연산자 그대로
- `2 * v`도 멤버 `operator*`로 된다?
  - 멤버는 왼쪽이 그 클래스 객체여야 함. 전역 함수로
- `operator+`가 `*this`의 참조를 돌려줘도 된다?
  - 새 값을 만드는 연산자는 값으로 돌려줌. 참조는 `+=` 같은 대입 계열에서
- `&&`를 오버로드해도 단락 평가는 그대로다?
  - 사라짐. 양쪽을 모두 계산함

## 정리

| 요소 | 핵심 |
| --- | --- |
| 목적 | 내 클래스를 기본 타입처럼. 쓰는 사람을 편하게 |
| 제약 | 새 기호 불가, 일부 연산자 불가, 인수 개수·우선순위·결합 방향 고정, 기본 타입끼리 불가 |
| 멤버 / 전역 | 왼쪽이 내 클래스가 아니어야 하면 전역, 아니면 멤버(`virtual` 가능) |
| 매개변수 | 기본 타입이 아니면 참조, 바꾸지 않으면 `const` |
| 반환 | 기본 타입과 같은 종류. 새 객체는 값, 아니면 참조. 대입 계열은 `const` 아닌 참조 |
| 피할 것 | `&`(주소), `&&`, `\|\|`(단락 평가 상실), `,` |

## 복습 질문

<details>
<summary>`Money` 클래스에 `m * 3`과 `3 * m`을 모두 지원하려면 연산자를 어떻게 정의하는가?</summary>

- `m * 3`은 멤버나 전역 둘 다 가능. `3 * m`은 왼쪽이 `int`이므로 전역 `Money operator*(int, const Money&)`가 필요함. 둘 다 전역으로 두고 한쪽이 다른 쪽을 부르게 하면 깔끔함

</details>

<details>
<summary>`operator+=`의 반환 타입은 무엇이 알맞고, 왜 그런가?</summary>

- `T&`(`*this`의 참조). 새 객체를 만들지 않고, 기본 타입처럼 `(a += b) += c` 같은 식에서 좌측값으로 쓰일 수 있어야 하므로 `const`가 아닌 참조

</details>

<details>
<summary>`Condition` 클래스에 논리곱을 지원하고 싶다. `operator&&` 대신 무엇을 권하는가?</summary>

- `operator&`. `&&`를 오버로드하면 단락 평가가 사라져 쓰는 쪽의 기대와 어긋남

</details>
