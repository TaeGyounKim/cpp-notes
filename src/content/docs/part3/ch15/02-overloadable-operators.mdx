- 다루는 것: 연산자를 오버로드할 때 두고 보는 참고표. 반환 타입이 무엇이었는지, 멤버여야 했는지는 잊기 쉬움
- 이 글에서 배우는 요소: 연산자별 멤버·전역 권장과 원형, 우측값 참조 판, 우선순위와 결합 방향, `std::rel_ops`, 대체 표기

## 참고표

- 표에서 `T`는 연산자를 쓰는 클래스, `E`는 다른 타입. 원형 예는 전부가 아니며 `T`와 `E`를 다르게 조합할 수도 있음 <CppRef path="cpp/language/operators" />
- 오버로드할 수 없는 `.`, `.*`, `::`, `?:` 등은 표에 없음

### 산술·비트 연산자

| 연산자 | 멤버/전역 | 언제 | 원형 예 |
| --- | --- | --- | --- |
| 이항 산술 `+ - * / %` | 전역 권장 | 클래스에 이 연산을 제공할 때 | `T operator+(const T&, const T&);`<br/>`T operator+(const T&, const E&);` |
| 단항 산술·비트 `- + ~` | 멤버 권장 | 클래스에 이 연산을 제공할 때 | `T operator-() const;` |
| 전위 `++ --` | 멤버 권장 | 산술 인수를 받는 `+=`, `-=`를 오버로드할 때 | `T& operator++();` |
| 후위 `++ --` | 멤버 권장 | 위와 같음 | `T operator++(int);` |
| 이항 비트 `<< >> & \| ^` | 전역 권장 | 클래스에 이 연산을 제공할 때 | `T operator<<(const T&, const T&);`<br/>`T operator<<(const T&, const E&);` |

### 대입 연산자

| 연산자 | 멤버/전역 | 언제 | 원형 예 |
| --- | --- | --- | --- |
| `=` | **멤버여야 함** | 동적으로 할당한 자원이나 참조 멤버가 있을 때 | `T& operator=(const T&);` |
| 복합 산술 대입 `+= -= *= /= %=` | 멤버 권장 | 이항 산술 연산자를 오버로드했고 불변 클래스가 아닐 때 | `T& operator+=(const T&);`<br/>`T& operator+=(const E&);` |
| 복합 비트 대입 `<<= >>= &= \|= ^=` | 멤버 권장 | 이항 비트 연산자를 오버로드했고 불변 클래스가 아닐 때 | `T& operator<<=(const T&);` |

### 비교 연산자

| 연산자 | 멤버/전역 | 언제 | 원형 예 |
| --- | --- | --- | --- |
| 삼중 비교 `<=>` <Badge text="C++20" /> | 멤버 권장 | 비교를 제공할 때. 되도록 `= default` | `auto operator<=>(const T&) const = default;`<br/>`std::partial_ordering operator<=>(const E&) const;` |
| `==` | C++20 이후 멤버 권장, 이전에는 전역 권장 | 비교를 제공하는데 `<=>`를 기본으로 만들 수 없을 때 | `bool operator==(const T&) const;`<br/>`bool operator==(const T&, const T&);` |
| `!=` | C++20 이후 필요 없음(`==`에서 자동), 이전에는 전역 권장 | C++20 이전에 비교를 제공할 때 | `bool operator!=(const T&, const T&);` |
| `< > <= >=` | 전역 권장 | 이 연산을 제공할 때. `<=>`를 제공했다면 필요 없음 | `bool operator<(const T&, const T&);` |

### 그 밖의 연산자

| 연산자 | 멤버/전역 | 언제 | 원형 예 |
| --- | --- | --- | --- |
| 스트림 `<< >>` | **전역이어야 함** | 이 연산을 제공할 때(3편) | `std::ostream& operator<<(std::ostream&, const T&);`<br/>`std::istream& operator>>(std::istream&, T&);` |
| 논리 부정 `!` | 멤버 권장 | 드물게. `bool` 변환을 대신 씀 | `bool operator!() const;` |
| 이항 논리 `&& \|\|` | 전역 권장 | 거의 없음. 단락 평가가 사라짐. `&`, `\|`를 대신 씀 | `bool operator&&(const T&, const T&);` |
| 첨자 `[]` | **멤버여야 함** | 첨자를 지원할 때(4편) | `E& operator[](std::size_t);`<br/>`const E& operator[](std::size_t) const;` |
| 함수 호출 `()` | **멤버여야 함** | 객체가 함수처럼 동작하게 할 때(5편) | 반환 타입과 매개변수는 자유 |
| 변환 `operator 타입()` | **멤버여야 함** | 내 클래스에서 다른 타입으로 변환할 때. 타입마다 하나(6편) | `operator double() const;` |
| 사용자 정의 리터럴 `""_x` | **전역이어야 함** | 사용자 정의 리터럴을 지원할 때(8편) | `T operator""_i(long double d);` |
| `new new[]` | 멤버 권장 | 클래스의 메모리 할당을 제어할 때(드물게, 7편) | `void* operator new(std::size_t size);` |
| `delete delete[]` | 멤버 권장 | 메모리 할당 함수를 오버로드할 때마다(드물게) | `void operator delete(void* ptr) noexcept;` |
| 역참조 `* ->` | `*`: 멤버 권장<br/>`->`: **멤버여야 함** | 스마트 포인터 등(5편) | `E& operator*() const;`<br/>`E* operator->() const;` |
| 주소 `&` | 해당 없음 | 절대 하지 않음 | 해당 없음 |
| 멤버 포인터 역참조 `->*` | 해당 없음 | 절대 하지 않음 | 해당 없음 |
| 쉼표 `,` | 해당 없음 | 절대 하지 않음 | 해당 없음 |

## 우측값 참조를 받는 연산자

- 9장의 이동 대입 연산자: 대입 원본이 대입 뒤 사라질 임시 객체이거나 `std::move()`로 명시적으로 옮기는 객체일 때 쓰임

```cpp
T& operator=(const T&);       // 보통의 대입
T& operator=(T&&) noexcept;   // 이동 대입. 인수를 바꾸므로 const가 아님
```

- 위 표에는 우측값 참조 판이 없지만, 대부분의 연산자에서 좌측값 참조 판과 우측값 참조 판을 둘 다 쓰는 것이 의미 있을 수 있음. 클래스의 구현에 따라 다름
- 예: 불필요한 메모리 할당을 피하는 `operator+`. 표준 `std::string`은 대략 다음 오버로드를 가짐(단순화)

```cpp
using S = std::string;
S operator+(const S& a, const S& b);   // 재사용 없음
S operator+(S&& a, const S& b);        // a의 메모리 재사용
S operator+(const S& a, S&& b);        // b의 메모리 재사용
S operator+(S&& a, S&& b);             // 둘 중 하나 재사용
```

- 우측값 참조 인수는 연산이 끝나면 사라질 임시 객체이므로, 그 메모리를 결과에 다시 쓸 수 있음
  - 크기와 용량에 따라 다음 둘 중 하나로 구현함

```cpp
return std::move(a.append(b));      // a 뒤에 b를 붙임
return std::move(b.insert(0, a));   // b 앞에 a를 넣음
```

  - 재사용하는 방법은 9장의 이동 대입 연산자와 같음

- 볼 것
  - `a + b`는 둘 다 좌측값이라 복사본을 만듦
  - `Label{ "실내" } + b`는 왼쪽이 임시 객체라 우측값 참조 판이 골라지고, 그 문자열의 메모리를 옮겨 와 이어 붙임
  - `<=>`와 `==`를 `= default`로 두자 `<`, `!=`, `>=`를 모두 쓸 수 있음
  - `and`, `not`은 `&&`, `!`의 대체 표기

## 우선순위와 결합 방향

- 한 문장에 연산자가 여럿이면 **우선순위**로 무엇을 먼저 계산할지 정함. 예: `*`, `/`는 늘 `+`, `-`보다 먼저
- **결합 방향**: 우선순위가 같은 연산자끼리 왼쪽부터인지 오른쪽부터인지
- 오버로드할 수 없는 연산자까지 포함한 전체 표. 번호가 작을수록 먼저 계산함. `T`는 타입, `x`, `y`, `z`는 객체 <CppRef path="cpp/language/operator_precedence" />

| 우선순위 | 연산자 | 결합 방향 |
| --- | --- | --- |
| 1 | `::` | 왼쪽부터 |
| 2 | `x++` `x--` `x()` `x[]` `T()` `T{}` `.` `->` | 왼쪽부터 |
| 3 | `++x` `--x` `+x` `-x` `!` `~` `*x` `&x` `(T)` `sizeof` `co_await` `new` `delete` `new[]` `delete[]` | 오른쪽부터 |
| 4 | `.*` `->*` | 왼쪽부터 |
| 5 | `x*y` `x/y` `x%y` | 왼쪽부터 |
| 6 | `x+y` `x-y` | 왼쪽부터 |
| 7 | `<<` `>>` | 왼쪽부터 |
| 8 | `<=>` | 왼쪽부터 |
| 9 | `<` `<=` `>` `>=` | 왼쪽부터 |
| 10 | `==` `!=` | 왼쪽부터 |
| 11 | `x&y` | 왼쪽부터 |
| 12 | `^` | 왼쪽부터 |
| 13 | `\|` | 왼쪽부터 |
| 14 | `&&` | 왼쪽부터 |
| 15 | `\|\|` | 왼쪽부터 |
| 16 | `x?y:z` `throw` `co_yield` `=` `+=` `-=` `*=` `/=` `%=` `<<=` `>>=` `&=` `^=` `\|=` | 오른쪽부터 |
| 17 | `,` | 왼쪽부터 |

## 관계 연산자와 std::rel_ops

- `<utility>`의 `std::rel_ops` 네임스페이스에 관계 연산자 함수 템플릿이 있음 <CppRef path="cpp/utility/rel_ops/operator_cmp" />
  - `==`와 `<`만 구현하면 `!=`, `>`, `<=`, `>=`를 공짜로 만들어 줌
- 문제가 많음
  - 내 클래스뿐 아니라 관계 연산에 쓰는 모든 클래스에 그 연산자가 만들어질 수 있음
  - `std::greater<T>`(19장) 같은 도구가 이렇게 만든 연산자와 함께 동작하지 않음
  - 암시적 변환이 되지 않음
- C++20에 삼중 비교 연산자가 생기고 `std::rel_ops`가 권장하지 않음으로 바뀌었으므로 더 쓸 이유가 없음(GCC: ``'std::rel_ops' is deprecated: use '<=>' instead``)

:::danger
`std::rel_ops`는 쓰지 않는다. C++20부터 권장하지 않는다. 비교 연산자 여섯 개를 모두 지원하려면 `operator<=>`와 필요하면 `operator==`를 `= default`로 만들거나 직접 구현한다(9장).
:::

## 대체 표기

- 일부 연산자에는 단어로 된 대체 표기가 있음. `~`, `|`, `^` 같은 문자가 없는 문자 집합을 쓰던 시절에 주로 썼음 <CppRef path="cpp/language/operator_alternative" />

| 연산자 | 대체 표기 | 연산자 | 대체 표기 |
| --- | --- | --- | --- |
| `&&` | `and` | `!=` | `not_eq` |
| `&=` | `and_eq` | `\|\|` | `or` |
| `&` | `bitand` | `\|=` | `or_eq` |
| `\|` | `bitor` | `^` | `xor` |
| `~` | `compl` | `^=` | `xor_eq` |
| `!` | `not` | | |

## 헷갈리기 쉬운 점

- C++20에서도 `!=`를 따로 정의해야 한다?
  - `==`가 있으면 컴파일러가 `!=`를 알아서 씀
- `<=>`를 `= default`로 만들면 `==`도 생긴다?
  - `<=>`를 `= default`로 선언하면 `==`도 암시적으로 기본 선언됨. 직접 구현한 `<=>`라면 `==`는 따로 필요함
- `operator[]`, `operator()`, `operator->`, `operator=`는 전역으로 써도 된다?
  - 멤버여야 함
- 스트림 `<<`는 멤버로 써도 된다?
  - 왼쪽이 스트림이라 전역이어야 함
- `and`, `or`는 매크로다?
  - C++의 키워드(대체 토큰). 헤더 없이 씀

## 정리

| 요소 | 핵심 |
| --- | --- |
| 멤버여야 함 | `=`, `[]`, `()`, `->`, 변환 연산자 |
| 전역이어야 함 | 스트림 `<<` `>>`, 사용자 정의 리터럴 |
| 멤버 권장 | 단항 연산자, `++` `--`, 복합 대입, `<=>`, `==`(C++20 이후), `new` `delete`, `*` |
| 전역 권장 | 이항 산술·비트, `<` 등(C++20 이전) |
| 하지 않음 | `&`(주소), `->*`, `,`. `&&` `\|\|`도 되도록 피함 |
| 우측값 참조 판 | 임시 객체의 자원을 재사용. 예: `std::string`의 `operator+` |
| `std::rel_ops` | 쓰지 않음. `<=>` |

## 복습 질문

<details>
<summary>후위 `++`의 원형에 있는 `int` 매개변수는 무엇인가?</summary>

- 전위와 후위를 구별하기 위한 표시일 뿐 값은 쓰지 않음. 후위 판은 증가 전의 값을 복사해 값으로 돌려줌(3편)

</details>

<details>
<summary>`a = b = c`가 동작하려면 `operator=`가 무엇을 돌려줘야 하는가? 결합 방향은?</summary>

- `*this`의 참조. 대입은 오른쪽부터 결합하므로 `b = c`가 먼저 되고 그 결과(`b`의 참조)가 `a`에 대입됨

</details>

<details>
<summary>`x << 2 + 1`은 `(x << 2) + 1`인가 `x << (2 + 1)`인가?</summary>

- `+`(6)가 `<<`(7)보다 우선순위가 높아 `x << (2 + 1)`. 오버로드한 `<<`도 같은 우선순위를 가짐

</details>
