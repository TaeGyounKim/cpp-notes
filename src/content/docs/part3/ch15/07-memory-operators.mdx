- 다루는 것: 프로그램의 메모리 할당·해제 방식을 바꾸는 법. 전역 수준과 클래스 수준 모두 가능
- 쓸모가 큰 경우: 작은 객체를 많이 할당·해제해 **메모리 단편화**가 걱정될 때. 매번 기본 할당을 쓰는 대신 크기가 정해진 덩어리를 재사용하는 **메모리 풀** 할당자를 쓸 수 있음
- 이 글에서 배우는 요소: `new` 식과 `operator new`, 여섯 가지 형태, 배치 `new`, 클래스별 오버로딩, 할당 함수 지우기, 추가 매개변수, 크기를 받는 `operator delete`

:::caution
메모리 할당 전략을 잘 알지 못한다면 메모리 할당 함수를 오버로드하는 것은 대개 수고만큼 가치가 없다. 멋져 보인다는 이유로 하지 않는다. 실제로 필요하고 필요한 지식이 있을 때만 한다.
:::

## new와 delete는 실제로 어떻게 동작하는가

```cpp
Reading* r{ new Reading{} };
```

- `new Reading{}` 부분이 **new 식** (new-expression). 두 가지 일을 함 <CppRef path="cpp/language/new" />
  1. `operator new`를 불러 `Reading` 객체가 들어갈 공간을 할당함
  2. 그 공간에서 객체의 생성자를 부름. 생성자가 끝난 뒤에야 포인터를 돌려줌

```cpp
delete r;
```

- 이 줄은 **delete 식** (delete-expression). 먼저 소멸자를 부르고, 그다음 `operator delete`를 불러 메모리를 해제함 <CppRef path="cpp/language/delete" />
- `operator new`와 `operator delete`는 오버로드할 수 있지만, **new 식과 delete 식은 오버로드할 수 없음**
  - 실제 메모리 할당·해제는 바꿀 수 있지만, 생성자와 소멸자를 부르는 부분은 바꿀 수 없음

### new 식과 operator new

- new 식은 여섯 형태가 있고, 각각에 대응하는 `operator new`가 있음 <CppRef path="cpp/memory/new/operator_new" />
- 이미 본 넷: `new`, `new[]`, `new (std::nothrow)`, `new (std::nothrow)[]`(14장). `<new>`에 있는 대응 함수

```cpp
void* operator new(std::size_t size);
void* operator new[](std::size_t size);
void* operator new(std::size_t size, const std::nothrow_t&) noexcept;
void* operator new[](std::size_t size, const std::nothrow_t&) noexcept;
```

- 특별한 둘: 할당은 하지 않고 **이미 할당된 메모리 위에서 생성자만 부르는** **배치 new** (placement new). 단일 객체 판과 배열 판

```cpp
void* place{ allocateSomehow() };
Reading* r{ new (place) Reading{} };
```

- 대응 함수는 다음과 같지만, 표준은 이것을 **오버로드하지 못하게** 함

```cpp
void* operator new(std::size_t size, void* p) noexcept;
void* operator new[](std::size_t size, void* p) noexcept;
```

- 잘 알려지지 않은 기능이지만 있다는 것은 알아 두면 좋음. 메모리를 해제하지 않고 재사용하는 메모리 풀을 구현할 때 씀. 객체마다 메모리를 다시 할당하지 않고 만들고 없앰(메모리 풀 구현은 29장)
- 배치 new로 만든 객체는 `delete`하지 않고 **소멸자를 직접 부름**: `r->~Reading();`. 메모리는 원래 주인이 해제함

### delete 식과 operator delete

- 부를 수 있는 delete 식은 둘뿐: `delete`, `delete[]`. `nothrow`나 배치 형태는 없음
- 그런데 `operator delete`는 여섯 개 모두 있음. 왜 비대칭인가?
  - `nothrow`와 배치 판 넷은 **생성자가 예외를 던질 때만** 쓰임. 그때는 생성자 호출 전에 메모리를 할당한 `operator new`와 짝이 맞는 `operator delete`가 불림
  - 포인터를 보통으로 지우면 `delete`는 `operator delete`, `delete[]`는 `operator delete[]`를 부름(`nothrow`나 배치 판은 절대 아님)
  - 실제로는 문제가 안 됨. `delete`(예: `delete`가 부른 소멸자)가 예외를 던지면 정의되지 않은 동작이므로 `delete`는 애초에 예외를 던지면 안 됨. 그러니 `nothrow` 판 `operator delete`는 군더더기. 배치 `delete`는 배치 `new`가 할당을 하지 않으니 아무것도 하지 않아야 함

```cpp
void operator delete(void* ptr) noexcept;
void operator delete[](void* ptr) noexcept;
void operator delete(void* ptr, const std::nothrow_t&) noexcept;
void operator delete[](void* ptr, const std::nothrow_t&) noexcept;
void operator delete(void* ptr, void*) noexcept;
void operator delete[](void* ptr, void*) noexcept;
```

## operator new와 operator delete 오버로딩

- 전역 `operator new`와 `operator delete`를 원하면 **바꿀** 수 있음
  - 클래스에 더 구체적인 판이 없는 한 프로그램의 모든 new 식과 delete 식에 쓰임
  - C++을 만든 사람도 전역 판을 바꾸는 것은 담력이 필요한 일이라고 했음. 권하지 않음

:::danger
그래도 전역 `operator new`를 바꾼다면, 그 안에서 `new`를 부르는 코드를 쓰면 안 된다. 무한 재귀가 된다. 예를 들어 `std::print()`로 콘솔에 메시지를 쓸 수도 없다(내부에서 메모리를 할당할 수 있다).
:::

- 더 쓸모 있는 기법: **특정 클래스**에 오버로드함. 그 클래스의 객체를 할당·해제할 때만 쓰임

```cpp
class Tracked
{
public:
    void* operator new(std::size_t size)
    {
        std::println("operator new({})", size);
        return ::operator new(size);           // 전역 판에 넘김
    }
    void operator delete(void* ptr) noexcept
    {
        std::println("operator delete");
        ::operator delete(ptr);
    }
    // operator new[], operator delete[], nothrow 판도 같은 방식
};
```

- 위 구현은 메시지를 쓰고 전역 판(`::operator new`)에 넘길 뿐이라 별 쓸모는 없음. 문법을 보이려는 것
- `nothrow`는 사실 `std::nothrow_t` 타입의 변수. 전역 판에 넘길 때도 그 변수를 넘김

```cpp
return ::operator new(size, std::nothrow);
```


:::caution
`operator new`를 오버로드할 때마다 짝이 맞는 `operator delete`도 오버로드한다. 그러지 않으면 메모리는 내 방식으로 할당되고 기본 방식으로 해제되어 서로 맞지 않을 수 있다.
:::

- `operator new`와 `operator delete`의 여러 형태를 모두 오버로드하는 것이 지나쳐 보이지만, 할당 방식이 섞이지 않게 하는 데 대개 좋은 생각
  - 구현하고 싶지 않은 형태는 `= delete`로 명시적으로 지워 아무도 쓰지 못하게 함

:::caution
`operator new`와 `operator delete`의 모든 형태를 오버로드하거나, 쓰이지 않기를 바라는 형태는 명시적으로 지운다. 할당 방식이 섞이는 것을 막는다.
:::

## operator new를 지우거나 기본으로 두기

- 8장의 `= delete`, `= default`는 생성자와 대입 연산자만의 것이 아님
- `operator new`를 지우면 그 클래스의 객체를 `new`로 동적 할당할 수 없음

```cpp
class StackOnly
{
public:
    void* operator new(std::size_t) = delete;
    void* operator new[](std::size_t) = delete;
    void* operator new(std::size_t, const std::nothrow_t&) noexcept = delete;
    void* operator new[](std::size_t, const std::nothrow_t&) noexcept = delete;
};

StackOnly* p{ new StackOnly };   // 컴파일 오류
```

- GCC는 지워진 함수(`use of deleted function`)를 썼다고 알림. 멤버 `operator new`는 암시적으로 `static`

## 추가 매개변수가 있는 operator new

- 표준 형태 말고도 **추가 매개변수**를 받는 판을 쓸 수 있음
  - 할당 함수에 플래그나 카운터를 넘길 때 씀
  - 예: 디버그 모드에서 객체를 할당한 파일 이름과 줄 번호를 넘겨, 메모리 누수가 났을 때 할당한 줄을 찾음

```cpp
void* operator new(std::size_t size, int tag);
void operator delete(void* ptr, int tag) noexcept;
```

- 추가 매개변수가 있는 `operator new`를 쓰면 컴파일러가 대응하는 new 식을 자동으로 허용함. 추가 인수는 `nothrow`처럼 괄호 안에 넘김

```cpp
Tracked* t{ new (7) Tracked{} };
delete t;   // 보통의 operator delete가 불림
```

- 추가 매개변수가 같은 `operator delete`도 함께 정의함. 하지만 직접 부를 수는 없음. 추가 매개변수가 있는 `operator new`로 할당한 뒤 **생성자가 예외를 던질 때만** 불림

## 크기를 받는 operator delete

- `operator delete`의 다른 형태: 포인터와 함께 해제할 메모리의 **크기**를 받음 <CppRef path="cpp/memory/new/operator_delete" />

```cpp
void operator delete(void* ptr, std::size_t size) noexcept;
```

- `operator delete`의 각 형태를 독립적으로 크기를 받는 형태로 바꿀 수 있음
- 복잡한 할당·해제 방식을 쓸 때만 쓸모가 있음

:::caution
클래스에 크기를 받는 `operator delete`와 받지 않는 `operator delete`를 둘 다 선언하면, 크기를 받지 않는 쪽이 늘 불린다. 크기를 받는 쪽을 쓰고 싶으면 그것만 둔다.
:::

## 헷갈리기 쉬운 점

- `operator new`를 오버로드하면 생성자 호출 방식도 바꿀 수 있다?
  - 메모리 할당만. 생성자와 소멸자 호출은 new 식·delete 식이 하고, 그것은 오버로드할 수 없음
- 배치 new로 만든 객체는 `delete`로 지운다?
  - 소멸자를 직접 부름. 메모리는 원래 할당한 쪽이 해제
- `new (7) T`로 만든 객체를 지우면 `operator delete(void*, int)`가 불린다?
  - 보통 `operator delete`가 불림. 그 판은 생성자가 던질 때만
- `operator new`만 오버로드해도 된다?
  - 짝이 맞는 `operator delete`도 함께
- 전역 `operator new` 안에서 로그를 출력해도 된다?
  - 출력이 메모리를 할당하면 무한 재귀

## 정리

| 요소 | 핵심 |
| --- | --- |
| new 식 | `operator new`로 할당 + 생성자. 오버로드 불가 |
| delete 식 | 소멸자 + `operator delete`로 해제. 오버로드 불가 |
| `operator new` 여섯 형태 | 보통, 배열, `nothrow` 둘, 배치 둘(배치는 오버로드 불가) |
| `operator delete` 여섯 형태 | `nothrow`·배치 판은 생성자가 던질 때만 쓰임 |
| 클래스별 오버로드 | 그 클래스 객체에만. 짝을 맞추고, 안 쓸 형태는 `= delete` |
| 추가 매개변수 | `new (인수) T`. 같은 매개변수의 `operator delete`는 생성자가 던질 때만 |
| 크기 받는 `delete` | `operator delete(void*, std::size_t)`. 크기 없는 판과 함께 두지 않음 |
