## 깊은 복사 생성자

- 원본의 포인터를 복사하는 대신, **같은 크기의 배열을 새로 잡고 값을 복사**함

```cpp
Grid::Grid(const Grid& src)
    : Grid{ src.m_width, src.m_height }   // 위임: 같은 크기의 배열을 잡음
{
    std::copy(src.m_cells, src.m_cells + size(), m_cells);   // 값 복사
}
```

- 위임 생성자(8장)를 씀
  - 초기화 목록에서 보통 생성자에게 일을 맡겨 알맞은 크기의 메모리를 잡음
  - 본문에서 값을 복사함
  - 둘이 합쳐 깊은 복사가 됨
- `std::copy(처음, 끝, 대상)`: `<algorithm>`에 있음. `[처음, 끝)` 범위의 원소를 대상 위치부터 차례로 복사 <CppRef path="cpp/algorithm/copy" />
- 원래 배열을 지울 필요가 없음. 복사 생성자는 객체를 새로 만드는 중이라 원래 배열이 아직 없음

## 깊은 대입 연산자: 단순한 버전

- 대입은 이미 배열을 가진 객체에 덮어쓰는 것. 그래서 할 일이 많음

```cpp
Grid& Grid::operator=(const Grid& rhs)
{
    if (this == &rhs) {        // 자기 대입 확인
        return *this;
    }
    delete[] m_cells;          // 1. 원래 배열을 지움
    m_width = rhs.m_width;     // 2. 크기를 바꿈
    m_height = rhs.m_height;
    m_cells = new double[size()];                            // 3. 새 배열
    std::copy(rhs.m_cells, rhs.m_cells + size(), m_cells);   // 4. 값 복사
    return *this;
}
```

- 볼 것: 복사본과 대입받은 객체가 각자 배열을 가지므로, 한쪽을 바꿔도 다른 쪽은 그대로. 셋이 각자 자기 배열을 지우니 이중 해제도 없음

### 무엇이 문제인가: 예외 안전성

- 이 함수에는 일이 많고, 그만큼 잘못될 곳도 많음. 중간에 실패하면 객체가 **망가진 상태**로 남을 수 있음
- 예: 원래 배열을 지우고 크기도 바꾼 뒤, 3단계의 `new`가 메모리 부족으로 예외를 던짐
  - 나머지 코드는 건너뛰고 함수를 빠져나감
  - 객체의 너비·높이는 새 크기인데 배열은 없음. 크기와 메모리가 맞지 않는 객체
- 이런 코드를 **예외에 안전하지 않다** (not exception-safe)고 함
- 원하는 것은 **전부 아니면 전무**: 모두 성공하거나, 실패하면 객체가 손대지 않은 그대로 남는 것

## 복사 후 교환

- **복사 후 교환** (copy-and-swap) 관용구: 예외에 안전한 대입 연산자를 만드는 표준적인 방법
- 준비물: 두 객체의 내용을 맞바꾸는 `swap()`

```cpp
class Grid
{
public:
    Grid& operator=(const Grid& rhs);
    void swap(Grid& other) noexcept;
    // ...
};
void swap(Grid& first, Grid& second) noexcept;
```

- 멤버 함수 `swap()`: 데이터 멤버를 하나씩 `std::swap()`으로 맞바꿈
  - `std::swap()`은 `<utility>`에 있는 표준 함수. 두 값을 효율적으로 맞바꿈 <CppRef path="cpp/utility/swap" />
  - 포인터와 정수만 바꾸므로 메모리를 잡지 않고, 예외가 날 일이 없음

```cpp
void Grid::swap(Grid& other) noexcept
{
    std::swap(m_width, other.m_width);
    std::swap(m_height, other.m_height);
    std::swap(m_cells, other.m_cells);
}
```

- 멤버가 아닌 `swap()`도 함께 두는 것이 좋음. 표준 라이브러리 알고리즘들이 이것을 찾아 씀. 멤버 함수에 넘기기만 함

```cpp
void swap(Grid& first, Grid& second) noexcept
{
    first.swap(second);
}
```

### noexcept

- **`noexcept`** <Badge text="C++11" />: 이 함수가 예외를 던지지 않는다고 표시함 <CppRef path="cpp/language/noexcept_spec" />
  - 복사 후 교환이 안전하려면 `swap()`이 절대 예외를 던지지 않아야 하므로 붙임
  - `const`가 있으면 그 뒤에 씀: `void f() const noexcept;`
  - `noexcept` 함수가 그래도 예외를 던지면 프로그램이 종료됨
  - 자세한 내용은 14장. 이 장에서는 이 정도면 충분

### 대입 연산자

```cpp
Grid& Grid::operator=(const Grid& rhs)
{
    Grid temp{ rhs };   // 모든 일은 임시 객체에서
    swap(temp);         // 예외 없는 연산으로 확정
    return *this;
}
```

- 세 단계
  1. 오른쪽의 임시 사본 `temp`를 만듦. 현재 객체는 건드리지 않으므로 여기서 예외가 나도 문제없음
  2. `swap()`으로 현재 객체와 사본을 맞바꿈. `swap()`은 예외를 던지지 않음
  3. 함수가 끝나며 `temp`가 소멸함. 맞바꾼 뒤이므로 `temp`는 원래 객체의 배열을 가지고 있고, 그것을 정리함

<StepViz client:load data={copyAndSwapViz} />

- 이것이 **강한 예외 보장** (strong exception safety): 예외가 나면 객체 상태가 전혀 바뀌지 않음
- 자기 대입 확인이 필요 없음. `a = a;`여도 사본을 만들어 맞바꿀 뿐 결과가 맞음
  - 복사 후 교환을 쓰지 않는 대입 연산자에서는 효율과 정확성을 위해 첫 줄에서 자기 대입을 확인하는 것이 보통
- 복사 생성자와 대입 연산자 사이의 코드 중복도 사라짐(8장에서 미뤄 둔 문제). 대입이 복사 생성자를 재사용함

:::caution
대입 연산자는 복사 후 교환 관용구로 구현한다. 코드 중복을 피하고 강한 예외 보장을 얻는다.
:::

- 대입 연산자만의 기법이 아님. 여러 단계로 이뤄진 연산을 전부 아니면 전무로 만들고 싶을 때 어디서나 쓸 수 있음
  - 먼저 사본을 만들고, 사본에 모든 수정을 하고, 오류가 없으면 예외 없는 `swap`으로 확정

## 복사와 대입 막기

- 동적 메모리를 가진 클래스에서 가장 쉬운 길은 아예 복사와 대입을 못 하게 하는 것일 때도 있음
- 복사 생성자와 대입 연산자를 `= delete`로 지움(8장)

```cpp
Grid(const Grid& src) = delete;
Grid& operator=(const Grid& rhs) = delete;
```

- 지운 멤버 함수의 정의는 쓰지 않음. 컴파일러가 호출을 허락하지 않으므로 링커가 찾을 일도 없음
- 그러면 다음이 모두 컴파일 오류
  - 값으로 넘기기, 값으로 돌려주기(복사 생략이 보장되지 않는 경우), 복사로 만들기: `use of deleted function 'Grid::Grid(const Grid&)'`
  - 대입: `use of deleted function 'Grid& Grid::operator=(const Grid&)'`
- `const` 참조로 넘기는 것은 복사가 아니므로 문제없음

## 이전 표준에서는

| 이 글에서 쓴 것 | 들어온 표준 | 그 이전에는 |
| --- | --- | --- |
| `noexcept` | C++11 | `throw()` 예외 명세(C++17에서 폐기 예정, C++20에서 제거) |
| 위임 생성자 | C++11 | 공통 할당 코드를 `private` 함수로 빼서 각 생성자가 부름 |
| `= delete` | C++11 | 복사 생성자와 대입 연산자를 `private`으로 선언만 하고 정의하지 않음 |
| `std::swap`의 위치 `<utility>` | C++11 | `<algorithm>` |

## 헷갈리기 쉬운 점

- 복사 생성자에서도 원래 배열을 먼저 지워야 한다?
  - 복사 생성자는 객체를 새로 만드는 중이라 지울 배열이 없음. 지우는 것은 대입 연산자의 일
- 자기 대입 확인만 있으면 대입 연산자는 안전하다?
  - 중간에 예외가 나면 객체가 망가질 수 있음. 복사 후 교환은 그것까지 막음
- 복사 후 교환은 원래 배열을 어디서 지우나?
  - 맞바꾼 뒤 `temp`가 원래 배열을 가지게 되고, 함수가 끝나며 `temp`의 소멸자가 지움
- `swap()`에 `noexcept`는 장식이다?
  - 2단계가 실패하지 않는다는 약속이 관용구의 핵심. 예외를 던지면 강한 보장이 깨짐
- 복사를 지운 클래스는 함수에 넘길 수 없다?
  - 참조나 포인터로는 넘길 수 있음. 값으로만 못 넘김

## 정리

| 요소 | 핵심 |
| --- | --- |
| 깊은 복사 생성자 | 같은 크기를 새로 잡고(위임) 값 복사 |
| 단순한 깊은 대입 | 지우고, 크기 바꾸고, 잡고, 복사. 중간 실패에 약함 |
| 강한 예외 보장 | 실패하면 상태가 전혀 바뀌지 않음 |
| `swap()` | 멤버를 `std::swap`으로 맞바꿈. `noexcept`. 멤버 아닌 버전도 둠 |
| 복사 후 교환 | `T temp{ rhs }; swap(temp); return *this;` |
| 복사·대입 막기 | 둘 다 `= delete`. 참조로는 여전히 넘길 수 있음 |
