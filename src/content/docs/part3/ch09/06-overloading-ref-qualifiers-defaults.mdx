## 멤버 함수 오버로딩

- 8장에서 생성자를 여러 개 둔 것처럼, 보통 함수와 멤버 함수도 **이름이 같고 매개변수의 개수나 타입이 다르면** 여럿 둘 수 있음 <CppRef path="cpp/language/overload_resolution" />
- 예: `Grid`의 값을 넣는 함수를 숫자판과 문자열판 모두 `set()`으로

```cpp
void set(std::size_t x, std::size_t y, double value);
void set(std::size_t x, std::size_t y, std::string_view text);
```

- 부르는 쪽의 인수에 따라 컴파일러가 하나를 고름: **오버로드 결정** (overload resolution)
- **반환 타입만** 다른 오버로드는 안 됨
  - 반환값을 받지 않고 부르면 어느 것을 부르는지 알 방법이 없기 때문
  - 오류: `'double T::get()' cannot be overloaded with 'int T::get()'`

## const에 따른 오버로딩

- 이름과 매개변수가 같고 하나는 `const`, 하나는 비`const`인 두 멤버 함수를 둘 수 있음
  - `const` 객체로 부르면 `const`판이, 비`const` 객체로 부르면 비`const`판이 골라짐
- 흔한 예: 원소에 접근하는 함수. `const` 객체에는 `const` 참조를, 비`const` 객체에는 바꿀 수 있는 참조를 돌려줌

```cpp
const double& at(std::size_t x, std::size_t y) const;
double& at(std::size_t x, std::size_t y);
```

- 문제: 두 판의 구현이 대개 똑같음. 몇 줄이어도 코드 중복은 피해야 함(6장의 DRY 원칙)
  - 몇 달 뒤 한쪽만 고치고 다른 쪽을 잊는 일이 생김
- 해법 두 가지

### const_cast 패턴

- `const`판은 평소대로 구현하고, 비`const`판은 적절한 캐스트를 거쳐 `const`판에 넘김(스콧 마이어스가 널리 알린 방법)

```cpp
const double& Grid::at(std::size_t x, std::size_t y) const
{
    verifyCoordinate(x, y);
    return m_cells[y * m_width + x];
}

double& Grid::at(std::size_t x, std::size_t y)
{
    return const_cast<double&>(std::as_const(*this).at(x, y));
}
```

- 순서
  1. `std::as_const(*this)`: `Grid&`인 `*this`를 `const Grid&`로 바꿈. `<utility>`에 있음 <Badge text="C++17" /> <CppRef path="cpp/utility/as_const" />
  2. 그러면 `const`판 `at()`이 불려 `const double&`가 돌아옴
  3. `const_cast<double&>`로 `const`를 벗김 <CppRef path="cpp/language/const_cast" />
- 안전한 이유: 이 함수는 비`const` 객체에서만 불리므로 원래 객체는 바꿔도 되는 객체임

- 볼 것
  - 비`const` 객체로 부르면 비`const`판이 불리고, 그것이 `const`판에 맡김
  - `const` 참조로 부르면 `const`판이 바로 불림
  - 정수 `30`으로 `set()`을 부르는 줄은 막혀 있음(아래 "오버로드 지우기")

### private 도우미 멤버 함수

- 다른 방법: 반환 타입은 비`const`이지만 함수 자체는 `const`인 `private` 도우미를 두고, 두 판이 모두 그것을 부름

```cpp
double& Grid::at(std::size_t x, std::size_t y)
{
    return atHelper(x, y);
}

const double& Grid::at(std::size_t x, std::size_t y) const
{
    return atHelper(x, y);
}

double& Grid::atHelper(std::size_t x, std::size_t y) const
{
    verifyCoordinate(x, y);
    return m_cells[y * m_width + x];
}
```

- `atHelper()`가 `const` 함수이면서 비`const` 참조를 돌려주려면, 멤버가 포인터(`double*`)처럼 가리키는 대상까지 `const`가 되지 않는 경우여야 함
  - 앞 글들의 `double* m_cells`가 그런 경우. `const` 함수 안에서 포인터 자체는 바꿀 수 없지만 가리키는 `double`은 바꿀 수 있음
  - `std::vector`를 멤버로 쓰면 `const` 함수 안에서 원소도 `const`라 이 방법을 그대로 쓸 수 없음. 그때는 `const_cast` 패턴을 씀
- 템플릿과 명시적 객체 매개변수로 두 판을 하나로 합치는 방법은 12장에서 다룸

## 오버로드 지우기

- 오버로드를 `= delete`로 지워, 특정 인수로 부르는 것을 막을 수 있음 <Badge text="C++11" />
- 예: `set(x, y, double)`에 정수를 넘기면 컴파일러가 `double`로 바꿔 부름. 정수로 부르는 것을 막고 싶다면

```cpp
void set(std::size_t x, std::size_t y, double value);
void set(std::size_t x, std::size_t y, int value) = delete;
```

- 정수로 부르면 오류: `use of deleted function 'void Grid::set(std::size_t, std::size_t, int)'`

## 참조 한정 멤버 함수

- 보통 멤버 함수는 이름 있는 객체에서도, **임시 객체**에서도 부를 수 있음

```cpp
Label kitchen{ "부엌" };
kitchen.text();            // 이름 있는 객체
Label{ "거실" }.text();     // 임시 객체
```

- **참조 한정자** (ref-qualifier) <Badge text="C++11" />로 어떤 객체에서 부를 수 있는지 정할 수 있음 <CppRef path="cpp/language/member_functions" />
  - 멤버 함수 머리 뒤에 `&`: 이름 있는 객체(좌측값)에서만
  - `&&`: 임시 객체(우측값)에서만
- 예 1: 임시 객체라면 곧 사라지니, 안의 문자열을 복사하지 말고 **옮겨 줌**

```cpp
const std::string& text() const& { return m_text; }
std::string&& text() && { return std::move(m_text); }
```

- 예 2: 임시 객체에 **대입하는 헛일**을 막음
  - `makeLabel() = "헛일";`은 곧 사라질 객체에 대입하는 것이라 의미가 없음
  - 대입 연산자를 `&`로 한정하면 컴파일 오류가 됨: `passing 'Label' as 'this' argument discards qualifiers`

```cpp
Label& operator=(const std::string& rhs) &;
```

- 볼 것: 이름 있는 `kitchen`에서는 `&`판이, 임시 `Label{ "거실" }`에서는 `&&`판이 골라짐

### C++23: 명시적 객체 매개변수로 쓰기

- 8장의 명시적 객체 매개변수 <Badge text="C++23" />로 같은 것을 다른 모양으로 쓸 수 있음

```cpp
const std::string& text(this const Label& self) { return self.m_text; }
std::string&& text(this Label&& self) { return std::move(self.m_text); }
Label& operator=(this Label& self, const std::string& rhs);
```

- 더 길지만 참조 한정이 훨씬 잘 보임. 함수 끝에 붙은 `&`, `&&` 하나는 코드 리뷰에서 놓치기 쉬움

## 인라인 멤버 함수

- 함수 호출을 별도 코드 블록으로 뛰어가는 호출로 만들지 말고, **함수 본문을 부르는 자리에 바로 넣으라고** 컴파일러에게 권할 수 있음
  - 이것을 **인라인화** (inlining), 그런 함수를 **인라인 함수** (inline function)라고 함 <CppRef path="cpp/language/inline" />
- 멤버 함수 정의 앞에 `inline`을 붙임

```cpp
inline double Temperature::celsius() const
{
    return m_celsius;
}
```

- `inline`은 **권고**일 뿐. 성능에 해롭다고 판단하면 컴파일러는 무시함
- 주의: 인라인 함수의 정의는 그것을 부르는 모든 소스 파일에서 보여야 함
  - 본문을 볼 수 없으면 바꿔 넣을 수도 없음. 그래서 클래스 정의와 같은 파일에 둠
  - 고급 컴파일러는 링크 단계에서 작은 함수를 알아서 인라인화하기도 함(MSVC의 LTCG, GCC·Clang의 LTO). 이때는 `inline`이 없어도, 다른 파일에 정의되어 있어도 됨
- 클래스 정의 **안에** 본문을 쓴 멤버 함수는 `inline`을 적지 않아도 저절로 인라인 함수
  - 단, 모듈(11장)에서 내보낸 클래스는 예외. 그때는 인라인으로 하려면 `inline`을 직접 붙여야 함
- 인라인 함수를 디버거로 한 줄씩 따라가면, 실제로는 본문이 들어가 있어도 함수를 부른 것처럼 보여 주는 디버거도 있음
- 오해 주의: `inline`을 붙인다고 빨라지는 것이 아님
  - 컴파일러는 아주 단순한 함수만 인라인화하고, 원하지 않으면 조용히 무시함
  - 요즘 컴파일러는 코드가 커지는 정도까지 따져서 이득이 없으면 인라인화하지 않음

## 기본 인수

- **기본 인수** (default argument): 함수 원형에서 매개변수에 기본값을 정해 둠. 오버로딩과 비슷한 효과 <CppRef path="cpp/language/default_arguments" />
  - 부르는 쪽이 인수를 주면 그 값을, 생략하면 기본값을 씀
- 제한: 기본값은 **가장 오른쪽 매개변수부터 연속해서**만 줄 수 있음. 그래야 컴파일러가 빠진 인수를 어느 매개변수에 맞출지 앎
- 보통 함수, 멤버 함수, 생성자 모두에 쓸 수 있음
- 기본값은 **선언에만** 적고 정의에는 적지 않음

```cpp
explicit Grid(std::size_t width = 10, std::size_t height = 10);
```

- 생성자는 하나지만 인수 0개, 1개, 2개로 부를 수 있음
- 모든 매개변수에 기본값이 있는 생성자는 **기본 생성자 역할**도 함
  - 그래서 기본 생성자를 따로 또 두면, 인수 없이 만들 때 어느 것을 부를지 몰라 오류: `call of overloaded 'Grid()' is ambiguous`

:::note
기본 인수로 할 수 있는 일은 모두 오버로딩으로도 할 수 있다. 인수 개수가 다른 생성자 세 개를 쓰면 된다. 기본 인수는 그것을 하나로 줄여 줄 뿐이다. 편한 쪽을 쓴다.

## 헷갈리기 쉬운 점

- 반환 타입이 다르면 오버로드할 수 있다?
  - 반환 타입만 다른 오버로드는 안 됨
- `const_cast` 패턴은 `const` 객체를 바꾸는 위험한 코드다?
  - 비`const`판은 비`const` 객체에서만 불리므로 안전함. 반대로 `const`판이 비`const`판을 부르게 만들면 위험
- 참조 한정 `&&` 함수는 `std::move()`한 객체에서도 불린다?
  - 불림. `std::move(kitchen).text()`는 우측값이라 `&&`판이 골라짐
- `inline`을 붙이면 반드시 인라인화된다?
  - 권고일 뿐. 컴파일러가 판단함
- 기본 인수를 선언과 정의 모두에 적는다?
  - 선언에만. 정의에도 적으면 오류

## 정리

| 요소 | 핵심 |
| --- | --- |
| 오버로딩 | 이름이 같고 매개변수가 다름. 반환 타입만 다른 것은 불가 |
| `const` 오버로딩 | `const` 객체에는 `const`판, 아니면 비`const`판 |
| 중복 없애기 | `const_cast<T&>(std::as_const(*this).f())` 또는 `private` 도우미 |
| 오버로드 지우기 | `void f(int) = delete;` |
| 참조 한정 | `f() &`: 좌측값에서만, `f() &&`: 우측값에서만 |
| 인라인 | 본문을 부르는 자리에 넣으라는 권고. 클래스 안 정의는 저절로 인라인 |
| 기본 인수 | 오른쪽부터 연속, 선언에만 |

<summary>`int count(); long count();`를 한 클래스에 둘 수 없는 이유는?</summary>

- 반환 타입만 다르기 때문. 반환값을 쓰지 않고 `count();`라고 부르면 어느 것인지 알 수 없음

</details>

<details>
<summary>비`const`판 `at()`을 `const_cast<double&>(std::as_const(*this).at(x, y))`로 쓸 때 `as_const`를 빠뜨리면?</summary>

- `*this`가 비`const`이므로 다시 비`const`판 `at()`이 불림
- 자기 자신을 끝없이 부르는 재귀가 됨

</details>

<details>
<summary>`getName() &&`만 있는 클래스에서 `Person p; p.getName();`이 컴파일되지 않는 이유는?</summary>

- `&&`로 한정된 함수는 우측값(임시 객체)에서만 부를 수 있음. `p`는 좌측값
- `&`판을 추가하거나 `std::move(p).getName()`으로 부름

</details>

<details>
<summary>`Grid(std::size_t width = 10, std::size_t height)`가 잘못인 이유는?</summary>

- 기본값은 오른쪽부터 연속해서만 줄 수 있음. `height`에 기본값이 없는데 `width`에만 줄 수 없음

</details>
